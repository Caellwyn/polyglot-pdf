## The harness (what it actually tests)

Two metrics, because mechanical fill is necessary but NOT sufficient:

- **`choice_fill_success` = filled / attempted** for checkbox+radio. Plans the
  widget writes a fully-selected field implies, applies them via the production
  semantics (`field_value` + `xref_set_key(AS,/on)` for buttons, NO `update()`;
  `field_value` + `update()` for text; exact-then-endswith `find_widget`;
  read-only bit-flip unlock), saves, re-opens, and verifies. **Checkbox/radio
  state is verified via the `/AS` xref key** -- probed fact: after save+reopen a
  checkbox's `field_value` reads back EMPTY; its state lives in `/AS`
  (`xref_get_key(xref,"AS") == ('name','/<on>')`). Text verifies via `field_value`.
- **`value_convention` = conforming / total** choice options. Checks bd 7a9.14
  rule #1: `option.value` must equal the widget leaf of its own
  `option.pdf_field_name`. This is the part `choice_fill_success` CANNOT catch on
  its own (see the closed-loop caveat below).

### Why `choice_fill_success` alone is not enough (the closed-loop trap)

The synthetic value set is derived from each schema's OWN `option.value`, so a
schema can fill 100% of its own widgets while using values the real app would
never send. On I-90, both LLM arms scored **100% mechanical choice fill but 0%
value-convention** -- they emit `value:"Yes"/"No"`, not the widget-leaf
`P1_checkbox4[0]` the frontend (`RadioField.tsx`) emits and `controls_fields[].value`
references. Without the convention metric the harness would have falsely declared
them fill-ready. **Both metrics are required; report them together.**

Read this as: the LLM arms find + write the widgets fine, but their

conditional logic key on. That is the checkbox/radio round-trip failure, made

## Finding 3 -- encoding the convention FIXES the LLM arm (0% -> 100%)

After adding the CHOICE-FIELD RULES + a canonical leaf-convention example to the
schema contract (scripts/bakeoff/schema_contract.py), re-running the LLM-native
arm on I-90 (claude-opus-4-8) moved value-convention from **0% to 100%** while
holding mechanical fill at 100%:

| I-90 arm | value-convention | choice fill (mechanical) | text |
|---|---:|---:|---:|
| Opus, generic contract (before) | 0.0% (0/78) | 100% | 100% |
| baseline gemini hybrid | 0.0% (0/67) | 100% | 100% |
| **Opus, convention-aware contract** | **100.0% (78/78)** | **100% (28/28)** | 100% |
| I-90 gold (reference) | 66.2% (mixed) | 82.1% (p3_race bug) | 100% |

Spot-check confirms the arm reproduced the hard-won I-90 shape exactly: radios
carry pdf_field_name=null with widget-leaf option.values; controls_fields[].value
reuses the SAME leaf string (conditional logic wired correctly); and the Male/
Female case is grouped as ONE radio across two different widget names (rule #3).
The arm even scores HIGHER than the gold on value-convention (100% vs 66.2%)
because it applies the leaf convention uniformly, including to the demographic
dropdowns the gold left semantic -- which is the open product question in Finding 2.

A robustness bug in arm_llm_native.py surfaced here and was fixed in this PR: the
Claude CLI sometimes narrates BEFORE the JSON ("Let me build the schema...\n{...}")
and/or adds a trailing remark; the old _extract_json grabbed a stray bracket from
the prose and returned a 1-field fragment. It now scans every {/[ start,
raw_decodes each, and keeps the dict carrying "fields" (else the longest parse).

## Finding 1 -- production bug in the live I-90 gold (filed: 7a9.15)

The harness's self-test (gold must be ~100%) FAILED at 82.1%, and the 5 misses
were all `p3_race`:
- its 5 option `pdf_field_name`s drop the trailing `[0]` (`P3_checkbox7_White` vs
  the real `...P3_checkbox7_White[0]`), so the production filler's
  exact-then-endswith `find_widget` never matches them -- **Race silently does not
  fill in the live app today**; and
- its `option.value`s are semantic (`"white"`, `"asian"`), off the widget-leaf
  convention.

Excluding `p3_race`, the gold scores **23/23 choice + 108/108 text = 100%**, which
VALIDATES the harness: it fills every convention-following widget and flags only
the genuine defect. Filed as **polyglot-pdf-7a9.15** (P1 bug) rather than fixed
here -- it touches the live production schema, beyond this research bead's scope.

## Finding 2 -- the I-90 value convention is MIXED, not uniform

The bead framed `option.value == widget-leaf` as THE I-90 convention. The harness
shows it holds for **18 of 24** choice fields -- specifically the **Yes/No /
select-one structural checkboxes tied to conditional logic** (`controls_fields[].value`
references those exact leaf strings, so an LLM emitting semantic values there
breaks conditionals AND selection at once). The **exceptions are the 4 demographic
dropdowns** (`p3_ethnicity`, `p3_race`, `p3_eye_color`, `p3_hair_color`), which use
semantic values, plus 2 height "radios" that are really numeric dropdowns with no
option values.

**Refined rule:** the value must be *what the frontend/voice layer sends for that
field*, and for any conditional-DRIVING field that is necessarily the widget leaf
(so it equals `controls_fields[].value`). For standalone demographic pickers a
semantic value is acceptable IF the app sends it -- but that is a product/contract
decision about the value vocabulary, overlapping **7a9.13** (the section_id/
convention decision). The high-confidence, non-ambiguous part (leaf convention for
conditional-bearing choice fields) is safe to enforce now; the demographic-value
vocabulary is flagged for the maintainer.

   arm that emits choice fields -- the name-match proxy demonstrably passes
   schemas that would not fill. Add it alongside `schema_score.py` in the runner.
2. **Enforce the leaf convention** in the schema contract + LLM-native prompt --
   DONE + PROVEN in this PR (Finding 3): Opus went 0% -> 100% value-convention on
   I-90 and reproduced the exact hand-built shape (incl. the multi-widget Male/
   Female radio and the controls_fields leaf reference). Validate it holds on
   I-589 next (folded into 7a9.11 / the adoption gate).
3. **Decide the demographic-dropdown value vocabulary** (semantic vs leaf) --
   product/contract call, coordinate with 7a9.13.
4. **Fix the live I-90 `p3_race`** (7a9.15) so Race actually fills.
5. This bead **gates 7a9.12**: do not retire the heuristics until an arm reaches a
   target `choice_fill_success` AND `value_convention` on I-90 + I-589.
