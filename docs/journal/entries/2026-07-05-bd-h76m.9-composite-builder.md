## Trigger

P4.1 of the schema-v2 epic `polyglot-pdf-h76m` (plan:
`~/.claude/plans/rustling-discovering-hearth.md`, maintainer-machine-local):
the contractor-facing UI for compound conditions. Absorbs bd
`polyglot-pdf-jplx` (in/not_in had no array-value editor, so those rules
were authoring-excluded and displayed read-only).

## What shipped

- `schema-editor/src/components/ConditionBuilder.tsx` (new): "Shown when" +
  "Required when" cards on every field. Up to three labeled buckets --
  ALL of / AT LEAST ONE of / NONE of -- of sentence-style rows
  ([trigger dropdown] [operator dropdown] [value control]); a NO-nesting
  design (the one-level ceiling is unrepresentable in the UI, per the plan's
  risk item); plain-language summary line under the card.
- Value controls adapt to the trigger (exit criterion 3): option dropdown
  for single-value operators, option multi-select checklist for in/not_in
  (jplx closed), plain input only for free-text/number/date triggers,
  nothing for no-value operators. Fresh rows default to the trigger's first
  option slug; retargeting/operator switches coerce values INTO the new
  option set. No UI path can emit an out-of-set value.
- Operator dropdown filtered by a TS mirror of the backend v2 compat matrix
  (`operatorsForTrigger`): group triggers offer includes/not_includes and
  never equals (retired vocabulary); a stored off-matrix operator still
  displays itself so merely touching a rule cannot silently rewrite it.
- Wire-shape rule: exactly one ALL-of atom emits the LEGACY single
  condition (v1 kits stay v1 on round-trip); anything else emits the v2
  composite with only non-empty buckets; zero atoms removes the key.
  Malformed conditions render read-only with Remove as the only edit.
- FieldEditor: legacy show_if editor + the P3.1 composite read-only
  stopgap replaced by the two builder cards; require_if is now authorable.
- PreviewPane renders the v2 `checkbox_group` type (same multi-select UI as
  the legacy checkbox-with-options shape); editor FieldType union gains
  'checkbox_group'.
- 18 component tests over the three exit criteria, incl. a PreviewPane
  integration test driving the authored ALL[A,B]+NONE[C] composite live
  (hidden -> shown -> re-hidden as NONE-of trips) and a live require_if
  badge test (the preview's required '*' tracks isFieldRequired, not the
  static flag -- fresh-eyes round 2). Dev server boots in
  preview with zero console errors (full form-load needs the native
  directory picker, which the sandboxed preview cannot drive -- the
  component tests carry the behavioral verification).
- Fresh-eyes triage (Sonnet, 3 rounds -- the ceiling, exiting clean):
  - Round 1: GAPS-FOUND(2) -- (a) EC3: a stored value whose option was later
    removed from the trigger persisted invisibly -> now SURFACED (a
    '(missing option)' entry + role=alert; stale in/not_in members render as
    removable checklist entries; never silently rewritten); (b) PreviewPane
    rendered a zero-option checkbox_group as a lone "Yes" checkbox -> now a
    no-options notice. Two more findings REJECTED with rationale (round 2
    upheld both): includes on legacy checkbox-with-options cannot reach v2
    validation (v2 forbids that field shape entirely); checkbox_group stays
    out of the type dropdown (P4.2's merge flow is the intended producer).
  - Round 2: refuted the missing-option re-select worry (the stale entry
    unmounts after heal) but found the preview's required '*' badge ignored
    require_if -> now driven by isFieldRequired (live badge test added).
  - Round 3: NO-GAPS (badge fix verified incl. static-required short-circuit
    and shared-evaluator parity).
  - Adopt 3 / reject 2 (rationale upheld) / defer 0; no beads filed.

## Lessons

- The controlled-component test harness (a tiny useState wrapper capturing
  the last emitted value) is the right shape for authoring-flow tests on
  controlled editors -- fireEvent sequences read like the contractor's
  clicks and the assertion is the exact wire value.
