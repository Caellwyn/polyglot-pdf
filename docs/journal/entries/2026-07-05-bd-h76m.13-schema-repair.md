## Trigger

Fifth Lane-2 bead of the schema-v2 epic `polyglot-pdf-h76m` (plan:
`~/.claude/plans/rustling-discovering-hearth.md`, P5.2), absorbing bd 4c58
(the original "extractor hallucinates invalid conditional operators" bug --
closed with this bead). Extraction models invent vocabulary when the schema
cannot express what they mean; until now an invented operator was a
validation dead-end (the draft failed Pydantic and a human triaged). The
P5.1 ablation sharpened the case: with grouping hints the model preserves
widget identity perfectly and fails ONLY on vocabulary -- exactly the class
a deterministic pass can fix.

## What shipped

- `backend/services/schema_repair.py` (core) + `scripts/authoring/
  schema_repair.py` (CLI shim; the path `eval_extraction._try_repair`
  discovers). Placement mirrors schema_lint: the P5.3 editor "Repair all"
  imports the same implementation, so CLI and editor output are equal by
  construction. `repair(schema, dump=None) -> (repaired_copy, repairs[])`,
  pure and idempotent.
- Slug minting: choice fields whose option values violate the v2 slug
  convention (or collide) get slugs minted from labels via the P1.1
  registry; old value / widget path / leaf / label all resolve to the new
  slug for reference rewriting.
- Alias table for the OBSERVED invented vocabulary (each shape decoded from
  a real fixture): `is_selected` -> registry-valid membership; `contains_any`
  -> `any_of` membership; the `or`/`and` pseudo-group with `option_id`
  widget paths (P5.1 ablation) -> `any_of`/`all_of`; `contains`-on-group ->
  membership reading. The membership TARGET is decided by the compat
  matrix, never hardcoded: `includes` on `checkbox_group`, `equals` on a
  v1-typed group (where the registry forbids includes and the evaluator's
  array branch already gives equals membership semantics; P6.1's migration
  retypes and upgrades those to includes).
- Fail-open drops: unknown operators and unresolvable values DROP the
  condition with a recorded ERROR -- the field stays visible, and the
  invented token is never emitted (exit criterion 2).
- Hallucinated widgets fail LOUDLY (`RepairError`) when a dump is supplied
  -- repair cannot invent mappings. In the extract_form pipeline this is
  caught, reported on stderr + provenance, and the unrepaired draft is
  still written for inspection (P5.3 owns exit semantics).
- Alias hit-rate recorded per pass (`alias-hit-rate` entry + extract_form
  log line) -- the P6 decay metric: the P1.2 contract-from-model should
  drive it toward zero; an alias still firing at P6 belongs in the prompt.
- Wiring: extract_form runs normalize -> REPAIR -> validate -> lint with
  the report in `_bakeoff.authoring.repair`. eval_extraction repairs
  DRAFTS only (gold baseline rows stay as-shipped), writes repaired temp
  files to the system temp dir (never beside a fixture input), gains
  `--no-repair` (the pre-repair defect-profile mode the P2.2
  broken-draft-scores-RED record uses), and stops counting the v1
  widget-leaf value-convention column toward RED on rows repair ran on
  (slugs deliberately replace that convention; lint + roundtrip gate
  those rows).

Exit criteria: (1) the replayed broken W-7 draft repairs to lint-ERROR-free
and 100% choice roundtrip fill (>= 95 gate) -- PASS, test-pinned; (2)
unknown operator never emitted, dropped with recorded ERROR -- PASS,
test-pinned. 17 new tests incl. idempotency (repair(repair(x)) == repair(x),
zero substantive second-pass repairs), input immutability, and the P5.1
candidates-on fixture repairing clean (its 8 collapsed "1" values become 8
distinct label-minted slugs; its or-pseudo-groups resolve via option_id).

Suites: 1450 passed (backend + root, -m "not external").

## Lessons

- An alias table is an input contract with the model's mistakes -- keep it
  registry-driven (the compat matrix picks the rewrite target) or the
  repair itself emits invalid combos: the first cut hardcoded
  is_selected->includes and produced 14 operator-trigger lint errors on
  v1-typed triggers before the registry consult fixed it.
- When a pipeline step lands mid-epic, its consumers' semantics shift too:
  activating repair inside eval_extraction silently changed what the P2.2
  "broken draft scores RED" record measured. Preserving the old meaning
  behind --no-repair (and pinning BOTH meanings as tests) kept the two
  beads' exit criteria simultaneously true.
