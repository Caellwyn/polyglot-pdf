## Trigger

`bd polyglot-pdf-7a9.10`, a research follow-up to 7a9.9 under the PDF->JSON
authoring epic `7a9`. The bead asked for a per-signal ablation of
`structural_enrich.py`'s three signals (name-token decomposition, the
reading-order rank, visual-row clusters): run the llm-native arm on I-90 with each
signal individually disabled, score, and trim any signal that is noise or
net-negative. Mid-flight the maintainer steered the ordering question
substantially (twice), which expanded the bead into a reading-order experiment.

## What shipped

A per-signal ablation + a model-derived reading-order probe, both on I-90 against
the committed gold, plus the trim and a findings doc. Throwaway research output
(per-arm drafts, annotated PDFs/PNGs, run scripts/logs all gitignored under
`scripts/bakeoff/outputs/`).

**Ablation (Opus, n=3 per arm).** Disabling each enrichment signal -- and all
three at once -- does **not** move the (a) field-extraction metrics on Opus: F1
~96.7-97.1, type 97.0, options 65.4 are flat regardless of which signal is on.
The 7a9.9 "enrichment lifts typing 85.5 -> ~96" result was a **gemini-3.5-flash**
effect; the stronger model gets its typing from the base AcroForm dump (exact
names + /TU tooltips + page/xy geometry + flags/choices) plus reading the PDF. The
signals' only measurable influence is on (b) relationship recall and spurious-field
churn, both with large run-to-run variance. Verdicts: KEEP `name_decomp` (cheap,
mild (b) upside) and the reading-order rank (its removal was the worst (a) hit -- 9
FPs every run, the model loses the consolidation cue); **DROP `row_cluster`** (no
(a) value, net-negative on (b) show_if recall when isolated). `row_cluster` is now
dropped from the default render (`DEFAULT_DISABLED`); `--full-bundle` re-enables it
for ablation.

**The "tab order" misnomer + the ordering breakthrough.** The signal the code
called `tab_order` was never the form authors' tab order -- it is a mechanical
geometric sweep (`(page, y-band, x)`). The maintainer's point: that y-then-x sweep
is not a reliable human reading order (it interleaves columns on multi-column
pages). I first tried prompt-relabeling it (a heavy "distrust this, re-derive it
yourself" caveat measurably HURT (a) -- F1 95.7, FPs doubled to 12 -- by
suppressing the consolidation cue; a lighter "geometric layout order, use page+xy"
framing is the shipped default). Then the maintainer steered to the right approach:
**stop making the model reconcile a mechanical order, and instead play to Opus's
visual judgment** -- give it an annotated page (each widget tagged with a numbered
marker) and ask "what order would a human fill this out?". Built as
`scripts/bakeoff/order_probe.py`. Result on 5 I-90 pages: the model BEATS the sweep
on every page, median Kendall tau **0.996 vs 0.534** against the gold authored
order -- near-perfect on two-column pages (1.000 vs 0.534) where the sweep
scrambles columns, and still 0.696 vs 0.368 on the hardest page (48-marker
checkbox grids, where "the human order" is genuinely ambiguous). This approach is
generalizable: it works from pixels, so it needs no semantic field names and
survives opaque-name forms (W-7's `f1_23`, I-589's mixed names). A name-parsing
shortcut (the question numbers ARE encoded in I-90's `P1_Line3a` names) was
considered and rejected as the general method -- it is the USCIS-heuristic
treadmill the epic retires, failing on W-7/I-589's opaque names. Maintainer's call
(2026-06-12): go with model-derived ordering; with a human reviewing every schema,
95%+ is a strong win.

Full numbers, per-signal verdicts, and the ordering table:
`docs/research/2026-06-12-7a9.10-enrichment-signal-ablation-findings.md`.

## Lessons

- **A "signal" that helps a weak model can be inert on a strong one.** The
  enrichment bundle's headline win was real on gemini-3.5-flash and ~zero on Opus.
  Re-measure per-model before generalizing a signal's value; do not assume an
  ablation result transfers across model tiers (cf. the genai-2.8 re-measure scar).
- **Play to the model's strength instead of making it reconcile your mechanical
  output.** Feeding a known-bad geometric sweep and asking the model to correct it
  HURT extraction (it distrusted a cue that was helping). Asking Opus the one
  visual-judgment question it is good at -- from an annotated image -- scored tau
  ~1.0. The leash-lengthening was the maintainer's steer and it was decisively
  right.
- **The CLI per-message output ceiling silently truncates long replies.** Both the
  schema arm (~30K-token schema) and the order probe (model narrating grid
  reasoning before a 48-int array) had results truncated mid-output, masquerading
  as parse failures / refusals. Fix: have the model WRITE the answer to a scratch
  file (`--permission-mode acceptEdits` so the headless session can write) and read
  it back. This is now the pattern for any CLI-backed arm that emits a large
  artifact.
