### Two findings from exploration that shaped it

1. **The prior pipeline lived in THIS repo and is recoverable from git history.**
   `pdf_schema_extractor/` (PyMuPDF deterministic + `gemini_enhancer_v2.py` LLM
   pass) and the `schema-editor/` WYSIWYG correction UI were deleted in commit
   `5ea05d4` ("moved to a separate repo"). The separate repo is lost, but the
   content is intact at the parent commit **`a0bf111`** (= `5ea05d4^`):
   `git checkout a0bf111 -- schema-editor/` recovers 49 files -- a Vite/React app
   (`PDFViewer`, `FieldOverlay`, `FieldEditor`, `ValidationPanel`,
   `pdfCoordinates` utils, tests).

2. **Maintainer steer:** the extraction was rough (clean-slate it, don't
   resurrect), but the WYSIWYG correction UI was genuinely valuable. Since
   extraction will never be 100%, human correction is unavoidable -- so the
   correction tool is at least as important as the extractor. Hence **two pillars,
   not one.**

### Pillar 1 -- Extraction (clean-slate, current multimodal models)

PDF -> draft FormSchema, measured on two halves SEPARATELY:
- **(a) field extraction** -- id/name/type/label/spoken_name, PDF widget mapping
  (`pdf_field_name`/`consolidated_widgets`/`pdf_position`), options, validation,
  `section_id`. The OCR/layout/widget-decoding problem.
- **(b) relationship/logic** -- parts/sections hierarchy + ordering, `show_if`,
  `controls_fields`/`conditional_fields`, `conditional_logic`/`conditional_behavior`,
  `copy_to`, supplements + `overflow_to_supplement`, tables/`multi_entry`. The
  reasoning-hard part.

Bake-off: **GCP Document AI Form Parser vs multimodal Gemini vs multimodal Claude.**
Do not resurrect the old extractor (rough); reference-only.

### Pillar 2 -- Human-correction WYSIWYG UI

Recover `schema-editor/` from `a0bf111`, run it, assess what's still useful, treat
it as where the hours are actually saved (correction speed is the real lever).

## Lessons

- **Deleted-but-valuable tooling is often recoverable from git history** -- check
  the delete commit's parent (`<delete>^`) before treating a "moved to another
  repo" tool as lost. The `schema-editor` UI was one `git checkout` away.
- **When extraction can't hit 100%, the correction tool is a co-equal deliverable,
  not a nice-to-have.** The lever on human-hours is the correction loop's speed,
  not just the extractor's first-pass accuracy.
