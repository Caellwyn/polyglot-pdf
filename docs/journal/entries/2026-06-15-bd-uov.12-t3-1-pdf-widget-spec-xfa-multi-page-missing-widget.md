## Trigger

Bead polyglot-pdf-uov.12 (T3.1, under the spec-driven test epic uov, Phase 3).
`test_pdf_fill_readonly_unlock.py` pins two historic I-90 choice-field bugs
against the on-disk kit, but the widget-lookup core of `/fill-pdf` --
`find_widget`'s XFA path matching and the multi-page / missing-widget paths --
had no coverage. The bead's charge: spec the XFA exact-then-endswith matching,
multi-page widget lookup, the weak-ref re-fetch, and the missing-widget path.

## What shipped

A new `backend/tests/test_pdf_widget_lookup.py` (6 tests) speccing those edges
with SYNTHETIC in-memory PDFs built with PyMuPDF, each driven through the REAL
`fill_pdf` route. The route's only I/O dependency is the form-kit store
(`load_pdf_bytes`); mocking just that lets the route's actual `find_widget` /
`fill_widget` closures run against a PDF we construct on demand -- so the edges
are deterministic and present without depending on the real kit (and without
reimplementing the lookup logic in the test).

- **XFA path matching.** The schema carries the leaf `MyField[0]` while the only
  widget is the XFA full path `form1[0].#subform[0].MyField[0]`;
  `find_widget`'s endswith pass resolves it. Mutation-verified: breaking the
  endswith pass fails this test.
- **exact-beats-endswith precedence (the subtlest edge).** `find_widget` runs a
  full EXACT pass across ALL pages before any endswith pass, so an exact
  `MyField[0]` on page 1 wins over an endswith-only `form1[0].sub[0].MyField[0]`
  on page 0 -- a partial path must never shadow the real field. Mutation-verified:
  collapsing the two passes (endswith in the first pass) makes the earlier-page
  partial win and fails this test.
- **multi-page lookup.** A widget on page 3 (empty pages before it) is found and
  filled.
- **missing widget.** A `pdf_field_name` matching no widget is skipped
  gracefully -- the route still returns 200 with a valid PDF (no 500, no aborted
  fill) -- and a SIBLING field whose widget exists still fills in the same
  request (per-field degradation).

**Weak-ref re-fetch (scoped out, with reason).** The bead listed `fill_widget`'s
weak-ref re-fetch as an edge, but it is NOT separately observable through the
public route: `find_widget` and `fill_widget` both re-resolve the SAME
`field_name` on the SAME page, so they cannot diverge in a way the route exposes
(if `find_widget` matched, the re-fetch matches too). It is an internal
crash-guard against PyMuPDF's "weakly-referenced object no longer exists"; its
observable contract -- fills work across the page boundary -- is covered by the
multi-page test. A test that monkeypatched the closure internals would pin the
implementation, not the contract, so I did not write one. No defect found.

353 backend tests pass; test-only, no product code changed. The bead had no
`## Exit criteria` (creation-time-norm slip); a retrospective rubric was written
at claim time.

## Lessons

When the unit under test is a nested closure (here `find_widget` /
`fill_widget` live inside `fill_pdf`), you cannot import it -- but you do not
have to fall back to a reimplementation. Mock only the boundary I/O (the form-kit
store) and drive the real entrypoint with a synthetic input you fully control
(an in-memory PyMuPDF doc). The closures run for real, the input is deterministic,
and the spec stays a black-box contract test. The companion discipline: when a
listed "edge" turns out to be an unobservable implementation detail (the weak-ref
re-fetch), say so and scope it out rather than writing a test that asserts the
implementation -- pinning internals is the opposite of what the spec-driven epic
wants.
