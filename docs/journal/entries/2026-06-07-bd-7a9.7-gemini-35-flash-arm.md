## Trigger

`bd polyglot-pdf-7a9.7`, a maintainer-requested follow-up to the closed `7a9.4`
extractor bake-off: re-run the Gemini arm with **gemini-3.5-flash** (a newer stable
release than the gemini-3.1-pro-preview used in 7a9.4). The original 7a9.4 left the
I-589 gemini-hybrid cell SKIPPED because 3.1 Pro hit an HTTP ReadTimeout on that
heavy 460-widget fusion call at both 8-min and 20-min deadlines.

## What shipped

No new harness code -- `arm_gemini.py` already takes `--model`. This change is the
**results** of four new runs (I-90 + I-589 x multimodal + hybrid) plus the table /
FINDINGS update:

- `scripts/bakeoff/manifest.json` -- relabeled the existing Gemini arms
  `gemini31pro-*` and added `gemini35flash-*` (so the two model families are an
  explicit, side-by-side comparison).
- `scripts/bakeoff/FINDINGS.md` + `_scores.json` -- regenerated with both families.

## Result -- gemini-3.5-flash is the better Gemini

- **It COMPLETES the I-589 hybrid call** (334 fields, ~49K output tokens, ~1 min)
  that 3.1 Pro could not finish in 20 min. That alone makes it the usable Gemini.
- **Best (b) of any arm on I-589:** show_if 54.7% (29/53), b.cond 44.6% -- edging
  claude-hybrid's 41.5% -- with full parts/sections/supplements structure. Its one
  I-589 weakness is tables (0/9 vs claude-hybrid's 7/9), so its b.strc is 75.0.
- **Ties on I-90:** a.F1 97.0 vs 3.1 Pro 98.5 and claude 96.0; b.cond 17.5 ~ 3.1
  Pro's 18.8. No meaningful loss on the field-extraction form.
- Much faster + cheaper than 3.1 Pro.

So the bake-off's recommended (b) engine is now **either claude-hybrid or
gemini-3.5-flash-hybrid** (3.5-flash wins I-589 conditionals, claude wins I-589
tables; they tie I-90). The recommended pipeline is unchanged in shape
(deterministic skeleton + strong-LLM relationship pass); the Gemini option in it is
now 3.5-flash, NOT 3.1 Pro.
