## Trigger

A maintainer audit of "empty audio frames" (cost + error concern: users in noisy
waiting rooms, or walking away with the mic open). The audit found literal empty
frames are a non-issue (one harmless ~2-byte frame per session at mic-arm), but
surfaced a real gap: in NATIVE VAD mode (the default) the WS idle watchdog never
fires on a walk-away. In native mode the frontend streams CONTINUOUS audio incl.
silence, and the watchdog reset its activity clock (`last_rx`) on EVERY received
message -- including those silence frames (`websocket_routes.py`). So an abandoned
open mic kept the connection "active" and billed Gemini's audio-input stream
(~25 tok/s, $3/1M = ~$0.0045/min) until Gemini's own 15-min audio SESSION cap
force-closed it (~7 cents worst case). The 15-min cap was the ONLY backstop;
context compression is ruled out (see [`l3a.3` entry](2026-06-15-bd-l3a.3-session-resumption-declined.md)),
so it stays -- but relying on it meant up to 15 min of charge per abandonment.

## What shipped

A server-side-only fix so the idle watchdog resets on MEANINGFUL activity, not on
raw mic bytes:

- **Adapter** (`live_ai_gemini.py`): a new optional `on_user_activity` callback,
  fired when `server_content.input_transcription` has text -- i.e. Gemini's native
  VAD heard a REAL user utterance. (Signal correction found mid-implementation:
  the existing `on_transcript` fires on `output_transcription` -- Gemini SPEAKING,
  the wrong signal; and `input_transcription` was being read into a local var and
  then DROPPED, surfaced nowhere.) The callback gets NO text -- only the fact a
  turn occurred -- keeping PHI out of the liveness path (bd hjo). Errors are
  swallowed so it never crashes the receive loop.
- **Service** (`form_filling_service.py`): stores `_on_user_activity` (set by the
  route before `start_session`) and threads it into BOTH `set_callbacks` sites --
  the primary one and the section-switch re-registration -- so the timeout still
  works after a section switch.
- **Route** (`websocket_routes.py`): `last_rx` is now a 1-element list shared by
  the watchdog, the receive loop, and the activity callback. Inbound AUDIO frames
  no longer bump it; non-audio control/text messages (ping/form_state/hint) and the
  native-VAD user-turn callback do. On timeout the EXISTING path is reused
  (`idle_timeout` WS message -> frontend `ConnectionTimeoutModal`), so no frontend
  change was needed.

Scope: only `/ws/fill` (the real form-fill handler driving Gemini). The other two
WS handlers (`/ws/audio`, `/ws` handshake) are AFRM-protocol echo/smoke harnesses
that never open a Gemini session, so they have no walk-away billing exposure and
were left untouched.

**Tests** (`test_websocket_auth_lifecycle.py`): the pre-existing "idle timeout"
tests were vacuous (config-constant assertions + a self-fulfilling-mock
placeholder), giving zero coverage of the behavior. Added two REAL behavioral
tests driving the actual route watchdog with a controllable clock:
`test_idle_watchdog_ignores_inbound_audio_frames` (a continuous audio stream with
no user turn still times out -- the core fix) and
`test_user_activity_callback_resets_idle_clock` (a native-VAD user turn defers the
timeout). Full suite green: 351 passed.

**Exit-criteria scorecard (Step 5.5.a):**
1. Native-mode session with continuous audio but no user turn times out via the
   `idle_timeout` path -- PASS (`test_idle_watchdog_ignores_inbound_audio_frames`).
2. A real user turn resets the watchdog so an active user is never timed out --
   PASS (`test_user_activity_callback_resets_idle_clock`).
3. Server-side only; stateless invariant preserved (no client-side VAD, no new
   per-session server field state) -- PASS (the activity timestamp is per-connection
   liveness, not form state; frontend untouched).

**Fresh-eyes:** round 1 returned `NO-GAPS` (Haiku reviewer, arm-B picker live;
diff under the ~80-line threshold). Scored all three exit criteria PASS, traced the
callback registration + firing flows end-to-end, confirmed audio frames `continue`
past the `last_rx` bump, no PHI leak, backward-compatible `set_callbacks` kwarg, and
the two tests drive the real watchdog. No gaps, no out-of-scope beads filed.

**Sibling decision (same session):** session resumption (`l3a.3`) was declined and

would have PRESERVED an active one across an involuntary drop.

## Lessons

- **In native VAD mode, "received a frame" != "user is active."** The reliable
  "user present" signal is a native-VAD `input_transcription` (a detected
  utterance), NOT raw audio bytes -- silence and background noise stream as audio
  but never transcribe. Any liveness/timeout logic on the audio-up path must gate
  on turns, not bytes.
- **A captured-but-dropped signal reads as "handled" in a grep.** `input_transcription`
  was read into a local and discarded; only reading the surrounding lines (not the
  variable name) revealed it went nowhere. Verify the signal is actually consumed,
  not just named.
