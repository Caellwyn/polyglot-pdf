## Trigger

Found during the 2026-06-16 secretary-research discussion: the legacy/full SI
builder (`ai_context.build_form_context`) read only the FLAT `field["description"]`
key and never the canonical NESTED `field["help"]` block (`FieldHelp`:
instructions/format_hint/...). The demo schema uses flat `description` on 2/174
fields, which masked it -- but the real I-90 (`form-kits/i-90/schema.json`)
populates `help.instructions` on ALL 132/132 fields. NET EFFECT: on real forms the
live voice model received ZERO per-field instructions/format hints -- it guided
immigration intake with none of the authored field guidance (e.g. "the A-Number is
a 7-9 digit number on your green card"). A P1 correctness bug.

## What shipped

A small, contained fix in the legacy SI field-rendering:

- `ai_context.build_form_context` now reads `field["help"]` (a dict) when present:
  `help.instructions` feeds the existing `Note:` line (preferred over a flat
  `description`), `help.format_hint` feeds the existing `Format:` line (when no flat
  `format`). No rendering-path change -- the nested values flow into the
  `field_info["description"]`/`["format"]` keys the renderer already emits.
- Backward-compatible: a form using the flat `description`/`format` keys (demo
  shape) still renders unchanged.

The JIT and DTI paths already read nested help (via
`manifest_service.get_field_guidance`, bd jnjj.22); this closes the legacy/full-SI
path that was still dropping it.

**Exit criteria (rubric scorecard):**
1. ai_context renders help.instructions/help.format_hint into the per-field SI for
   nested-help forms -- **PASS** (verified on real I-90: 9 `Note:` lines on section
   1, incl. the A-Number guidance, was 0 before).
2. Verified on the real I-90 schema -- **PASS** (`A-Number ... 7-9 digit` text present
   in the built SI).
3. Backward-compatible with flat `description` -- **PASS** (demo `dob` field still
   renders `Note:`/`Format:`).

**Fresh-eyes (pre-PR assess):** [filled at closeout].

**SI-cost note:** rendering help ADDS tokens to the per-turn SI, in tension with
the SI-reduction goal -- the resolution is the JIT/DTI per-question direction
(bd jnjj.22, only the CURRENT field's help in context), not dropping the guidance.

## Lessons

- **Reading only the flat key while the canonical model is nested is a silent
  data-loss bug** -- it "works" on the demo (which happens to use the flat key) and
  fails invisibly on real forms (which use the nested block). When a model defines
  structured sub-objects (FieldHelp), every consumer must read the structured shape,
  not a flattened alias. The demo schema being non-representative hid this for a
  long time (same root as the invalidated G2 measurements).
