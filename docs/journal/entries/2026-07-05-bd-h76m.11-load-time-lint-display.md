## Trigger

Lane-3 bead of the schema-v2 epic `polyglot-pdf-h76m` (plan:
`~/.claude/plans/rustling-discovering-hearth.md`, P4.3), unblocked by P2.1's
`schema_lint.py` (bd h76m.5). It is the last gate before P5.3 (store-with-issues):
P5.3 needs a findings surface in the editor to show a stored-with-issues draft's
problems.

Before this, the hosted editor's ValidationPanel ran its OWN client-side
TypeScript ruleset (`schema-editor/src/utils/validation.ts`) -- a parallel
implementation that could (and did) drift from the authoritative Python
`schema_lint` the mark-complete promotion gate enforces. A contractor could see
"no validation errors" in the panel yet be blocked at promotion by a Python rule
the TS side never checked.

## What shipped

- `POST /api/editor/lint` (`backend/routes/editor_kit_routes.py`), editor-role
  gated like every editor route. It lints the schema the editor CURRENTLY HOLDS
  (posted as the body, not a kit id) so the panel reflects unsaved edits and
  never-stored drafts, over the same `schema_lint` rules the promotion gate uses.
  Returns `{findings, errorCount, warningCount}`. It never 4xxs on a malformed
  draft: `lint_schema` never raises, and a structural problem IS the finding the
  contractor needs (a bad `show_if` comes back as `condition-malformed`, not an
  HTTP error). No acroform dump is passed -- the dump is not a per-kit artifact
  until P5.3, matching the promotion gate's dump-less lint today.
- `schema_lint.field_id_of(path)`: extract the field id a finding anchors to
  (`fields[3] (id=dep).show_if` -> `dep`; the `fields (id=X)` no-index shape used
  by show-if-cycle warnings too). Authored ONCE in Python -- the frontend never
  re-parses paths. `LintFinding.as_dict()` now carries the derived `field_id`
  (null for a non-field-anchored finding like a dump widget-claim).
- `remoteKitStore.lintSchema()`: the frontend client for the endpoint (applies
  the same `stripEditorState` the save path does; AuthError on a rotated code).
- `ValidationPanel` now renders the backend findings (hosted mode) instead of
  always running the local TS ruleset. Field-anchored findings are clickable
  buttons that focus the field (`App` wires the click to select it and leave
  preview mode so the selection is visible); unanchored findings render as plain
  rows. A backend lint failure is NON-BLOCKING -- the editor stays fully usable
  and the panel shows a quiet "could not check for issues" note. A monotonic
  staleness guard drops an older in-flight lint so fast edits are never
  overwritten by a stale result.
- Local (non-hosted) mode keeps the client-side `validateSchema` (bd h903, fixed
  in this same diff -- see below): it has no backend and no access code to reach
  the token-gated `/lint` route, so the panel branches on `isHostedMode()` and
  lints synchronously client-side there, mapped into the same finding rows. So
  `validateSchema` is not orphaned -- it is the local-mode source of findings.

## Why body, not kit id

The endpoint takes a schema body rather than reading a stored schema by kit id.
"Load-time display in the editor" means linting what is on screen -- including
unsaved edits and drafts that were never stored -- which a kit-id read cannot
see. This also mirrors the client-side `validateSchema(schema)` it replaces
(which ran on the in-memory schema). Reversible: a kit-id variant could be added
later if a server-side "lint the stored copy" caller ever needs one.

## bd h903: local-mode fallback (folded into this PR)

The pre-PR fresh-eyes review caught a real regression this diff would otherwise
have shipped: the FIRST cut of `ValidationPanel` called the token-gated
`/api/editor/lint` route UNCONDITIONALLY, even in local (non-hosted) delivery
mode -- which has no backend and no `AccessCodeGate` to obtain a token. A
local-dev session against a backend with no editor tokens configured (503) or no
token entered (401) would then silently lose ALL lint feedback (a quiet gray
note, no findings ever) -- a full regression of the previously network-free
client-side lint. Filed as bd h903 (out of P4.3's exit criterion), but the fix
is a few lines in the same component, so folding it in is the right PR shaping
rather than shipping a self-inflicted regression and fixing it next.

Fix (h903 option (a)): `ValidationPanel` branches on `isHostedMode()`. Hosted
mode calls the backend linter; local mode lints synchronously via the retained
`validateSchema`, mapped into the same finding rows so display and field-focus
are identical. Both h903 exit criteria are met (local-mode lint works without a
network/auth dependency; a test asserts it).
