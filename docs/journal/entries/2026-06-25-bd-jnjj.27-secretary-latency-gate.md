## Trigger

Gate 2 of the secretary research (epic jnjj), gated on Gate 1 RECALL (jnjj.26,
"feasibility promising", PR #240). The `ask_secretary` call is BLOCKING -- the
principal (live voice model) waits mid-conversation -- so the question is whether a
cached flash-lite lookup is fast enough for live conversation UX. Two parts: (a)
establish Gemini context-caching facts from authoritative sources; (b) measure the
real round-trip and record a GO/KILL.

## What shipped

`backend/scripts/probe_secretary_latency.py` (reuses the Gate-1 renderer + corpus)
and `scripts/spikes/secretary_latency_findings.md`.

**Part (a) caching facts (authoritative -- gemini-docs MCP + live pricing/caching
pages; the vendored `docs/genai_docs/` is Live-API-only and had no caching content,
so recorded from the next authoritative tier per the bead's fallback order):**
- The secretary's ~9.5k-token static catalog clears both the explicit (2048) and
  implicit (~1-2k) minimums comfortably.
- flash-lite supports caching: $0.10/M input, $0.01/M cached (90% off), $0.40/M
  output, $1.00/M/hr storage. Explicit cache CREATE latency ~0.78s (measured live).
- **DECISION (maintainer): implicit caching now; explicit deferred to scale (~100
  concurrent users) -> bd jnjj.41.** Implicit is free/automatic; explicit's per-hour
  storage + lifecycle is overhead the input-discount does not pay back at low
  concurrency.

**Part (b) latency -- VERDICT: GO.** Clean run (n=12/arm): mean **0.83s**, median
0.81s, tail **~1.0-1.1s** (interpolated p90 ~1.07s; the probe's floor-indexed p90 of
0.89-0.95s understates the tail, so read max ~1.1s). A natural conversational beat,
well under the awkward-pause threshold; GO holds at the ~1.1s worst case. Two
structural findings: implicit caching hit **100%** (~8,122 of ~11,053 prompt tokens,
~74%, zero setup) -- the cost lever works -- and uncached vs implicit latency is
identical (0.837 vs 0.829s), so **implicit caching is a COST lever, not a latency
one**. (METHOD: both arms get a warm-up call that seeds the implicit cache, so the
"uncached" arm also shows 100% hits -- both effectively measure the warm round-trip;
the arm names describe intent. A true cold floor would disable warm-up.)

## The outage + the model-fallback resilience

At measurement time `gemini-2.5-flash-lite` (the target) was in a sustained,
widely-reported (Reddit) **503 UNAVAILABLE** outage -- intermittent, flash-lite-
generation-specific (the sibling `gemini-2.5-flash` answered ~0.67s; flash-lite
`caches.create()` worked; both confirm it was not an account/key/region issue).
Early runs were OUTAGE-CONTAMINATED (~3-6s, but a bare 1-token prompt also took
3-6s, so the slowness was the degraded model, not the ~9.5k payload) and NO verdict
was recorded off them.

This motivated a **probe-level model fallback chain** (2.5-flash-lite ->
3.1-flash-lite -> flash-lite-latest, all within the Gemini BAA), which produced the
clean number above on `gemini-3.1-flash-lite` (`is_fallback_model: true` in the
artifact) -- the newer same-tier lite model (~0.42s bare). A sound proxy; both lite
models are sub-second, so the GO is robust across them. The same resilience for the
PRODUCTION secretary/validator path (`TextAIGemini`) is filed as **bd jnjj.42**
(P2).
