## Trigger

The smooth-experience half of the 2026-07-01 goal ("I want the editor to be a
smooth experience so they can focus on the work"). The polisher core loop --
open a form, fix the yellow/red fields, mark it complete -- had three rough
edges: finding the next field needing attention meant scrolling and scanning
by eye across hundreds of rows; a FAILED save took over the whole editor with
the full-screen error state, whose only button ("Dismiss") DROPPED the loaded
schema -- a failed save could cost the very work being saved; and a contractor
landing on the hosted editor for the first time got no orientation at all.

## What shipped

**Review-flow navigation (FieldList).** A `visibleOrderedFields` memo flattens
the rendered order (sections as listed, then orphans, search filter applied)
and drives: a "Next to review" button + the N key (jump to the next field
whose status is not complete, wrapping, honoring the filter), ArrowUp/Down
(step selection through the visible list), and Escape (deselect, via a new
optional `onDeselect` prop wired from App). Guards: no modifier chords, no
firing from editable targets (typing in the search box or an editor input
never navigates). Option-row selections (`fieldId:option:n`) resolve to their
base field before positioning. Selection sync with the PDF + editor panel
rides the existing auto-scroll/expand effect untouched.

**Non-blocking save feedback (App).** New `saveError` state renders as a
dismissible `role=alert` banner between header and content; the editor and
the unsaved work stay fully alive underneath. All four save/reload failure
paths (hosted PUT, FS write, download fallback's success-reset, reload-from-
file) now set the banner instead of the full-screen `error` state -- that
state remains for open/load failures, where there is no work to lose. A later
successful save clears a lingering banner; opening another form clears it
too. The AuthError path (drop to the access gate, dirty state preserved) is
unchanged.

**First-run guide (hosted).** `HostedGuide` is a 3-step overlay (pick a form
-> fix the yellow/red fields, with the new navigation named -> save and Mark
complete) shown once per browser after the access code validates
(`schema-editor.guideSeen` in localStorage, try/catch-wrapped -- restricted
storage just means the guide shows again), re-openable from a hosted-only
Help button in the header.

Deliberately NOT folded in: bd polyglot-pdf-jplx (array-value editor for
in/not_in operators) -- the bead marked it optional-if-cheap; it is its own
editor surface with its own validation semantics, so it stays a separate P3.

## Lessons

A single-letter shortcut (N) is safe only behind an editable-target guard
checking tag/contentEditable on the event target -- the window-level listener
otherwise fires while a contractor types a field name containing "n".

The full-screen error state was designed for LOAD failures (nothing loaded to
lose) and then accreted save failures too; the distinction that matters is
not "how bad is the error" but "is there in-memory work the dismissal would
destroy".
