## Trigger

Bead polyglot-pdf-uov.9 (T2.2, under the spec-driven test epic uov, Phase 2
"high-risk invariant specs"). The existing `test_websocket_ephemeral.py` patches
`verify_token` throughout and exercises only the happy-path handshake, so the
security-critical auth gate and the documented connection-lifecycle close codes
on `/ws/fill` were entirely unspecified. The bead's charge: spec the auth gate
(verify_token raises -> close 1008 before accept), the idle watchdog
(idle_timeout message then close 1000), and warm reconnect -- filing a
finding/bug bead for each unmet behavior.

## What shipped

A new `backend/tests/integration/test_websocket_auth_lifecycle.py` (8 tests),
each assertion derived from `docs/components/websocket-routing.md` + the route
code:

- **Auth gate (security-critical, was unspecified).** A `verify_token` failure
  closes the socket with **1008 BEFORE `accept()`** and starts NO fill session --
  the close-before-accept ordering is the load-bearing contract (an
  accept-then-close, or a session started on an unauthenticated socket, is the
  regression this guards). A companion test asserts verify runs *before* accept
  on the success path, so the gate can't be silently reordered or bypassed.

- **Handshake close codes, asserted by exact code.** non-JSON -> 1007,
  non-object -> 1007, missing-schema -> 1007 (the sibling test only asserted that
  `close()` was awaited, not the code), bad-source -> 1008, and `pdf` source is
  ACCEPTED (allow-listed alongside `web`, since PDF schemas are voice-fillable).

- **Idle watchdog, against the REAL coroutine.** Drives the actual
  `_handle_fill_session` watchdog with a controllable clock (monkeypatched
  `time.time` + instant `asyncio.sleep`) so no wall-clock time elapses, and
  asserts it sends `{"type":"idle_timeout"}` and THEN closes with 1000 +
  reason "Idle timeout", with `end_session()` running in the finally block.
  **Mutation-verified:** changing the route's watchdog close code 1000 -> 4999
  fails the test, proving it exercises production code (not a stand-in).

**Finding filed (bd polyglot-pdf-01y6).** Deriving the idle spec surfaced that
`test_idle_timeout.py`'s four idle tests are FAKE coverage -- they call
`mock_ws.send_json`/`close` (and `mock_service.end_session`) *themselves* and
then assert the mock recorded the call the test just made, or define their own
local `watchdog_task` instead of the route's. They would stay green if the real
watchdog were deleted. This is exactly the rot the spec-driven epic exists to
catch. It was filed as a P3 bug wired as a prerequisite of T3.5 (uov.16,
"re-audit 'green' tests against spec") rather than fixed here -- the new test
supersedes that coverage, and rewriting the old file is T3.5's scope.

**Warm reconnect** was listed in the bead but is already specified by
`test_restart_gemini_session.py` (service level) and `test_resume_reconnect.py`,
so no new test was added for it -- noted rather than duplicated.

The bead had no `## Exit criteria` (a creation-time-norm slip); a retrospective
rubric (3 binary criteria) was written at claim time and scored at closeout.

322 backend tests pass; test-only change, no product code touched. Pre-PR
fresh-eyes assess: see merge ping for the round count + verdict.

## Lessons

The spec-driven epic's core failure mode has a concrete signature worth naming:
a test that constructs the expected payload, calls the mock with it, and then
asserts the mock was called with it. It is green, it reads as coverage, and it
verifies nothing -- deleting the production code leaves it passing. The
discriminating question when auditing a "green" test: *does any production
symbol appear on the path between the arrange and the assert?* For the idle
watchdog, the honest version had to import and run `_handle_fill_session` and
let ITS watchdog drive the mock. A cheap guard against writing the fake version
yourself: mutation-check one assertion (here, flip the close code) and confirm
the test goes red. Added the signature to docs/standards/testing.md.
