## Trigger

First bead of Lane 2 (extractor/safety-net) of the schema-v2 epic
`polyglot-pdf-h76m` (plan: `~/.claude/plans/rustling-discovering-hearth.md`,
P1.3). A live shipped bug found during the epic's design verification:
voice-filled checkbox groups silently fail PDF fill. The backend prompt
(config.py "Multiple checkboxes: comma-separated exact values") makes Gemini
deliver a group selection as ONE comma-joined string; `/api/fill-pdf` handled
only bool (standalone) and list (group), so the string fell to the
`checkbox_unsupported_value` branch and the group stayed empty on the printed
PDF. The frontend's existing comma-split (bd vq4m) is gated on
`group_kind == "checkbox"`, which no shipped kit sets, so it never fired
either.

## What shipped

One canonical value shape (string[]) for checkbox-group selections,
established at the AI-value ingress:

- `frontend/src/webFormConnection.ts`: new exported
  `canonicalizeAiCheckboxGroupValue(field, value)` -- for a checkbox field
  WITH options (the renderer's own group rule; CheckboxField renders
  options-bearing checkbox fields as a multi-select storing string[]) or one
  explicitly marked `group_kind: "checkbox"`, a string value is split on
  commas into a trimmed string[] (empties dropped; a single no-comma selection
  becomes a one-element array). Non-string values and all other field types
  pass through untouched. Called inside `applyAiValueWithValidation` (the
  single funnel all AI call sites use) BEFORE validate/store, and at the three
  call sites so the `onFieldUpdate` callback carries the stored shape.
- `backend/routes/pdf_fill_routes.py`: defensive comma-split in the checkbox
  branch (str value on an options-bearing field -> list) for sessions whose
  sessionStorage predates the frontend fix.
- Evaluator semantics untouched: the vq4m comma tolerance in
  `shouldShowField`/`validateOptionMembership` stays until the epic's P6.2
  strictness flip. This bead canonicalizes value SHAPE only, so it neither
  waits for nor invalidates the P0.1 vector suite.
- Tests: `backend/tests/test_pdf_fill_checkbox_group_comma.py` drives the real
  `/fill-pdf` route against the on-disk i-90 kit with a voice-shaped comma
  value and asserts widget /AS on-states (proven RED with the fix stashed,
  green with it); plus single-string and canonical-list cases.
  `frontend/src/webFormConnection.checkboxgroup.test.ts` pins the ingress
  split end-to-end through the field_update path (11 tests, incl. wrapper
  unwrap, standalone-boolean passthrough, and group_kind fallback).

Exit criteria: (1) voice-shaped comma value round-trips into a real PDF fill
-- PASS (new backend test, proven red pre-fix); (2) existing frontend +
backend suites stay green -- PASS (771 backend passed, 535 frontend passed).

## Lessons

- A "shipped" feature can be dead on one path and alive on another: the
  comma-split existed (vq4m) but was gated on an optional schema key
  (`group_kind`) with 0% kit adoption, so the voice path never hit it. Gate
  behavior on structural facts (options present -- the renderer's own rule),
  not on optional metadata nobody sets. This is the epic's core thesis
  (a TYPE is total; an optional marker can be forgotten) showing up in
  miniature.
- Proving a regression test red before the fix (git stash push <file> ->
  run -> pop) is cheap and catches tests that pass vacuously.
