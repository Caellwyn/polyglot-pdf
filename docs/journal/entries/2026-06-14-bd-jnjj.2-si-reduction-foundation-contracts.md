## Trigger

Phase 0 of the SI-reduction epic (bd polyglot-pdf-jnjj). The epic plan calls for
three FROZEN standards docs to land before any pillar work forks, so multiple
agents can build pillars A (SI-reduction), B (cheap-model validator), and C
(restart-cadence) in parallel without colliding on shared interfaces (the SI
templates, the WS handshake, the validator message shapes). This PR bundles the
three foundation doc beads -- F1 (jnjj.2), F2 (jnjj.3), F3 (jnjj.4) -- which are
individually too small to each warrant a full PR cycle. F0 (the d24n fix, PR #195)
merged first as the hard predecessor; this is the next layer it unblocked.

## What shipped

Three new tier-2 standards docs, plus their registration in `docs/INDEX.md`.
Doc-only -- no code touched.

- **F1 `docs/standards/si-reduction.md`** -- the SI-template contract. Pins the two
  templates (`SYSTEM_INSTRUCTION` legacy / `JIT_SYSTEM_INSTRUCTION`) and the exact
  placeholder sets (shared vs legacy-only `{fields_json}`/`{unfilled_count}` vs
  JIT-only `{manifest_text}`/`{next_field_schema}`), the reduced-SI target
  (`fields=[]`, ~1,850-token rendered floor measured by the G2 gate, not modeled),
  and records that the ADDRESS-CONSISTENCY prose removal is owned by B1 (jnjj.13),
  gated on the G1 detection gate, and serialized B1 -> A3 on the shared config.py
  block.

- **F2 `docs/standards/ws-protocol.md`** -- the `/ws/fill` wire contract. Enumerates
  the full handshake schema (legacy vs JIT modes, the `session_ready` ack) and the
  complete bidirectional `{"type": ...}` message-type union, each verified against
  real file:line. Reserves the epic's extension points tagged per pillar
  (B's `section_complete`/`form_complete`/`validation_result`/`steering`; C's
  `session_resumption_handle`). **Found one benign FE/BE drift** (flagged, not
  fixed -- doc-only bead): `section_id` and `initial_field_hint` are read by the
  backend but omitted by the primary handshake builder (sent only on
  section-switch); the backend tolerates `None`, but any pillar that comes to
  DEPEND on them at first-connect must close the gap first.

- **F3 `docs/standards/validation-delegation.md`** -- the cheap-model validator
  contracts: the verdict shape (`{conflicts:[{field_ids, reason}]}`, empty = clear),
  the minimal client-state payload (filled values + field identity, no schema
  overhead), the steering message (preserving the user-override escape hatch + a
  max-resteer-once bound), the section/form-complete payloads, the net-new
  `ITextAI` port (mirroring `ILiveAI`, `get_text_ai()` in dependencies.py), and the
  PII/PHI data-flow sign-off (same vendor + trust boundary as the Live model
  already uses; no PHI logged at the new call site -- the existing
  `test_no_pii_logging_anywhere_in_backend` sweep auto-covers the new module).

**Defended decision (F3): reuse `MODEL_LABELING` for the validator model id, do not
rename to `MODEL_VALIDATOR`.** It is already the project's orphaned "cheap non-Live
text model" knob (only `/health` reads it today); the validator is exactly that
role. A rename buys a new Settings field + /health edit + deploy plumbing for zero
behavioral gain. The only cost is the stale name, which is cosmetic and reversible
(split later if a real labeling model returns). Decide-by-default naming call, no
external contract; noted for the maintainer to overturn.

## Lessons

- **Freeze shared contracts as docs BEFORE forking parallel work.** The three
  pillars all write the same config.py SI block, the same handshake dict, and a
  shared validator/section-complete protocol. Naming the owner of each contract
  (and the serialization order on shared files) up front is what lets agents run in
  parallel without a merge pileup. The conflict cheat-sheet in the epic plan + these
  three docs are that coordination surface.
