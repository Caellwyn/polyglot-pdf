## Trigger

A1 (bd polyglot-pdf-jnjj.8) is the first Pillar-A bead of the SI-reduction epic,
and a deliberate one: the `USE_JIT_SCHEMA` path (the manifest-first SI the epic
reduces toward) was built by weaker models, so the bead is "examine + improve",
NOT "flip the flag". This is the read-only audit half -- catalog every correctness
gap in the JIT path so A2 (the fixer, jnjj.9) builds from a fix-list rather than
rediscovering the bugs. The F0 fix and the F1/F2/F3 foundation contracts merged
first (PRs #195, #202); Codex's review of F1 already surfaced several JIT gaps,
which this audit confirms and extends.

## What shipped

A new component doc `docs/components/jit-schema.md`: the JIT data flow as it
actually runs today, plus a 15-gap catalog (file:line + severity + fix-now/defer),
plus an ordered A2 worklist. No functional code touched (the bead's third exit
criterion).

**The core incoherence the audit nails:** the frontend builds a full-section
manifest (`{current_section, previous_sections, parts}`) and sends it on the JIT
handshake, but the backend ignores `current_section`/`previous_sections` and
REGENERATES the manifest from `schema["fields"]` -- which in JIT mode is just the
single `first_field_schema`. So today the "reduced SI" carries ONE field, not the
section, and never the previous sections.

**Gap split (9 fix-now, 6 defer):**
- **Fix-now:** A (handshake manifest ignored -> regenerated from one field),
  B (manifest_text lists only the first field), C (previous_parts hardcoded `[]` ->
  no cross-section recall via the manifest), D (next_field_schema is first-field not
  first-UNFILLED -- and the JIT handshake also omits `initial_field_hint`, so BOTH
  next-field placeholders are wrong in JIT). Plus five the F1 contract did NOT have:
  **L** (handshake `loaded_field_ids` never seeded into `self._loaded_field_ids`, so
  field schemas are re-sent on every reconnect), **G**
  (`should_include_schema_in_response` is dead-code -- imported, zero call sites),
  **M** (`previous_spoken_names` always empty in JIT mode -- a SEPARATE
  cross-section path from C; `get_field_value` prior-section lookups are dead),
  **N** (`filled_count`/`total_fields` read the one-field `schema["fields"]` so the
  SI progress count is always "x/1" per section), and **O** (`{form_title}` reads a
  `form_metadata` key the JIT schema lacks, so the SI says "Form" for every form --
  the model never learns it's filling an I-90 vs I-485).
- **Defer:** E (telemetry log reads a non-existent `manifest.fields` -> always 0;
  now flagged to fix DURING A2 since it misleads the fix's own debugging),
  F (part->section terminology holdout, already deferred per terminology.md),
  H (estimate_manifest_tokens is test-only), I (options-format code duplicated
  legacy/JIT), J (no handshake-shape validation on the JIT path), K (manifest stored
  in schema dict but unused).

A--D were independently confirmed by Codex's F1 review (PR #202); G and L were this
audit's own findings; **M, N, O, and the next_field_hint half of D were fresh-eyes
finds** across two pre-PR assess rounds (real correctness gaps an audit must not
miss -- three more SI placeholders that read the one-field schema or omitted
handshake data through independent code paths). The A2 worklist (fix-now in
dependency order, keystone = consume the handshake manifest) is recorded on bead
jnjj.9.

**Process:** the orchestrator read manifest_service.py + the JIT context branch
directly and dispatched one Explore agent to trace the full frontend->handshake->
backend->SI data flow; the two highest-value NEW findings (G dead-code, L de-dup
not wired) were orchestrator-verified by grep before writing the doc.

**Fresh-eyes assess (Step 5.5.b, sonnet).** Round 1: `GAPS-FOUND (3)` -- and exactly
the right catch for an audit (a missed gap fails criterion 1). It found two
correctness gaps the audit missed -- **M** (`previous_spoken_names` always empty in
JIT) and **N** (`filled_count`/`total_fields` always "x/1" in JIT) -- both verified
against code as independent SI placeholders reading the one-field schema, plus a
factual inaccuracy in Gap D (I wrote `{next_field_hint}` "computes correctly" but the
JIT handshake omits `initial_field_hint`, so it falls back to a generic string too).
All adopted: added M + N as fix-now, corrected D to cover both placeholders, and
elevated E to "fix during A2" per its operational-hazard note. Round 2: `GAPS-FOUND
(1)` -- confirmed M/N/D accurate, traced the REST of the JIT placeholders
(`section_list`, `confirmation_policy` OK) and found one last hole, **O**
(`{form_title}` always "Form"), plus a citation typo in D (`:694` is in
`websocket_routes.py`, not `ai_context.py`). Both fixed. Round 3: `NO-GAPS` -- the
definitive coverage pass enumerated all 13 `JIT_SYSTEM_INSTRUCTION` placeholders and
confirmed each is either catalogued (A/B manifest, D x2 next-field, M spoken-names,
N progress, O form-title) or verified-correct in JIT (`section_number`,
`total_sections`, `section_label`, `section_list`, `fill_language`,
`confirmation_policy`). The fresh-eyes loop did exactly what an audit reviewer should
-- exhaustively check that "every gap" is actually every gap; the convergence
(3 -> 1 -> 0) plus the final placeholder-by-placeholder enumeration gives confidence
the JIT placeholder set is fully covered for A2. This is the review record (docs-only
PR -> Codex skipped).

## Lessons

- **"Examine + improve" beads earn their keep.** Flipping `USE_JIT_SCHEMA` on
  without this audit would have shipped a reduced SI that silently carries one field
  per section and re-sends schemas on every reconnect -- a cost/correctness
  regression the G2/G3 gates might have caught only as a confusing number. Auditing
  the weaker-model infra first turned "flip the flag" into a concrete, ordered
  fix-list.
- **A contract review (Codex on F1) and a code audit (A1) are complementary, not
  redundant.** Codex found the contract-level gaps (A--D) from the docs; the code
  audit found the wiring-level gaps (G, L) the docs never described. Run both.
