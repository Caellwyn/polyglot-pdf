## Trigger

A1 (bd polyglot-pdf-jnjj.8) is the first Pillar-A bead of the SI-reduction epic,
and a deliberate one: the `USE_JIT_SCHEMA` path (the manifest-first SI the epic
reduces toward) was built by weaker models, so the bead is "examine + improve",
NOT "flip the flag". This is the read-only audit half -- catalog every correctness
gap in the JIT path so A2 (the fixer, jnjj.9) builds from a fix-list rather than
rediscovering the bugs. The F0 fix and the F1/F2/F3 foundation contracts merged
first (PRs #195, #202); Codex's review of F1 already surfaced several JIT gaps,
which this audit confirms and extends.

## What shipped

A new component doc `docs/components/jit-schema.md`: the JIT data flow as it
actually runs today, plus a 12-gap catalog (file:line + severity + fix-now/defer),
plus an ordered A2 worklist. No functional code touched (the bead's third exit
criterion).

**The core incoherence the audit nails:** the frontend builds a full-section
manifest (`{current_section, previous_sections, parts}`) and sends it on the JIT
handshake, but the backend ignores `current_section`/`previous_sections` and
REGENERATES the manifest from `schema["fields"]` -- which in JIT mode is just the
single `first_field_schema`. So today the "reduced SI" carries ONE field, not the
section, and never the previous sections.

**Gap split:**
- **Fix-now (6):** A (handshake manifest ignored -> regenerated from one field),
  B (manifest_text lists only the first field), C (previous_parts hardcoded `[]` ->
  no cross-section recall), D (next_field_schema is first-field not first-UNFILLED ->
  points at a filled field on reconnect). Plus two the F1 contract did NOT have:
  **L** (handshake `loaded_field_ids` never seeded into `self._loaded_field_ids`, so
  field schemas are re-sent on every reconnect -- `form_filling_service.py:55`/`665`)
  and **G** (`should_include_schema_in_response` is dead-code: imported at
  `form_filling_service.py:23`, zero call sites -- the schema de-dup gate is never
  applied).
- **Defer (6):** E (telemetry log reads a non-existent `manifest.fields` -> always
  0), F (part->section terminology holdout in manifest_service.py, already deferred
  per terminology.md), H (estimate_manifest_tokens is test-only), I (options-format
  code duplicated legacy/JIT), J (no handshake-shape validation on the JIT path),
  K (manifest stored in schema dict but unused).

A--D were independently confirmed by Codex's F1 review (PR #202); E--L are this
audit's own findings. The A2 worklist (fix-now in dependency order, keystone =
consume the handshake manifest) is recorded on bead jnjj.9.

**Process:** the orchestrator read manifest_service.py + the JIT context branch
directly and dispatched one Explore agent to trace the full frontend->handshake->
backend->SI data flow; the two highest-value NEW findings (G dead-code, L de-dup
not wired) were orchestrator-verified by grep before writing the doc.

## Lessons

- **"Examine + improve" beads earn their keep.** Flipping `USE_JIT_SCHEMA` on
  without this audit would have shipped a reduced SI that silently carries one field
  per section and re-sends schemas on every reconnect -- a cost/correctness
  regression the G2/G3 gates might have caught only as a confusing number. Auditing
  the weaker-model infra first turned "flip the flag" into a concrete, ordered
  fix-list.
- **A contract review (Codex on F1) and a code audit (A1) are complementary, not
  redundant.** Codex found the contract-level gaps (A--D) from the docs; the code
  audit found the wiring-level gaps (G, L) the docs never described. Run both.
