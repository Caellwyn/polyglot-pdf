## Trigger

This is Phase 1 of epic `polyglot-pdf-r3ham`, the post-migration validation of
`gemini-3.8-live`. Every behavioural, cost and latency figure in the repo had
been measured on 2.5, and 2.5 native audio retires on Vertex on 2026-12-13. The
goal was one production-config run per form to find obvious deficiencies before
spending on the n=3 benchmark.

## What shipped

- `scripts/spikes/3p8_smoke_findings.md`: a headline table and a scored
  checklist. Each defect has its own bead: j9jpk (mid-sentence cut-offs),
  r3ham.8 (silent_turn false positive), r3ham.9 (re-asks for a spelling
  forever), r3ham.10 (blank 'same as' write desync) and r3ham.11 (GoAway at
  about 9.5 min).
- The raw run artifacts for six live Vertex runs (about $5.8) under
  `scripts/spikes/data/r3ham/smoke/`. Debug transcripts are not committed.
- Harness: the name answers in `W7_QUESTIONS` and `I90V2_QUESTIONS` now
  include the spelling, plus the new gTTS fixture clips for them.
- At closeout, a by-hand pass found that the W-7 "fields correct" score is
  LENIENT: W-7 has no expected-value table, so any non-empty write counts as
  correct. Both models wrote "Anna" for "Ana, A N A", and 2.5 inserted a digit
  into the passport number. The strict score is 20/22 on both models. Added to
  the doc together with the unscored checklist rows (duplicate calls, date
  format, declined field, language drift, reconnect).
- Rebased off the squash-merged PR #909 onto dev as a single commit.

## Lessons

- **A lenient scorer hides the exact error class you are testing.** "Any
  non-empty write" counted a misspelled spelled name as correct on both models.
  Before quoting a fill-accuracy number, check whether that form has an
  expected-value table.
- 3.8 follows "ask for the spelling" literally, while 2.5 was forgiving. A
  scripted user that does not spell turns an SI instruction into a dead end on
  3.8.
