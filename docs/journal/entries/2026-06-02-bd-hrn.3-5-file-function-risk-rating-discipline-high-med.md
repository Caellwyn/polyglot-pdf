## What shipped

**hrn.3 — risk-rating discipline.** New tier-2 standard
[`docs/standards/risk-rating.md`](../../standards/risk-rating.md): a static
high/med/low risk rating of files (+ key functions), where "risk" = a file's
**blast radius** (a property of the file, not of any one diff). The high-risk
criteria deliberately mirror the three fresh-eyes self-escalation triggers
(genai wiring · exports a cross-file contract · money/PII surface), so the doc
and the agent clause stay in lockstep. Seeded from the plan's `RISKY_GLOBS`
intuition (`live_ai_gemini.py`, `websocket_routes.py`, `pdf_fill_routes.py`) and
extended by walking the actual backend layout — verified `live_ai_gemini.py` is
the only *non-test* `google-genai` importer (its unit test imports the SDK too),
that `config.py` is imported by ~7 source modules, and located
`callback_handler.py` under `services/` (the PII path). Anything unlisted
defaults to `low`. Wired the fresh-eyes self-escalation clause
(`.claude/agents/fresh-eyes-reviewer.md`) to lean on the doc as the cheapest
"risky-despite-being-short" signal, and registered the doc in `INDEX.md` +
`standards/README.md`.

**hrn.6 — merge-conflict resolution.** Added a Step-7 subsection to the closeout
skill (`.claude/skills/closeout/SKILL.md`) and mirrored the principle in
`docs/doctrine/review-flow.md`. The boundary: the orchestrator **resolves
mechanical/ordering conflicts inline** (append-only journal/ledger rows,
changelog interleaving, independent list/table additions → keep both sides,
order naturally, re-read to confirm both intents survived) and **escalates ONLY
genuine structural incompatibility** (same-logic/contract change where keeping
both is wrong and choosing is a design call; **ambiguous counts as structural**,
and on escalation you `git rebase --abort` first so the branch is left clean, not
half-merged). This makes "don't stop the maintainer to hand-merge a journal
ordering" an explicit rule, consistent with the escalation doctrine (hrn.11).

**Verification.** hrn.6's mechanical recipe was verified against a synthetic
append-only journal conflict in a throwaway repo: the collision produced a normal
conflict, "keep both, chronological" resolved it, and `rebase --continue`
succeeded with both entries intact. The structural→escalate branch is a
behavioral instruction (abort + ask), not a mechanizable test; the boundary is
unambiguous via ambiguous-counts-as-structural.

**Decisions made autonomously** (defended in the merge ping): bundling both beads
into one PR; risk-rating as a standards doc + RISKY_GLOBS seed (maintainer-chosen
form); adding `harness` + `doctrine` to the tag vocabulary (two tags with an
immediate consumer — this entry — declining the speculative `docs`/`architecture`
ones). The only escalation this PR: re-authorizing the blocked edit to the
fresh-eyes agent definition (auto-mode flagged it as self-modification outside the
bead's declared surfaces) — the maintainer approved it.

## Lessons

- **A risk doc and a reviewer prompt that drift apart are worse than neither.**
  Keeping the high-risk *criteria* identical to the self-escalation *triggers*
  (rather than two independent lists) is what makes the doc trustworthy as a
  lookup — generalized into the doc itself ("these mirror the triggers so the doc
  and clause stay in lockstep").
- **Mechanical-vs-structural is the right cut for autonomous conflict handling.**
  "Keep both" is safe precisely for append-only artifacts; the danger is a
  same-line *logic* clash, which is exactly where ambiguous-counts-as-structural
  routes to a human. Mirrors the existing "ambiguous = blocker" safe-default.
- **Auto-mode self-modification guard is load-bearing.** Editing an agent
  definition was correctly blocked even mid-task; the fix is to surface it and let
  the maintainer authorize, not to route around it.
