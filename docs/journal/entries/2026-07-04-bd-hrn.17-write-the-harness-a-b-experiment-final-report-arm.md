## What shipped

- **`docs/journal/telemetry/FINAL_REPORT.md`** -- the report. Loads all 199 telemetry
  rows (per-file dir + legacy JSONL, deduped by `(session_id, recorded_at)`), buckets
  the production rows (audit-category rows are never charged to an arm) by arm,
  and compares A / B / C / BC on cost, review rounds, maintainer touchpoints,
  deferred nits, Haiku escalations, and errors shipped.
  - **Verdict: keep B (fresh-eyes Haiku tiering) + C (bounded review loop); adopt
    the combined BC as the standing default** (which is already how closeout runs).
  - **Basis:** 0 errors shipped across all 138 production rows that recorded the
    counter (the guardrail gate, passed by every arm), and BC cuts maintainer
    touchpoints to 0.33/PR vs baseline A's 0.98/PR.
  - **Reported honestly as under-powered on cost:** B and C never hit their
    independent >10 thresholds (the experiment jumped straight to BC), and the
    `cost_usd` block was added late (bd cb6i) so only 22/127 A rows and 6/18 BC rows
    carry a dollar figure. Cost is presented as directional, not decisive.
  - **#282-284 flagged, per the bead's costing note:** those three BC rows (beads
    92qe.3/.4/.5) ran while Codex was quota-exhausted and the Opus-4.8 fallback
    reviewer ran instead. They are 3 of the 6 costed BC rows and the 3 most
    expensive ($708/$812/$851); excluding them drops BC clean cost from ~$497 to
    ~$203/PR. The report flags them explicitly rather than treating them as typical.

- **Directive off-switch (the second exit criterion).** The arm counter is derived
  by counting rows, and rows are never deleted, so `arm_BC > 10` stays true forever
  -- the "write the report" directive would nag on every future closeout. Added a
  committed sentinel `docs/journal/telemetry/REPORT_DONE`; `harness_ledger.py`
  `phase_directive()` now short-circuits to a terminal "experiment CLOSED" line when
  the sentinel exists. The sentinel path is derived from `TELEMETRY_DIR` at call
  time (bare `REPORT_DONE_FILENAME` constant, not a frozen import-time path) so a
  monkeypatched `TELEMETRY_DIR` in tests is honored. Delete the sentinel to re-open.

- **Tests:** added `test_report_done_sentinel_closes_experiment` and isolated the
  existing threshold-directive test from the now-present real sentinel by passing an
  explicit absent-sentinel path. 49/49 ledger tests pass; full suite 772 passed.

## Lessons

- **A derived-from-data counter needs an explicit terminal state.** Because the
  experiment phase is recomputed from never-deleted rows, no amount of new activity
  could move it past "report" -- the directive had no natural off-ramp. A committed
  sentinel is the minimal, reversible off-switch that doesn't corrupt the
  row-derived counts.
- **A module-level path constant that mirrors a monkeypatched constant is a test
  trap.** `REPORT_DONE_SENTINEL = TELEMETRY_DIR / "..."` froze the real repo path at
  import, so it ignored a test's monkeypatched `TELEMETRY_DIR` and short-circuited
  unrelated threshold tests. Deriving the path at call time from the (patchable)
  dir constant fixes it. Generalizes to any script whose tests monkeypatch a path.
