## Trigger

`bd polyglot-pdf-7a9.12` (B1), sprint 5 / epic 7a9 -- the extraction half of the
I-90 authoring loop. D1 lets a human ONBOARD a form; B1 is what produces its first
draft schema. The bead (rescoped from "adopt LLM-native pass / retire heuristics"):
ship a one-command `form.pdf -> draft FormSchema`, picking the prompt EMPIRICALLY
(plain claude-hybrid vs the enriched bundle) on I-90, big-form work deferred.

## What shipped

`scripts/authoring/extract_form.py` -- a single command (PDF -> schema-valid draft)
that reuses the bakeoff machinery and adds two deterministic improvements:
- **pdf_position back-fill from the dump.** The LLM scored pos 0% on BOTH raw arms
  (it does not copy coordinates), but the AcroForm dump has every widget rect keyed
  by exact name and the draft copies that name verbatim into pdf_field_name -- so a
  deterministic map recovers ~97-99% positions for free, beating either raw arm.
- **normalize-then-Pydantic-validate.** Fills required-but-missing scalars
  (form_metadata.version etc.) with draft placeholders, then validates against the
  canonical backend FormSchema so the draft is schema-valid out of the box.

`arm_llm_native.py` gained `--plain` (the claude-hybrid prompt: raw AcroForm field
list, no enrichment) so the prompt bake ran on the SAME Claude-CLI backend + scorer
as the enriched arm.

## The empirical pick: plain claude-hybrid

Fresh I-90 bake, n=2 each, identical harness:

| arm | F1 | type | pfn | b.cond |
|---|---:|---:|---:|---:|
| plain (claude-hybrid) | 96.2 | 93.6 | 100 | **45.0** |
| enriched | 96.2 | 95.5 | 100 | 31.9 |

Tied on F1 + pfn; plain wins relationship recall (b.cond 45.0 vs 31.9, the harder
touch-up half), enriched edges type within run variance. -> `DEFAULT_PLAIN = True`,
consistent with 7a9.10/7a9.11 (the enrichment layer does not earn its place on
I-90-grade forms and regresses on big forms).

End-to-end, the shipped tool scored F1 96.7 / type 97.0 / pfn 100 / pos 96.9,
schema-valid -- at or above the reference claude-hybrid arm (F1 96.0 / type 96.9 /
pfn 100) on criterion 2's metrics (type + pfn + F1). Full table + the
"best-of-any-arm is a mix of degenerate arms" caveat in the findings doc:
`docs/research/2026-06-15-7a9.12-i90-authoring-pass-findings.md`.

## Lessons

- **When the LLM is flaky at a thing the deterministic layer already has, do it
  deterministically.** pdf_position is in the AcroForm dump exactly; prompting the
  model to copy coordinates got 0%, a six-line dump->name->rect map got ~99%. The
  strong-LLM pass should reason over structure it CAN'T get deterministically
  (labels, relationships), not re-transcribe what the dump already holds.
- **"Best arm" must mean best USABLE arm, not max-per-metric.** A naive per-metric
  max across all bake-off arms gives F1 98.5 / type 100, but those come from
  degenerate arms (a hybrid with type 91.6 / pos 0; multimodal arms with F1 2-17).
  The honest bar is the best arm that works end-to-end -- claude-hybrid -- and the
  shipped tool meets it. Cherry-picking the per-metric max would have set an
  unmeetable, dishonest bar.
- **A tie on (a) + a small win on (b) + a deterministic post-step beats agonizing
  over noise.** The two prompts were statistically tied on extraction; the decision
  came down to the higher-value relationship metric and prompt simplicity, then the
  position backfill made the shipped tool better than either arm regardless.
