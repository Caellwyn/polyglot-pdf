## Trigger

Sprint-6 editor-authoring epic (s4dp), bead B2. The schema author can EDIT a
form's conditional logic (show_if, radio/checkbox grouping) but had no way to TEST
it -- a read-only PDF + raw JSON give no behavioral feedback. This is the epic's
capstone: it validates the grouping (B1) and the show_if logic the editor produces.

Maintainer steer (important): the preview must be COMPLETELY INDEPENDENT of the
voice model / live app -- it may seed a separate product. Do NOT embed
`frontend/src/schema-forms/` (wired to the voice app's WS/state/connection). REUSE
the field-rendering behavior in a NEW standalone pane with its own local value
state.

## What shipped

An Edit/Preview toggle on the editor's right pane that swaps the `FieldEditor` for
a live interactive `PreviewPane`. The PDF viewer and field list stay visible in
both modes, so the author can locate a field while previewing.

- **`schema-editor/src/components/PreviewPane.tsx`** -- renders the loaded schema
  as clickable inputs with its OWN local `fieldValues` state. Radios are mutually
  exclusive (a single selected value); checkbox GROUPS multi-select into an array;
  a lone checkbox is a boolean; select/text/textarea/date/number/tel/email render
  appropriately; signature/table are non-interactive stubs. Only VISIBLE fields
  render -- a `show_if`-gated field appears/disappears as its controlling field
  changes. Sections are the grouping unit (mirroring the editor's nav unit).
- **`schema-editor/src/utils/conditionalVisibility.ts`** -- a self-contained
  `shouldShowField` evaluator. schema-editor had NO conditional-visibility code
  (only reference-integrity validation), and the bead forbids importing the voice
  runtime's `shouldShowField`. So this is a FAITHFUL port of that runtime's
  semantics (`frontend/src/schema-forms/utils/validation.ts`): checkbox-group
  triggers compare by MEMBERSHIP for `equals`/`not_equals`, the comma-joined-string
  split is gated on the trigger actually being a checkbox group (so a scalar like
  "Springfield, IL" is never split), and all 10 operators match the runtime.
  Keeping it a faithful port means the preview's show/hide matches what the voice
  app will actually do.
- **`schema-editor/src/App.tsx`** -- `viewMode` state + the Edit/Preview toggle.

**Independence (crit 1).** The two new files import only `react` and the editor's
own `../types/schema` + `../utils/conditionalVisibility`. A static grep confirms NO
import from `frontend/src/schema-forms`, `webFormConnection`, `SchemaFormState`, or
`shared/` -- no WS, no backend call, no connection layer. The pane is the seed of a
potential standalone product, per the steer.

**Scope.** Interactive enough to test radio exclusivity, checkbox multi-select, and
show_if visibility -- NOT full validation/submission. `controls_fields`
lock/unlock is intentionally NOT implemented: the voice runtime's `isFieldReadOnly`
does not implement it either (it returns the static `read_only` flag), so the
preview matches production by gating purely on `show_if` + the static `read_only`.

**Fresh-eyes (pre-PR Assess).** 2 Sonnet rounds. Both criteria scored PASS each
round. Round 1 found 5 issues (all addressed inline): (1) unknown show_if operator
showed unconditionally instead of falling back to !field.hidden; (2) is_empty/
is_not_empty diverged from the runtime on a checkbox-group array -- resolved by
matching the runtime bug-for-bug so the preview shows production behavior, and
filing the runtime fix as a new bead (rigd); (3) a lone checkbox rendered its
label twice; (4) preview values leaked across a form switch (no remount); (5) the
group-detection key divergence was undocumented. Round 2: NO-GAPS, all fixes
verified against the real runtime. Filed: **rigd** (runtime is_empty/is_not_empty
array bug, out of scope here).

## Why a fresh evaluator (not reuse)

The voice runtime's `shouldShowField` is the authoritative behavior, but it lives
in `frontend/src/schema-forms/` -- the layer the bead explicitly forbids depending
on (it is wired to the WS/state machinery). schema-editor had no equivalent. So the
correct move was a faithful PORT into schema-editor, not an import. The port is
exercised by parity tests (checkbox-group membership, comma-split gating, every
operator) so a future divergence from the runtime is caught.
