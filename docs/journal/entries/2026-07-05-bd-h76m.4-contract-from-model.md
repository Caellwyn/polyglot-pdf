## Trigger

Lane-3 bead of the schema-v2 epic `polyglot-pdf-h76m` (plan:
`~/.claude/plans/rustling-discovering-hearth.md`, P1.2), unblocked by the P1.1
model core + registry (bd h76m.3). The extractor contract handed to every LLM
arm (`scripts/bakeoff/schema_contract.py`) hand-copied the conditional-operator
list and the choice-field example. That copy had already drifted to the retired
v1 vocabulary: option.value = widget-leaf identifier (v2 uses a semantic slug),
and `equals`/`unlocks` with widget-leaf values (v2 uses `includes`/`not_includes`
membership on option slugs). A drifted contract teaches the model to emit the
exact shape the v2 validator now rejects.

## What shipped

- `schema_contract.py` renders its MACHINE CORE from the single source of truth:
  - `render_operator_block()` builds the operator table from
    `conditional_vocabulary.OPERATORS` (name, value arity, trigger types, notes)
    -- no hand-copied list.
  - `CANONICAL_EXAMPLE` is ONE dict that is both embedded in the prompt (via
    `render_example()`) AND fed to `FormSchema.model_validate` by the sync test,
    so the illustrated example and the validated example can never diverge. It
    exercises the load-bearing v2 conventions: a `checkbox_group` with slug
    option values + per-box `pdf_field_name`, and a dependent field using
    `show_if includes <slug>`.
  - `SCHEMA_CONTRACT` keeps its module-level name (the bake-off arms import it
    directly), now assembled from the rendered core + a stable prose shell.
- Graceful fallback: the bake-off arms run standalone from `scripts/bakeoff/`
  where the `backend` package may be unimportable. The module adds the repo root
  to `sys.path` and, if the import still fails, renders from a STATIC snapshot
  (`_STATIC_OPERATOR_LINES`) kept byte-identical to the registry render by the
  sync test. So the contract always renders; only the drift GUARD needs the
  backend (always present in CI).
- `tests/test_schema_contract_sync.py`: rendered operator set == registry
  `ALLOWED_OPERATORS`; static snapshot == registry render (the drift guard);
  every operator name appears in the prompt; `CANONICAL_EXAMPLE` validates as v2.
  `test_drift_is_detected` monkeypatches a divergent registry and asserts the
  guard trips -- a permanent regression proof.
- `scripts/authoring/fewshot/v2_new_vocabulary_exemplar.json` (+ `README.md`): a
  hand-authored v2 exemplar teaching `checkbox_group` + slug option values +
  shared-name `radio` (via `pdf_on_value`) + `equals`/`includes` membership.
  `tests/test_fewshot_exemplars.py` pins that every exemplar under the dir passes
  `FormSchema.model_validate` as v2 AND lints clean (a broken exemplar would
  teach the model to emit broken schemas).

## Why two guards, not one

The P1.1 model already fails at IMPORT time (`form_models.py`) if the registry
and the `ConditionalOperator` enum disagree -- that guard catches registry<->enum
drift. This bead's sync test catches the layer ABOVE it: drift between the
registry and the rendered contract's static snapshot, which the enum guard cannot
see. Both bite on a real registry change; they cover different seams.

## Scope boundary

P1.2 delivers the exemplar FILE and its validate/lint-clean guarantee. WIRING the
exemplar into the production `extract_form.py` prompt is P5 (extractor-v2)
territory -- the plan reviews few-shot EFFECT at P5.2/P6, and `extract_form.py`
does not consume few-shot today (that is the bake-off arm's `--fewshot-truth`
path). Reaching into the extractor prompt now would exceed the bead.
