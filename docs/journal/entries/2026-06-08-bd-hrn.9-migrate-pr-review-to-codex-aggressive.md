## Trigger

The repo's prepaid GitHub Copilot review credits ran out (the marker bead hrn.8
fired -- maintainer confirmed exhaustion on 2026-06-07), green-lighting the
planned Copilot -> OpenAI Codex cutover (hrn.9). Mid-sprint the maintainer added a
second, related ask that became bead nvd: Codex's reviews were too quiet because
its system instructions surface only P0/P1 issues, so they wanted AGENTS.md
rewritten to redefine P0/P1 broadly and make the review aggressive. Both beads
shipped in this one PR (bundled per the bead/PR contract -- both touch the same
Codex-review surface, so one review cycle is cheaper).

## What shipped

**hrn.9 -- Copilot -> Codex trigger cutover.** Most of the Codex infrastructure
already existed (the watcher's CODEX_PROFILE with the 👍/+1 clean-reaction
classification, the AGENTS.md review etiquette, the installed
`chatgpt-codex-connector[bot]` app). The real gap was the trigger mechanism:
Copilot was REQUESTED via the GitHub reviewer API (`requested_reviewers`), but
Codex works differently. Two facts the maintainer supplied reshaped the
implementation mid-build:

1. Codex is triggered by an `@codex review` COMMENT, not the reviewer API.
2. **Codex AUTO-REVIEWS on PR open** -- so round 1 needs no trigger at all; only
   round 2+ re-reviews need an explicit `@codex review` comment.

Final design: `closeout_finish.py::request_review()` posts NO round-1 comment --
the `@codex review` nudge rides in the PR BODY and the auto-review fires on open;
the watch `--since` floor is the PR-open time (`_utcnow()` after `gh pr create`).
Round 2+ post a fresh `@codex review` comment (the SKILL Step-7 loop), floored at
that comment's `created_at`. Removed the dead Copilot reviewer-API POST,
`REVIEW_REVIEWER_SLUG`, and `swarm_config.review_reviewer_slug()` (nothing reads
it under the comment model). Flipped `pr_review_watcher.py`'s default `--reviewer`
copilot -> codex (the `copilot` profile is kept -- generic and harmless). Rewrote
the reviewer prose across SKILL.md, CLAUDE.md (scar #2 + Closeout), review-flow.md,
AGENTS.md, INDEX.md, and testing.md to the auto-review + comment-for-re-review
model.

**nvd -- aggressive review rules.** Added an `### Issue severity -- be AGGRESSIVE`
section to AGENTS.md's review block. Codex's system prompt can't be changed, but
AGENTS.md (which Codex reads, root-down, under the 32 KiB `project_doc_max_bytes`
cap) CAN redefine what counts as P0/P1 -- the same lever OpenAI uses in their own
AGENTS.md ("Highlight ... as P0"). The section uses imperative "treat everything
in the P1 list as P1 / when unsure, raise it" framing, enumerates generic
high-value bug classes (correctness, edge cases, races, resource leaks, contract
breaks, missing test coverage, perf, wrong docs) AND the repo's hard invariants
(stateless backend, no-PII-logging, confirm_field + audit, ASCII-only,
section!=part, VAD/barge-in, model wiring / single-field update_form_fields), with
an explicit P2 "don't bikeshed" carve-out to keep signal high.

**Decisions (autonomous -- defended in the merge report):** bundled nvd into this
PR (maintainer instruction); chose aggressive-but-substantive severity over
maximal-noise (reversible; cosmetics stay P2); added a light `test_agents_md.py`
(severity-section presence + 32 KiB Codex-cap guard) rather than no test; kept the
`--copilot-rounds` ledger flag name (avoids churning historical rows) but renamed
the SKILL-prose constant `MAX_COPILOT_ROUNDS` -> `MAX_REVIEW_ROUNDS`.

**Deferred (filed as beads):** `polyglot-pdf-xev` (P3) -- pre-existing 👍 emoji in
`pr_review_watcher.py` + its test violate the ASCII-only rule (predates this PR).

**Fresh-eyes / Codex triage:** recorded in the merge ping (Step 8).

## Lessons

- **Codex's trigger model is auto-review-on-open + comment-for-re-review**, NOT
  the Copilot reviewer-API request. Round 1 needs no trigger; only re-reviews do.
  Captured in CLAUDE.md scar #2 + review-flow.md doctrine.
- **AGENTS.md is the lever for Codex review behavior**, including severity: you
  can't edit Codex's system prompt, but redefining P0/P1 in AGENTS.md (kept INLINE
  -- Codex does not follow links) steers what it surfaces. Stay under the 32 KiB
  `project_doc_max_bytes` cap or late sections get truncated.
- A maintainer correction mid-build (auto-review on open) invalidated a just-built
  comment-at-open path -- worth confirming the external tool's actual behavior
  before building the trigger, not after.
