# Guidance enrichment joins extract() (bd wsao.6)

## What shipped

`extract_form.py` gained stage **3g** -- `_enrich_guidance` -- mirroring the
option-translation bake's contract exactly: post-repair (channels key off
final fields), pre-validate/lint (the shipped artifact is the linted
artifact), FAIL-OPEN (extraction never fails because enrichment failed),
skippable via `--no-enrich-guidance`, model override via `--guidance-model`
/ `INSTRUCTIONS_MODEL`.

The stage calls the wsao.4/5 engine through two new in-memory cores split
out of the CLI wrappers (`enrich_schema`, `apply_proposals` -- `enrich` and
`write_kit` now wrap them with file I/O): author from the booklet -> judge +
bounded rectify (KEEP rule) -> provenance-guarded apply. A `/TU` map built
from the acroform dump seeds `source: tu` provenance so a fresh draft's /TU
baseline is machine-owned (upgradeable), never mistaken for human text.

The old naive substring enrichment (`_enrich_instructions_from_pdf`, bd
s4dp.3) is DEMOTED to the stage's degraded-mode fallback. It fires on BOTH
degraded paths -- when the LLM stage raises, AND when the judge is
unavailable (the KEEP rule empties everything inside verify_and_rectify,
so that case never raises) -- and for the auto-discovered booklet as well
as an explicit `--instructions-pdf`. Where the fallback appends onto
tu-seeded text, the seeded provenance sha1s are re-hashed so the fields
stay machine-owned.

Report rides `_bakeoff.authoring.instructions_enrich` (flags LIST +
provenance + written/skipped counts; the merge is careful to keep the flags
list -- an early draft clobbered it with the summary's int count).

## Exit criteria evidence

1. **Fresh w7 extraction end-to-end** (raw PDF, no kit input): 54 fields
   extracted, 49 enriched (instructions 49, details 43), form-level details
   5,013 chars, booklet floor 81,200 chars, 49 provenance records, 0 judge
   flags, **0 lint errors** (1 warning: the 5-field coverage worklist).
   W-7 carries zero /TU, so all fields were legitimately blank-writable.
2. **(a)-arm invariance by construction + test**: the stage runs after every
   detection/repair/division step and only adds `help.*`,
   `form_metadata.details/booklet_text`, and `_bakeoff` keys;
   `test_enrich_guidance_stage_end_to_end` pins that field structure
   (ids/types/pdf names/options) is byte-identical across the stage.

## Notes

- extract_form.py's `--pdf`/`--out` are FLAG arguments, not positionals
  (one wasted run).
- The booklet is found by kit-dir glob next to the form PDF
  (`instructions.pdf`, `*instr*.pdf`) or `--instructions-pdf` -- same
  resolution as the standalone engine (`find_booklet`).

## Review follow-ups (same PR)

Fresh-eyes rounds added, post the recorded fresh-w7 run: the hosted editor
route passes `--guidance-model settings.EXTRACTOR_MODEL` (without it the
stage resolved through raw env vars to the absent claude CLI and silently
degraded to the naive fallback on the deploy target); console top line only
mentions the naive fallback when it fired; help text states the real model
resolution order; `write_kit` skips the /TU PDF parse when provenance
exists. Regression tests pin the route cmd and the provenance-lockout case
(any existing provenance means unrecorded fields stay human-protected --
by design; the wsao.7 refresh decision covers relitigating it).
