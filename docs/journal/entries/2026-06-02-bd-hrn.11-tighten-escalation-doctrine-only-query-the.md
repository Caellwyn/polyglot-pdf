## Trigger

`polyglot-pdf-hrn.11` (filed mid-session after the orchestrator over-used
`AskUserQuestion` for trivial process calls — e.g. asking the maintainer to choose
"plan-first vs. build" and a branch-basing strategy, both derivable from context).
Each needless ask burns tokens and the maintainer's attention, defeating the
bounded-autonomy goal of the `hrn` epic. The maintainer workshopped the doctrine
live in a planning session; this entry records the result.

## What shipped

A new **`### Escalation vs. autonomy`** section at the top of CLAUDE.md's "Critical
rules" — the first behavioral rule every orchestrator inherits. It is an
**explicitly incremental first step**, not the final doctrine: the narrow goal is
to kill trivial, no-consequence escalations without letting work creep past what a
bead authorizes. Key design points (all maintainer decisions during planning):

- **The bead is the unit of authorization.** Decide anything that implements the
  bead/plan as written or is trivial with no effect beyond the sprint; escalate
  longer-term commitments the bead doesn't call for.
- **Shaped as a 3-step decision procedure** (NEVER → escalate-cases →
  decide-and-note), not scattered prose — a single ordered algorithm is more
  reliably followed, and the shape matches Anthropic's own Opus 4.8 guidance for
  curbing over-asking ("for minor choices, pick a reasonable option and note it…").
- **NEVER tier** (force-push, deploy, merge) is distinct from "escalate" — these
  are not the orchestrator's at all, not even to ask. (Corrects the first draft,
  which had wrongly listed them as escalate-cases.)
- **Comparative advantage:** the maintainer is the product owner (direction,
  priorities, scope, product/UX tradeoffs); the orchestrator owns
  implementation + **small bead-serving architecture**. "Architecture" was
  replaced as a trigger word — only *beyond-the-bead* commitments (new contracts,
  new operational/cost/security dependencies, broken invariants, architecture
  bigger than the small obvious one serving the bead) escalate.
- **Scope creep → file a bead**, don't ask and don't silently expand. This is what
  makes a conservative rule cheap: out-of-scope work routes to a new bead, not a
  maintainer turn.
- **The soft edge is deliberate.** "Bigger than the small obvious one" is a
  judgment call; the rule defaults to escalate-on-doubt, so the only failure mode
  is an occasional unnecessary ask (never an unauthorized commitment). The line is
  self-flagged in the doc as a known soft spot to sharpen next round.
- **The defended PR-decision list is the audit surface.** The merge report must
  now LIST and DEFEND each autonomous decision in plain language — that defended
  list (read at every merge, the human gate) is where the maintainer catches
  anything *decided that should have been escalated*, the real risk of widening
  autonomy. This replaces a more elaborate telemetry-tagging idea (the human
  review is the better, simpler instrument).

**Fresh-eyes triage (Sonnet; docs-only PR, Copilot skipped per the review gate):
4 findings, all adopted inline — none were cosmetic nits; each would have caused
wrong behavior.**
- **(high)** The NEVER list's "don't ask to [merge]" contradicted the closeout
  merge-ping ("ping the maintainer to merge"). A literal reader could suppress the
  ping — the endpoint of every closeout. Fixed: NEVER now says "don't do it
  yourself / don't ask permission to do it yourself," with an explicit carve-out
  that the merge-ping is the handoff, not an ask.
- **(high)** `bd_safe.py / bracketed bd create` read as two valid paths, but
  `bd_safe.py` has no `create` subcommand (a known footgun). Fixed to "bracketed
  `bd create`; `bd_safe.py` has no `create` subcommand."
- **(high)** The sprint-plan north-star's scope-creep bullet lost the "unless it's
  a maintainer decision → escalate" qualifier that CLAUDE.md has, so it would file
  a bead for *everything* out-of-scope, including genuine owner decisions. Fixed:
  added the qualifier to both docs.
- **(medium → corrected + sharpened by the maintainer)** The "STOP and wait, but
  reversible work may continue in parallel" sentence was self-contradictory.
  Fresh-eyes flagged the ambiguity; the **maintainer corrected the substance**: I
  had attributed a capability I don't have — a blocking question ENDS the turn and
  halts the process; there is no parallel-continue-while-blocked, no polling for
  presence, no open-ended waiting. The maintainer then **sharpened it into the real
  principle: DEFER the escalation until nothing further can be done without the
  answer** — a *dependency* trigger, not "do it last." When a question arises, keep
  doing everything that doesn't depend on the answer, commit it cleanly, decide what
  you can, and ask only at the point where nothing else can proceed (which may come
  early or late) — so the work still stops, but as much as possible is done first
  and the one reply unblocks the most.
  Rewrote the doctrine paragraph accordingly; recorded as scar tissue
  ([[escalating-is-a-hard-stop-no-parallel-work]]).

## Lessons

- **Behavioral guidance for the orchestrator belongs in CLAUDE.md (tier-1, always
  loaded), not a tier-2 doctrine doc.** Tier 2 is loaded on-demand; escalation
  guidance is needed every session by every orchestrator, so a tier-2 split would
  silently fail to load it when it matters. (First draft wrongly proposed the full
  lists in `workflow.md`.)
- **For a first autonomy increase, the real risk is under-escalation, and the
  human-readable defended decision list is the cheapest instrument to catch it** —
  better than telemetry, because the maintainer is already reading every merge.
  Generalizes: when widening an agent's autonomy, make its decisions *legible and
  defended* at the existing human gate before adding new measurement.
