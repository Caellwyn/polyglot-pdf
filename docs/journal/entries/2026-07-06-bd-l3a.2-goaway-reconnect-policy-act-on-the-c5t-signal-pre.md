## Trigger

Bead polyglot-pdf-l3a.2 (epic l3a, Live API session management). Its predecessor
c5t wired the Gemini Live GoAway signal end to end -- the adapter detects
`event.go_away`, the backend forwards `{type:"go_away", time_left}`, and the
frontend dispatches it to an optional `onGoAway` callback -- but deliberately
stopped short of ACTING on it: `onGoAway` had no default consumer, so a GoAway was
observed and then ignored. This bead is the policy decision plus implementation:
when the server announces it is about to reset the connection, what should the
client do? The bead framed option (d) as the likely answer -- silently and
pre-emptively reconnect, leveraging vmxx's resume flag so the user never notices --
and that is what shipped.

## What shipped

A built-in GoAway reconnect policy inside `WebFormConnection`: on a `go_away`, the
connection now tears down the current socket and immediately reconnects through the
EXISTING reconnect path (`connect(connectedUrl)` -> `handleOpen`), which already
sends `resume:true` (bd vmxx), so the new session comes up around the server's own
close with no re-greeting and no jarring drop. The `onGoAway` callback still fires
for any UI consumer, but the reconnect no longer depends on one being wired -- which
is exactly the gap c5t deferred.

Design decisions (all mine; defended in the PR body):

- **Policy lives in `WebFormConnection`, not a UI consumer.** It is co-located with
  the reconnect machinery it needs (`connectedUrl`, the fresh-token `connect()`, the
  `handleOpen` resume flag). Wiring it into `shared/connection.ts`'s callback bag
  would have re-implemented the same teardown/reconnect the class already owns, and
  would have re-introduced the "no default consumer" gap in a different place.
- **Seamless = keep status "connected".** The pre-emptive path suppresses the
  `connect()` "connecting" status flip and stands `handleClose` down (via a
  `goAwayReconnectInFlight` guard) so the user sees no connecting/disconnected
  flicker. This mirrors how a section switch (`isSectionSwitching`) drives its own
  reconnect without a status flicker.
- **Once-guard coalesces a burst of GoAways** into a single reconnect and clears
  when the new socket opens (`handleOpen`) or the reconnect attempt rejects (so a
  later GoAway can retry rather than being permanently coalesced).
- **Skip the paths that already own the socket lifecycle:** an idle timeout (its
  no-reconnect gate must win -- a GoAway must not override the user's
  manual-reconnect requirement), an in-flight section switch, no stored URL, or no
  open socket. A failed pre-emptive reconnect surfaces `error` via the existing
  `handleError` path rather than silently looping.

## Lessons

The reusable pattern here is the **guard-driven self-driven reconnect**: when a
class needs to reconnect its own socket without the auto-reconnect machinery
double-firing, set an in-flight flag, null `this.ws` before closing (so a late
`onclose` is treated as stale/guarded), drive `connect()` yourself, and clear the
flag on open/failure. The codebase already had this shape for section switches
(`isSectionSwitching`); GoAway is the second instance. Not general enough for a
standards doc, but worth noting the two now share the idiom.
