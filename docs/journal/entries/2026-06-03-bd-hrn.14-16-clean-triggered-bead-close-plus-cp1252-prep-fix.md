## Trigger

`bd polyglot-pdf-hrn.14` + `bd polyglot-pdf-hrn.16`, bundled into one PR. hrn.14
came out of the hrn.13 discussion: the post-CLEAN bead-close on a review-worthy
PR is pure mechanics with zero judgment, yet it cost the orchestrator a turn (the
manual second `closeout_finish.py --close-only` call). The bead's original idea
was a GitHub Action triggered on `pull_request` closed+merged. hrn.16 was a
crash found during hrn.15 closeout: `closeout_prep.py` raised
`UnicodeEncodeError` on a cp1252 console when `render_todo` printed the bd
orphans/stale glyphs.

## What shipped

**The original hrn.14 premise was verified WRONG, and the design changed
accordingly (maintainer-steered).** The bead assumed a merge-triggered GitHub
Action would need CI credentials to a *separate Dolt remote*. Investigation
showed:

- Bead state syncs via `bd dolt push`/`pull` to its **own** remote (the
  `git+https` repo URL, marked `[CLI only]`), **independent of any PR or git
  merge**. The git-tracked `.beads/*.jsonl` is a secondary *mirror*, not the
  transport. (Proven: a `bd update` in the worktree showed up in the main
  checkout's working tree with no commit/push.) So no new CI secret was ever
  needed.
- The merge-trigger path is blocked anyway: the `To Dev` ruleset requires a PR
  (+ non-fast-forward) for any push to `dev`, so an Action could not push the
  closed-bead state back.

**Shipped instead: a CLEAN-triggered close driven by the LOCAL review watcher.**
`pr_review_watcher.py` gains `--close-on-clean <bead-id>` (repeatable). On the
**CLEAN** terminal state ONLY -- never COMMENTS/ERROR/TIMEOUT/MERGED -- it shells
out to the existing, verified `closeout_finish.py --close-only` (= `bd_safe
close` -> `bd dolt push`), closing the bead(s) and waking the orchestrator only
for the merge ping. This removes the manual second-call turn. The CLEAN-vs-not
gate lives inside the watcher (where it is already computed) via a module-level
`_LAST_STATE` that `main()` reads after `watch()` returns -- not a shell wrapper
re-deriving the distinction from the shared exit-0.

Key properties:
- **No commit/push, no merge-race:** the close propagates via `bd dolt push`, so
  there is nothing to ride into the PR. The re-exported `.beads/*.jsonl` mirror
  is left dirty for the next manual `bd` sync (maintainer's explicit call).
- **Telemetry stays clean:** `--close-only` writes NO ledger row, preserving the
  hrn.15 A/B discipline (no duplicate row).
- **Failure is visible:** a failed close exits `CLOSE-FAILED` (3) so the
  orchestrator triages instead of pinging a false "ready to merge".
- **fresh-eyes race:** SKILL guidance is to pass `--close-on-clean` on the
  round-1 watch only once fresh-eyes is known to have no on-branch fixes;
  otherwise carry it on the re-watch (whose CLEAN is genuinely terminal).

`SKILL.md` wires the flag into the round-1 + re-watch commands, documents the
CLOSE-FAILED state and the fresh-eyes race, and makes Step 8's close conditional
(don't re-close what the watcher already closed).

**hrn.16:** added the module-level stdout/stderr `reconfigure(encoding="utf-8",
errors="replace")` idiom to `closeout_prep.py`, matching `journal_scaffold.py`
and `closeout_finish.py`. The prep run during this very closeout printed the
`✓`/`⏰` glyphs without crashing -- the fix proving itself.

## Lessons

- **Beads has its own sync channel.** Bead state moves via `bd dolt push/pull`,
  not through git/PRs; the tracked JSONL is a mirror. A deterministic bead-close
  is just `--close-only` -- no commit, no PR-branch push, no merge-race. (Caught
  a wrong "the close must ride in on the PR" assumption mid-design.)
- **Verify a bead's stated cost before treating it as binding.** hrn.14's
  headline "escalation-worthy credential dependency" evaporated on inspection;
  the real obstacle was elsewhere (branch protection). The premise, not just the
  implementation, deserves a fresh read.
