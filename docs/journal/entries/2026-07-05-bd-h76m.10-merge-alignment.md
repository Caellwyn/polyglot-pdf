## Trigger

P4.2 of the schema-v2 epic `polyglot-pdf-h76m` (plan:
`~/.claude/plans/rustling-discovering-hearth.md`, maintainer-machine-local).
The editor's merge feature (bd s4dp.1) predated schema v2: it always emitted
a `radio` whose `option.value` was the SOURCE FIELD ID, carried the primary's
field-level `pdf_field_name` onto the group, and stamped a legacy
`consolidated_widgets` key -- none of which is v2-valid. P4.2 aligns merge
output to the v2 group contract (and P4.1's runtime, P1.1's model, P2.1's
lint) and surfaces the option metadata contractors need.

## What shipped

- `fieldGrouping.ts` `mergeFields(schema, ids, kind)`:
  - `kind` chooses `checkbox_group` (several boxes -> multi-select) vs
    `radio` (exactly one -> single-select). Dependent conditionals rewrite to
    `includes <slug>` for a group vs `equals <slug>` for a radio.
  - `option.value` is a SEMANTIC slug minted from the label (new TS
    `mintOptionSlug` / `mintUniqueSlugs`, mirroring backend
    `conditional_vocabulary`), unique per field. Widget identity lives ONLY
    on `option.pdf_field_name`.
  - The merged group carries NO field-level `pdf_field_name` (deleted; the
    backend model rejects one on a group) and no `consolidated_widgets`.
- Un-merge was already keyed off `option.pdf_field_name`; the
  save (strip stash) -> reload -> un-merge FALLBACK reconstructs clean v2
  standalone checkboxes (type=checkbox, no options, own pdf_field_name).
- `FieldList`: the single Merge button becomes "Merge (several)" ->
  checkbox_group and "Merge (exactly one)" -> radio -- the plan's "several or
  exactly one?" prompt as two labeled actions.
- `FieldEditor`: the Options block now renders for `checkbox_group` too;
  `option.value` is a read-only slug CHIP (minted, never free-typed --
  renaming is done via the label); per-option `pdf_field_name` sits under an
  "Advanced: PDF widget" disclosure gated on a new `authorTier` prop (local
  editing, or hosted role=author). The old "+ Add Option" (which minted an
  empty, slug-invalid value) is gone; groups are built by Merge.
- Fresh-eyes triage (Sonnet, 2 rounds): round 1 scored EC1 PASS, EC2 FAIL --
  the merge introduced includes/not_includes for checkbox_group dependents,
  but the post-reload un-merge FALLBACK (remapFallbackAtom /
  normalizeWholeGroupOperator) only knew equals/not_equals, so a
  checkbox_group dependent's condition survived save->reload->un-merge as a
  dangling `includes` on a now-standalone boolean checkbox that never fired
  (my crit-2 test missed it by having no dependent field). Fixed: membership
  ops on a matched option remap to is_checked / not_equals-true like
  equals/not_equals; an unmatched includes->equals (hidden), not_includes->
  not_equals (always-show). New dependent-bearing crit-2 test, proven red
  without the fix. Round 2: NO-GAPS (matched/unmatched not_includes +
  composite-atom paths all verified). Also filed out-of-scope bead
  polyglot-pdf-ttzn (select-field manual option-add removed) and fixed a
  stale comment. Adopt 1 gap + 1 nit / reject 0 / defer 1 (ttzn).

## Exit criteria evidence

- **Merging W-7-style checkboxes -> lint-clean group passing roundtrip fill**
  is proven on BOTH sides of the language boundary: `fieldGrouping.test.ts`
  pins the transform (checkbox_group type, minted unique slugs, per-option
  pdf, no field-level pdf), and
  `backend/tests/test_merged_group_v2_roundtrip.py` takes the EXACT shape
  mergeFields emits, lints it as v2 (zero ERRORs), validates it under the
  strict Pydantic model, and round-trips a real `/fill-pdf` (the selected
  option slugs land on exactly their widgets).
- **Merge -> save -> reload -> un-merge -> lint-clean standalone fields**:
  the crit-2 fallback test strips the stash (the save shape), un-merges, and
  asserts every reconstructed field is a standalone checkbox with its own
  pdf_field_name and no options.

## Lessons

- The v1/v2 lint gating means "lint-clean" alone is a weak assertion on an
  unstamped schema (the strict slug/structure checks only fire under
  schema_version="2"). The honest proof is to lint AND model-validate the
  merge output stamped v2 -- which is what the backend test does, so the
  group is genuinely valid, not trivially-passing.
