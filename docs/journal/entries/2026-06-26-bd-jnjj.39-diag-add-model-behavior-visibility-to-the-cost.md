## Trigger

The jnjj.38 investigation into a DTI fill stall burned many live-Gemini runs
because the cost/fill harness (`scripts/spikes/measure_form_session_costs.py`)
showed WHETHER a fill landed but almost nothing about WHY the model acted -- no
transcript of what it heard or said, no record of the exact tool args it sent or
the response it got back. Diagnosis devolved into guess-and-rerun. jnjj.39 builds
that visibility FIRST so the DTI bug (jnjj.40, which depends on this) and future
model-behavior questions resolve in one instrumented session instead of ten.

## What shipped

A gated `--debug` mode that writes a per-run `<base>.debug.json` with, per question:

- **model_heard** -- the INPUT transcript (what Gemini's speech-to-text produced).
  Captured via a new optional `_on_input_transcript` diagnostic observer on the
  adapter, mirroring the existing `_on_raw_usage` harness-observer pattern: default
  `None` = production no-op, so production behavior is byte-identical and the PHI
  boundary holds (the liveness path stays text-less; only the local-only spike opts
  in).
- **model_said** -- the OUTPUT transcript, de-chunked from the streamed tokens
  (`send_transcript` requested only under `--debug`).
- **tool_io** -- the EXACT args the model sent to `update_form_fields` /
  `confirm_field` AND the response it got back (success/error message +
  `next_field_guidance`). The single most useful signal, and it was entirely
  missing.
- **tools_reliable vs tools_legacy** -- tool calls attributed by TIME WINDOW (which
  question's `t_start..t_end` the call's timestamp falls in) shown alongside the old
  mutable-counter attribution. The window method correctly attributes a call that
  lands after the loop advanced -- the exact failure behind the "24/25 filled but
  tools logged for 6" symptom that (over-)motivated jnjj.38.

All gated behind `--debug` (off by default): normal cost/fill runs request no
transcription, build no debug structures, and write no debug file. The artifact is
LOCAL-ONLY (transcripts + field values are user data) so `*.debug.json` is
gitignored; the cost CSV/meta siblings stay committable.

**Exit-criteria scorecard (Step 5.5.a):**
1. `--debug` produces input transcript + output transcript + tool args + tool
   response per question -- **PASS** (validated on a live DTI run; all four signals
   present in the artifact).
2. `per_question_tools` correctly attributed, verified against a controlled run --
   **PASS** (`tests/test_measure_cost_debug.py` pins the window method against the
   late-call case the legacy counter mishandles).
3. Normal (non-debug) runs unchanged -- **PASS** (every debug path is `if DEBUG`-
   gated; the adapter observer is a default-`None` no-op).

**Fresh-eyes (Sonnet, 2 rounds, all adopted):** round 1 NO-GAPS on all 3 criteria,
with two imprecisions fixed inline: (1) a dead `plan` parameter on
`_write_debug_artifact` (passed, never used) removed; (2) the adapter comment
overclaimed it "mirrors `_on_raw_usage`" when its except branch deliberately LOGS
(PHI-safe) rather than swallowing -- comment tightened to state the difference.
Round 2 confirmed the fixes, no new gaps. No deferrals, no out-of-scope beads.

**Diagnostic payoff (recorded on jnjj.40).** The very first `--debug` run diagnosed
the DTI stall end-to-end, and the input transcript sharpened it decisively: the
account-number "comma hallucination" is NOT the model inventing commas -- the INPUT
transcript literally reads "...account number is $1,234,567,890" for the spoken
digit string, i.e. Gemini's own speech-to-text reformatted it, and the model then
(correctly, given that input) rejected it as >12 chars. The output transcript alone
could not have shown this. The follow-on empty-confirm loop (model clears the field,
`confirm_field` errors on the empty value, model loops) is a separate robustness bug
noted for jnjj.40.

## Lessons

- **Build model-behavior visibility before diagnosing model behavior.** The single
  most expensive part of jnjj.38 was inferring the model's intent from fill
  outcomes; the tool-args/response capture would have collapsed that to one run.
  The instrument is the cheaper investment.
- **Input vs output transcript are not redundant.** The output transcript showed the
  model "rejecting an invalid account number"; only the input transcript revealed
  the rejection was driven by a transcription artifact upstream of the model's
  reasoning. When a model "misbehaves," capture what it HEARD, not just what it SAID.
- **Match a new harness observer to the existing pattern.** `_on_input_transcript`
  copied `_on_raw_usage`'s default-None-no-op shape exactly, which kept the
  production change a true no-op and the PHI boundary intact -- no new review
  surface beyond "is the observer truly off by default."
