## Trigger

Bead polyglot-pdf-uov.13 (T3.2, the last child of the spec-driven test epic uov).
The frontend auth surface -- `AuthContext` (sign-in/up/reset, loading/user
state), the `ProtectedRoute` gate, and the email-signup allowlist -- had NO
tests. This is a security-relevant surface, so it is the last gap the epic closes.

## What shipped

A new `frontend/src/contexts/AuthContext.test.tsx` (14 tests), the first coverage
of this surface. Firebase is fully mocked -- `../firebase/config` (which calls
`getAuth`/`getFirestore` at import and would otherwise need real credentials) is
replaced with sentinels, and the `firebase/auth` + `firebase/firestore` functions
the context calls are `vi.fn()`s the tests assert on.

- **The email-signup ALLOWLIST GATE (security-critical).** `signUpWithEmail`
  queries the `authorized_emails` collection and REFUSES to create an account
  when the email is not on the list -- a regression here would let anyone
  self-register. Spec'd hardest: the refuse path (and that
  `createUserWithEmailAndPassword` is never reached), the authorized path, that
  the allowlist is queried with a LOWERCASED email (so a lowercase-stored entry
  matches a mixed-case signup), and that a Firebase create error propagates.
  **Mutation-verified:** bypassing the `snap.empty` gate makes the refuse test
  fail, proving it actually guards the gate.
- **Delegation:** `signInWithEmail` (credentials + re-throw), `resetPassword`,
  and `logout` each call the right Firebase function.
- **Lifecycle:** `AuthProvider` renders nothing until `!loading`, then flips to
  ready when the auth state settles; the double-gated test-harness bypass
  (`isTestHarnessEnabled`) installs the mock user and does NOT attach the real
  `onAuthStateChanged` listener, and the mock user's `getIdToken` resolves (the
  SchemaForm needs it for the WS token).
- **`useAuth` outside a provider throws.**
- **`ProtectedRoute` gate:** loading -> protected content absent (the provider
  gates its children), no user -> the Login screen, user present -> the protected
  children.

**Bead-vs-source note.** The bead lists "dev bypass VFF_DISABLE_AUTH" under
`contexts/AuthContext.tsx`, but that file does not read `VFF_DISABLE_AUTH` --
that is a BACKEND env flag (`backend/services/auth.py`), exercised by the uov.9
WS-auth tests. The FRONTEND auth-bypass is the test-harness path
(`isTestHarnessEnabled`, double-gated `__VFF_LOCAL_DEV` + `__VFF_TEST_HARNESS`),
which is what this spec covers. The bead's wording conflated the two layers; the
frontend bead correctly specs the frontend bypass.

390 frontend tests pass (was 376; +14). Test-only, no product code changed. The
bead had no `## Exit criteria` (creation-time-norm slip); a retrospective rubric
was written at claim time.

## Lessons

For a Firebase-backed context, the testable seam is the module boundary: mock
`../firebase/config` (so the import-time `getAuth`/`getFirestore` never touch real
credentials) plus the specific `firebase/auth`/`firebase/firestore` functions the
unit calls, then drive the context's methods and assert on those spies. The
security-critical assertion (the allowlist gate) earns a mutation check -- flip
the gate condition and confirm the refuse test goes red -- so the test is proven
to guard the behavior, not just to pass alongside it.
