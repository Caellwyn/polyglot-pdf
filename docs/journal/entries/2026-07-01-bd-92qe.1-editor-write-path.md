## Trigger

Second slice of the hosted-schema-editor epic (`polyglot-pdf-92qe`), plan Bead 2,
extended by the maintainer's 2026-07-01 `/goal` directive: contractors get TWO
permission tiers -- (a) *author* (collect/upload PDFs, run hosted extraction,
review) and (b) *editor* (polish a provided collection of extracted forms). The
merged read slice (bd sbfk, PR #277) can serve a manifest-listed kit's bytes, but
nothing lets a contractor SEE drafts (the complete-only manifest hides them by
design), save an edited schema back, or flip a kit's status -- and the backend had
no auth surface distinguishing the two tiers. This bead builds that write path.

## What shipped

**Store (backend/services/form_kits.py), additive:** `load_metadata` /
`put_metadata` / `put_schema` / `list_kit_files` (+ a derived `list_kit_ids`)
for BOTH LocalFormKitStore and GCSFormKitStore. Local writes are atomic
(temp file + `os.replace`, mirroring the dev extraction endpoint's discipline)
so a concurrent reader never sees a half-written schema; GCS uploads set
`content_type=application/json` + `cache_control=no-cache` so a post-save re-pull
is never stale. `list_kit_files` is ONE storage listing grouped into
`kit_id -> [filenames]`, which gives the catalogue hasSchema/hasPdf without a
per-file existence probe (expensive on GCS). Read contract unchanged; the voice
app never calls the new methods.

**Routes (new backend/routes/editor_kit_routes.py, prefix /api/editor):**
- `GET /session` -> `{role}` -- the access-code probe the hosted editor calls
  once after code entry.
- `GET /kits` -- every kit in the store, DRAFTS INCLUDED, built from
  `list_kit_files` + per-kit `metadata.json`, deliberately bypassing the
  complete-only manifest. One malformed kit lists with unknowns rather than
  hiding the rest.
- `GET /kits/{id}/schema` + `/pdf` -- draft-capable reads (filenames resolved
  from the kit's own metadata, not the manifest allowlist the public routes use).
- `PUT /kits/{id}/schema` -- the hosted save. Lenient by design (work-in-progress
  may be incomplete) but never formless: requires a JSON object with a `fields`
  list. Writes only to EXISTING kits; kit creation is the author-tier onboarding
  route (bd 92qe.3).
- `POST /kits/{id}/status` -- draft <-> complete, read-merge-write preserving
  label/description/custom filenames. **Promotion to `complete` is the publish
  gate**: it requires the schema to exist AND validate against the canonical
  Pydantic `FormSchema` -- a structurally-broken schema surfaces to the person
  who can fix it, not later in the voice app. Reverting to draft is
  unconditional.

**Two-tier auth:** `X-Editor-Token` compared (hmac.compare_digest) against
`SCHEMA_EDITOR_TOKEN` (editor role) and `SCHEMA_AUTHOR_TOKEN` (author role;
implies editor). Fail-closed: 503 when NEITHER is configured (surface off, not
open), 401 on mismatch. `require_author_role` (403 for editors) is exported for
the 92qe.3 onboarding/extraction routes. Shared-secret (not per-user auth) is
the approved 92qe design for a small set of trusted contractors; the goal's
two-tier requirement is met with a second secret rather than a login system.

**CORS:** `CORS_EXTRA_ORIGINS` (comma-separated env) appended to the hardcoded
localhost list in `main.py` -- the hosted editor calls Cloud Run directly
(the Hosting `/api` rewrite's 60s cap would kill minutes-long extraction), so
its origin arrives per-deploy via env, plus `localhost:3001` (the editor dev
server) added to the static list.

**Tests** (`backend/tests/unit/test_editor_kit_routes.py`, +32): auth wiring
through a real FastAPI TestClient (503 unset / 401 wrong / role per token /
editor-only AND author-only deployments / author-gate 403); Local store round-trips (schema,
metadata, listing, atomic-write leaves no temp files, traversal filename
degrades); GCS via a mocked client (upload content-type + cache-control,
metadata round-trip, listing grouped + manifest/deep blobs ignored, upload
failure -> FormKitStoreError); the draft-visibility linchpin (a GCS-shaped store
whose manifest lists only the complete kit: editor list shows both, public list
+ public single-kit route refuse the draft); save/status round-trips incl.
metadata preservation, promote-without-schema 409, promote-invalid 422 with the
validation detail, revert-to-draft unconditional; guard 400s. Full backend
suite green (641 passed / 2 skipped pre-existing).

Pre-PR assess: exit-criteria rubric all PASS; fresh-eyes round 1 returned
NO-GAPS with four nit-level notes -- three adopted pre-PR (the journal's test

## Lessons

The complete-only manifest gate and the contractor's need to see drafts are the
SAME mechanism viewed from two sides -- so the editor surface must NOT reuse the
public read path (whose allowlist is the manifest) but enumerate storage
directly, and the split belongs at the ROUTER level (a separate token-gated
router) rather than as flags on the public routes. Keeping the public surface
byte-identical is what makes the draft-leak reasoning auditable.

Promotion-time strict validation + save-time lenient validation is the right
split for human-in-the-loop editing: blocking a mid-polish save on full contract
validity would fight the workflow, but letting an invalid schema get PUBLISHED
ships the breakage downstream to the voice app. Validate at the gate where the
contract starts to matter.
