## Trigger

Deferred nit from the fresh-eyes review of bd polyglot-pdf-p4ale (E4.5:
dedicated Cloud Build service account, role pin, actAs bindings, deploy-plane
IAM in one pin, part of the admin-console E4 deploy-plane epic,
polyglot-pdf-nacfo). The finding: `scripts/setup-cloud-build.sh`'s
`PROJECT_ROLES` array grants `roles/run.admin` project-wide with no comment
explaining why, sitting a few lines above a comment block that explicitly
argues AGAINST project-wide grants for the actAs bindings further down the
same section. Not a rubric-fail or functional defect -- Cloud Run IAM has no
role narrower than run.admin for managing revisions across multiple named
services, so project-wide is the only practical option -- but a reviewer or
future maintainer skimming the "resource-scoped, never project-wide" framing
could reasonably assume run.admin follows the same rule.

## What shipped

Added a short comment next to the `roles/run.admin` entry in
`scripts/setup-cloud-build.sh`'s `PROJECT_ROLES` array explaining that it is
project-wide because Cloud Run IAM has no per-service role narrow enough to
scope it down to, unlike the actAs bindings a few lines below -- closing the
gap the review flagged without touching any granted role, script behavior, or
IAM envelope.

While reviewing the surrounding docs for the same shape, found that
`docs/components/config-deployment.md` (which documents this same
PROJECT_ROLES grant in prose) has the identical gap: it lists `roles/run.admin`
without noting it is project-wide, then a following paragraph explains why the
actAs bindings ARE resource-scoped. Filed as a separate deferred bead
(polyglot-pdf-mxzkf) rather than expanding this bead's scope -- it is a
docs-prose fix with no behavior or contract change, independently schedulable.

## Lessons

A one-line "why this is the exception" comment next to a grant that departs
from the surrounding scoping convention is cheap insurance against a reader
assuming a uniform rule that doesn't actually hold everywhere. When the same
gap appears in a second document describing the same fact, file a bead for it
rather than opportunistically expanding an already-scoped nit fix -- keeps the
diff reviewable and the follow-up separately triageable.

project-wide scoping rationale -- tracked separately as polyglot-pdf-mxzkf).
