## Trigger

jnjj.25 measured DTI principal cost on the real I-90 and landed GO **with
calibrated eviction** (-21% on the unhappy path; DTI alone is a wash). That
measurement also surfaced the production gap it could not close itself: the
winning calibration is *load-bearing and form-specific* -- the sliding window
must sit JUST ABOVE the unevictable SI+tools floor (~1978 tok for the I-90 DTI
SI). Too loose and Gemini barely evicts (the l3a finding); at or below the floor
and compression fires on turn 1. The findings spelled out the fix
(`scripts/spikes/jnjj_25_dti_cost_findings.md`, the production-wiring note): "the
window must be DERIVED from the rendered DTI SI floor, not a fixed constant." The
production path still used static global env constants
(`CONTEXT_COMPRESSION_TRIGGER_TOKENS=5000` / `WINDOW=3000`), which are correct for
no particular form. This bead (filed as A6 to carry the proven-but-unwired work)
moves the calibration into the live path so it is correct for any form, not just
the I-90.

## What shipped

A per-form derivation of the compression window/trigger from the rendered SI
floor, gated to the DTI path, with the static constants kept as the explicit
override.

- **`backend/adapters/live_ai_gemini.py`**: two pure module-level helpers --
  `estimate_si_floor_tokens(SI, tools)` (the unevictable floor = rendered SI +
  serialized tool declarations, at the file's existing ~4 chars/token estimate)
  and `derive_compression_window(SI, tools, *, headroom, margin)` (window = floor
  + headroom; trigger = window + margin, with both bands clamped to `max(1, ...)`
  so `window > floor` and `trigger > window` hold by construction). The
  `if settings.CONTEXT_COMPRESSION_ENABLED:` block in `_build_live_config` now
  derives when `USE_DTI` + the new `CONTEXT_COMPRESSION_DERIVE_FROM_SI_FLOOR` flag
  are on AND a rendered SI is present; otherwise it uses the static env values.
  The log line gained `derived_from_si_floor` + `si_floor_tokens` so an operator
  can see which path fired.
- **`backend/config.py`**: new knobs -- `CONTEXT_COMPRESSION_DERIVE_FROM_SI_FLOOR`
  (default on), `CONTEXT_COMPRESSION_WINDOW_HEADROOM_TOKENS` (**599** -- see the
  estimator-undershoot note below), `CONTEXT_COMPRESSION_TRIGGER_MARGIN_TOKENS`
  (600). The defaults reproduce the validated I-90 calibration: the chars/4
  estimator reports a ~1601 floor for the I-90 DTI SI, and headroom 599 lifts that
  to the ~2200 window (which clears the ~1978 MEASURED floor), +600 -> ~2800
  trigger. The static `TRIGGER`/`WINDOW` constants stay as the override.
- **Tests** (`backend/tests/unit/test_live_ai_gemini.py`, +11): the estimator
  against a known fixture and against the REAL `TOOL_DECLARATIONS` (so the floor
  provably counts tools, not SI alone); the derivation arithmetic
  (floor -> window -> trigger, window < trigger); and the `_build_live_config`
  wiring across all four config combinations (derive under DTI; a different floor
  yielding a different window; the static override when derive is off; the static
  override when DTI is on but there is no SI yet).
- **`docs/components/context-compression.md`**: the Parameters table and a new
  "Per-form window derivation" section; clarified that the floor is the rendered
  SI *plus* tools (both unevictable), not the SI template alone.

## Why this way (defended decisions)

- **Derive-on-by-default under DTI.** When an operator flips
  `CONTEXT_COMPRESSION_ENABLED`, derivation activates automatically and the static
  values become the fallback. That is the point of the bead -- a static constant
  is wrong for any form whose floor differs from the one it was tuned for, so the
  *correct* behaviour should be the default once compression is on. The static
  knobs remain reachable (derive flag off, or a non-DTI SI), and the log line
  surfaces which path fired. (This was fresh-eyes gap 2, rated low / "design
  intent per the bead"; kept and defended rather than changed.)
- **A pure helper, not inline arithmetic.** The derivation lives in two free
  functions so the calibration rule is unit-testable against a fixed SI-floor
  fixture without standing up the adapter or a live session.
- **The floor uses the file's coarse ~4 chars/token estimate**, not an exact
  tokenizer: the window only has to land *just above* the floor, and the
  headroom/margin bands absorb the estimator's slop. An exact count would add a
  tokenizer dependency for no behavioural gain.

## Scope / what this does NOT do

- `CONTEXT_COMPRESSION_ENABLED` stays **default-off**. This bead makes the window
  *correct* when enabled; the default-flip is A5 (`jnjj.12`), gated on G2 + G3.
- The fill-correctness gate under eviction (G3, `jnjj.7`) is the next step -- it
  should now run with eviction ON, against this production-correct derived window
  rather than a hand-tuned harness constant.

## Codex review corrections (PR #239)

Two review rounds, both catching real defects:

- **Round 1, P1 (the load-bearing one): the headroom was calibrated against the
  estimator's output, not the MEASURED floor.** The chars/4 estimator UNDERSHOOTS
  the floor Gemini bills: the I-90 DTI SI is 3786 chars -> ~1601 ESTIMATED tok,
  but the live eviction landing was ~1978-2034 MEASURED tok (the run's
  `eviction_drops`). The first-draft headroom (222) therefore derived a ~1823
  window -- BELOW the ~1978 real floor -> compression would fire on turn 1 and
  evict all conversation. Corrected to headroom **599** (1601 + 599 = ~2200
  window, clearing 1978). A regression guard
  (`test_production_default_headroom_clears_measured_i90_floor`) pins the SHIPPED
  default against the measured floor. **Caveat: the headroom is anchored to the
  one form with measured eviction data (I-90); the estimator's undershoot scales
  loosely with content, so re-measure when a second form's floor is known.**
- **Round 1, P1: the cost harness silently overrode itself.**
  `measure_form_session_costs.py` set `USE_DTI=True` + explicit `--trigger/--window`
  but not `DERIVE_FROM_SI_FLOOR=False`, so a calibration sweep would auto-size the
  window while its metadata recorded the requested fixed pair. Fixed: the harness
  disables derivation whenever it applies explicit `--trigger/--window`.
- **Round 2, P1: this journal still recorded the unsafe 222.** Corrected above to
  599 so the calibration record matches the shipped code.
