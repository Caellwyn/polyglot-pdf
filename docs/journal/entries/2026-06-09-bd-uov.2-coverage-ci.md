## Trigger

Phase 0 of the spec-driven test-and-codebase-health epic (`polyglot-pdf-uov`),
the rest of it after T0.0 (uov.1) made collection deterministic. Two beads
bundled into one PR because both are tiny Phase-0 infra chores with disjoint
surfaces (coverage configs vs CI/closeout): T0.1 (uov.2) wires the coverage
instrument and records a baseline; T0.2 (uov.3) adds informational CI and audits
the closeout gate's xfail handling.

## What shipped

**Coverage tooling (uov.2), opt-in on all three stacks.**

- Backend: `pytest-cov==5.0.0` added to `backend/requirements.txt`;
  `[coverage:run]`/`[coverage:report]` sections in the root `pytest.ini`
  (`source = backend`, omit `backend/tests/*`). `--cov` is deliberately NOT in
  `addopts` -- coverage is opt-in via the flag so a bare `pytest` and the
  closeout gate stay fast and uncoupled.
- Frontend + schema-editor: `@vitest/coverage-v8` (matched to each project's
  vitest major -- ^3 for frontend, ^4 for schema-editor), a `coverage` block in
  each `vite.config.ts` (v8 provider, `src/**` include, tests excluded), and a
  `test:coverage` npm script each.
- Artifacts (`.coverage`, `**/coverage/`) gitignored at root.

**Baseline statement coverage (2026-06-09):** backend **54%** (source-scoped via
`.coveragerc`; corrected from an initial mis-measured 71% -- see Codex round 2
below), frontend **12%**, schema-editor **33%**. Recorded as instruments, not
gates.

**Informational CI (uov.3).** `.github/workflows/ci.yml`: three jobs on every PR
-- backend pytest (`-m "not external"`), frontend vitest, schema-editor vitest.
NON-BLOCKING by design: not a required status check, so the manual-merge gate and
the inert required_deployments ruleset stay the only merge controls. The header
comment makes the non-gate intent explicit so a future reader does not promote it
to a required check without a separate decision.

**Closeout xfail audit (uov.3) -- no fix needed.** The bead flagged "fix closeout
tooling here if needed." Audited: `scripts/closeout_prep.py` step 4 keys purely
off `proc.returncode`, and pytest exits 0 when all failures are `xfail` (only a
real failure or a `strict` `xpass` is non-zero). Proved empirically with a probe
(`@pytest.mark.xfail` test -> `1 xfailed`, exit 0). So the closeout gate already
treats xfail as pass; the land-intentionally-red-specs policy works unchanged.
Same for CI (same exit-code semantics) and vitest (`test.fails`).

## Decisions (defended)

- **Bundled uov.2 + uov.3 into one PR.** Both Phase-0 infra chores, individually
  too small for a full PR cycle; surfaces disjoint except `docs/standards/testing.md`
  (one writer here). Process-mechanics call (CLAUDE.md step 3).
- **Coverage opt-in, not in `addopts`.** Avoids coupling every closeout run +
  bare `pytest` to coverage overhead; the instrument is there when wanted. Form-
  of-artifact call left to me by a bead silent on it.
- **Backend coverage source-scoped to `backend`, tests omitted.** First run
  counted test files (68%); scoping to source gives the real signal (71%).
- **CI non-blocking + Node 20.** The bead specified informational-only; Node 20
  is the current LTS and matches the vite/vitest engines. Internal-structure call.

## Review findings adopted

**Fresh-eyes (round 1):** frontend CI switched from the fragile `npm test -- run`
arg-order invocation to a new explicit `npm run test:run` script (mirrors
schema-editor); schema-editor `vite.config.ts` got the
`/// <reference types="vitest/config" />` directive so its coverage block is
type-checked; coverage exclude globs hardened to `*.{test,spec}.{ts,tsx}`.

**Codex (round 2) -- three real P1s, all adopted:**

1. **`[coverage:*]` in `pytest.ini` was dead config.** coverage.py only
   auto-discovers `.coveragerc` / `setup.cfg` / `tox.ini` / `pyproject.toml`, NOT
   `pytest.ini` -- so bare `--cov` ignored `source`/`omit` and counted test files.
   Verified empirically (test files appeared in the report). Moved the scoping to
   a standalone root `.coveragerc`; re-verified `backend/tests/*` is now omitted
   and `source = backend` pulls in untested modules. This corrected the backend
   baseline from a mis-measured **71%** to the honest **54%**.
2. **schema-editor lockfile tripped `npm ci`** (`Missing: esbuild@`) under a
   different npm version than the local one (could not reproduce on npm 11.9.0,
   but Codex reproduced consistently). Regenerated the lockfile
   (`npm install --package-lock-only`), which dropped 723 lines of inconsistent
   nested entries down to a canonical tree; clean `npm ci` + 113 tests pass. The
   frontend lockfile regen was a no-op (already canonical).
3. **Node 20 is EOL** (2026-04-30; today 2026-06-09). Bumped both CI jobs to
   Node 22 (current maintained LTS).
