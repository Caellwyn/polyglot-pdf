## Trigger

Maintainer directive (2026-06-12): while closing uov.5 I noticed the frontend
had ~22 `tsc --noEmit` errors that neither vitest (transpile-only, no full
type-check) nor CI caught. The maintainer asked me to fix the errors AND make
tests or CI catch this class going forward. Filed as polyglot-pdf-uov.17 under
the spec-driven test & codebase-health epic (uov); a clean type-check is exactly
the kind of codebase-health gap the epic exists to close.

## What shipped

Took the count from **23 -> 0** (`cd frontend && npm run typecheck`). 23 not 22:
one was self-inflicted -- an unused `@ts-expect-error` I shipped in
`webFormConnection.reconnect.test.ts` (#168), invisible to vitest, which is
precisely the gap this gate now closes.

Fixes, each triaged (stale type / real bug / safe narrow -- never an `any` cast):

- **FormSchema has no `id`** -> the two voice overlays passed `schema.id` to
  `LanguageSelectionModal`'s `preselectedFormId`; switched to
  `form_metadata.form_number` (the form identifier the modal matches against).
- **navigation.ts declared a duplicate, incompatible local `FormField`** (a flat
  `{id,name,type,required?,options?...}`) and assigned canonical schema fields to
  it. Replaced with a re-export of the canonical `FormField`. **This unmasked two
  latent runtime bugs in `formatNextFieldHint`** -- the hint string Gemini
  receives for the next field:
  - `field.required` was always `undefined` (canonical puts it under
    `validation.required`); the "required" suffix never rendered. Fixed to
    `field.validation?.required`.
  - `field.options` are `FieldOption` objects, not strings, so
    `options.join(', ')` produced **`[object Object]`** in the hint. Fixed to map
    to `o.label`. (Both were hidden by the duplicate type; now correct.)
- **FieldHelp has no `format_hint`** -> SelectField placeholder uses
  `inline || example`.
- **ConnectionCallbacks missing `onStopCapture`/`onFormComplete`** -> the call
  sites were already optional-guarded and no consumer wires them; added both as
  optional interface members (kept as the UI-lifecycle seam rather than deleting).
- **`AudioEnergyCallback` imported but never defined** (dev-only vad-tuning tool)
  -> defined + exported it in `audioManager.ts` to match the shape the hook
  builds; that also typed the implicit-any `reason` param.
- **`new Set()` -> `new Set<string>()`** in `clearLoadedFieldIds`.
- **`Blob([Uint8Array])` -> `Blob([new Uint8Array(bytes)])`** in pdfFiller (TS
  5.x BlobPart tightening; described pdf-filling behavior is unchanged).
- **validation.ts `show_if` membership** (`contains`/`in`/`not_in`) -> coerce both
  sides to string so the mixed `string|number|boolean[]` value list and the
  `string|boolean|string[]|null` trigger compare stably.
- **SchemaFormDemo `selectedForm` possibly null** -> capture the narrowed form in
  a const so the async `loadSchema` closure keeps the guard's narrowing.
- **Real bug -- `unwrapToBoolean`**: `unwrapped === 1` was type-dead (the unwrap
  return type excludes number) but DID handle a numeric `1` at runtime. Rewrote
  to `String()`-coerce so both `1` and `'1'` map to `true` without a
  TS-unreachable branch.
- Removed the unused `@ts-expect-error` (my #168 slip).

**The gate** (exit criterion 2): added a `typecheck` script
(`tsc --noEmit -p tsconfig.json`) to `frontend/package.json` and a "Type-check
(frontend)" step to the `frontend-tests` CI job, split out from the test step so
a type error surfaces as its own red step. Proven both ways: a deliberately
injected `const x: number = "str"` made `npm run typecheck` exit 2 (job fails);
clean again after revert (exit 0). Informational, NOT a required check -- the
uov.3 "CI is non-blocking by design" decision still governs; making it a required
check would be a separate call.

Verification: `tsc --noEmit` 0 errors; full FE vitest suite stays **289 green**
(no behavioral regression from any type fix). Pre-PR fresh-eyes assess: **1 round
(Sonnet) -> NO-GAPS.** The reviewer built truth tables for `unwrapToBoolean`
(identical for every input) and the `contains`/`in`/`not_in` String-coercion
(confirmed live-neutral -- no active schema uses those operators with mixed
types), and proved the CI gate exits non-zero on an injected type error. The two
genuine behavior changes (`formatNextFieldHint` hint correction;
`preselectedFormId` now forwards the real form_number) are intentional bug fixes,
noted above. No out-of-scope beads filed.

## Lessons

A **duplicate local copy of a shared type** (navigation.ts's own `FormField`)
silently absorbed two real runtime bugs -- the type was loose enough that wrong
property accesses (`field.required`, `field.options.join`) compiled. The moment
the duplicate was replaced with the canonical type, both surfaced. Generalizes:
prefer importing the canonical type over redeclaring a "simplified" local one;
the local copy is where drift hides. And: **vitest does not type-check** (it
transpiles), so a green test suite is NOT evidence of type-correctness -- a
standalone `tsc --noEmit` gate is the only thing that catches this class. Noted
in `docs/standards/testing.md`.
