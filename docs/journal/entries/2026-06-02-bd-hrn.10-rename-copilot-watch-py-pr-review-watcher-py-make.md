## Trigger

GitHub changed Copilot pricing on 2026-06-01 to per-token metering against a
finite monthly credit pool -- the previously-"unlimited" tier is gone, and the
maintainer burned ~250 of 7000 monthly credits in the first hour. Two responses,
bundled into one PR:

- **hrn.7** (near-term cost control): make Copilot review opt-in and skip it for
  PRs that can't regress.
- **hrn.10** (cutover prep): get the review tooling ready to switch from Copilot
  to OpenAI Codex once the prepaid credits are spent (the cutover itself is
  hrn.9, gated behind the hrn.8 "credits exhausted" marker), without ungating
  hrn.9. Doing the watcher generalization now, while the design is fresh, keeps
  the eventual cutover to a config flip.

## What shipped

**hrn.7 -- Copilot review is now OPT-IN.** Auto-review-on-open was disabled in
repo settings (maintainer), so a review fires only when the PR body contains
`@copilot please review`. Closeout SKILL Steps 6-7 were rewritten: the trigger
goes in the PR **body** (not a comment -- saves a Claude turn), an
orchestrator-judged review-worthiness gate skips docs/beads/journal-only PRs, and
each re-review is now requested explicitly (a fix-push no longer auto-triggers).
The prior docs (SKILL.md, CLAUDE.md, review-flow.md) asserted auto-review-on-open
and `review_on_push` re-triggering -- both now FALSE -- so those claims were
corrected, not just appended to.

**hrn.10 -- reviewer-agnostic watcher.** `scripts/copilot_watch.py` ->
`scripts/pr_review_watcher.py` (git rename, history preserved), generalized to
`--reviewer copilot|codex` (default `copilot`). A frozen `ReviewerProfile`
dataclass isolates the four reviewer-specific knobs (login markers, timeline
lifecycle events, error sentinel, clean signals); the heavily-scarred classifier
(approval-phrase / change-ask / inline-findings-first, each a past `bd` fix) is
reused verbatim across both reviewers.

The Codex profile: login `chatgpt-codex-connector[bot]`; `uses_timeline=False`
because Codex emits no `copilot_work_*` events (completion is read off the review
surfaces + `--since` floor instead); and CLEAN detected from the **canonical 👍
(`+1`) reaction** via `clean_reaction="+1"`. The reaction is read from the
comment's inline `reactions` rollup (`comment["reactions"]["+1"] > 0`) -- GitHub
ships that by default, so **no extra API call**. The "Didn't find any major
issues" text sentinel and exact `LGTM` are fallbacks. Classification order in the
issue-comment path: ERROR > inline-finding(COMMENTS) > 👍-reaction(CLEAN) >
prose-approval(CLEAN) > change-ask(COMMENTS) > absence(CLEAN) -- an inline
finding always outranks a 👍, so a thumbs-up can never mask a real ask (pinned by
`test_codex_inline_finding_beats_thumbs_up`).

**Codex review-context files.** Added `AGENTS.md` (the OpenAI Codex sibling of
CLAUDE.md -- the file Codex actually auto-discovers, walking project-root -> cwd).
It points at the same canonical docs as CLAUDE.md and carries an inlined
"If you are reviewing a PR" section (comment-only, post-summary-every-round,
approve-via-👍, assign-on-dev-findings). Deleted the never-read
`.github/codex-instructions.md` -- that filename was never a Codex convention
(Codex reads AGENTS.md, and does not follow links inside it, so review rules must
be inline), and keeping it invited drift. Fixed its two live references
(copilot-instructions.md companion line, branch-protection-setup.md); the journal
reference was left as historical record.

**Tests.** `test_copilot_watch.py` -> `test_pr_review_watcher.py`; existing 75
tests updated to thread the profile and still pass (behavior-preserving for
Copilot). Added Codex coverage: profile/login disjointness, sentinel CLEAN,
no-timeline path, error sentinel, change-ask, and the reaction tests (detection
helper, reaction-CLEAN, empty-comment-with-👍, and the inline-beats-👍 ordering
guard). Full suite: **409 passed** (excl. flaky `external`).

**Trigger mechanism correction (mid-closeout).** The body-trigger premise behind
hrn.7 was WRONG: `@copilot please review` in the PR *body* does not fire a review
(observed on this very PR, #52) -- it must be a PR **comment**. Fixed by CHAINING
the trigger comment into the same Bash call as `gh pr create` (a `&&` sequence), so
it still costs zero extra Claude turns, and capturing the comment's `created_at` as
the round-1 watch's `--since` floor in that same call. SKILL Steps 6-7, the Hard
Rules, CLAUDE.md, and review-flow.md were corrected accordingly.

**Fresh-eyes triage (PR #52):** 7 findings; 2 high-confidence behavior bugs + 2
doc-staleness adopted, 3 rejected/accepted-risk.
- **Adopted (high):** (1) Codex TIMEOUT note always read "never started" (no
  in-flight signal for a non-timeline reviewer) -> now "did not complete in the
  window". (2) closed-without-merge was structurally unreachable for Codex
  (`state` always `"reviewed"` nullified `closed_state` every poll) -> an abandoned
  Codex PR TIMEOUTed instead of CLEAN; gated the nullification on `state ==
  "working"` so only a provably-in-flight review suppresses the closed terminal.
  Both pinned by new regression tests (+ a Copilot non-regression guard).
- **Adopted (doc-staleness):** stale `copilot_watch.py` refs in
  `docs/doctrine/workflow.md` (current-state -> renamed) and
  `docs/sprint_1_harness-tuning_plan.md` (point-in-time plan -> added a post-sprint
  rename note rather than falsify the historical prose).
- **Rejected / accepted-risk:** broad `("codex",)` login marker (same design as
  Copilot's `("copilot",)`; real bot login is distinctive) ; the
  count-not-actor 👍 rollup (documented accepted risk) ; the copilot-instructions
  cross-ref to AGENTS.md (informational, not a bug). The curly-apostrophe sentinel
  "duplicate" got a clarifying inline comment so a future maintainer won't collapse it.

Nothing deferred to a new bead this sprint beyond the already-filed hrn.8 (credits
marker) and hrn.9 (cutover activation).

## Lessons

- **Codex discovers `AGENTS.md`, not an ad-hoc `codex-instructions.md`**, and it
  builds its instruction chain from the files themselves without following links
  inside them -- so review rules a bot must obey have to be INLINE in AGENTS.md,
  not pointed-to. A file the agent never reads is pure drift risk; delete it.
- **Generalize by extracting a profile, not by branching the classifier.** The
  watcher's value is its scar tissue (each heuristic traces to a past
  false-positive/negative). Putting the reviewer-specific bits in a
  `ReviewerProfile` and leaving the classifier untouched preserved every fix
  while adding a second reviewer -- and made the Codex path independently
  testable.
- **Prefer structured signals over text.** Codex's 👍 is read from the structured
  `reactions` rollup key `"+1"` (pure ASCII, no glyph parsing), not by scanning
  the body for an emoji -- robust to language/wording and to Windows cp1252.
