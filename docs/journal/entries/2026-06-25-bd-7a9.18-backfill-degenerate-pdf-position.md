## Trigger

On the newly-extracted W-7 form, the schema editor's click-to-jump was dead: clicking
a field in the list did not scroll/highlight the PDF, and vice versa (it worked on
I-90). The maintainer suspected the field coordinates were wrong. They were: every
W-7 field's `pdf_position` was `{page, x:0, y:0, width:0, height:0}`.

## What shipped

Root cause (verified against the W-7 schema + AcroForm dump): the LLM extractor
frequently emits a PLACEHOLDER `pdf_position` of all zeros. `extract_form.py`'s
deterministic position back-fill guarded with `if field.get("pdf_position"): continue`
-- and a zero-filled dict is truthy, so the back-fill treated every field as "already
positioned" and never ran. The AcroForm dump HAS the real rect for each widget
(keyed by the exact `pdf_field_name` the draft copies verbatim), and 56/56 W-7 names
matched the dump exactly -- so the data to fix it was always present; the guard just
skipped it. I-90 only worked because that extraction run happened to OMIT
`pdf_position` entirely (so the truthy-guard passed and back-fill ran).

The fix (`scripts/authoring/extract_form.py`): a new `_has_usable_position()` helper
treats a position as usable ONLY when it has a positive width AND height (a genuine
AcroForm widget always does). The back-fill now runs when the position is missing OR
degenerate, replacing the zeros with the dump rect. A field whose name is absent from
the dump keeps its zeros (we can't do better) and is not counted as filled.

Verified on the real W-7: before, 61/61 fields had no usable position; after the
fixed back-fill, 0/61 -- every field got a real rect from the dump. The filled
positions are all on-page (page 612x792, all in-bounds) with 39 distinct
y-coordinates (genuinely spread across the form, not a repeated value). I re-ran the
deterministic back-fill on the on-disk `form-kits/w7/schema.json` so the form's
positions are now correct (that file is local working data, not part of this PR).

**Exit-criteria scorecard (all PASS):**
1. W-7 fields with a matching pdf_field_name have non-zero pdf_position; click-to-jump
   works -- PASS (61/61 filled, all in-bounds + varied; the editor's mapping is a pure
   function of this data, which is now valid -- the same shape I-90 already renders).
2. I-90 extraction still produces correct pdf_position -- PASS (the change only ADDS a
   back-fill path for degenerate/missing positions; a usable position is left
   untouched, covered by `test_backfill_preserves_a_usable_position`).
3. A test covers the degenerate-zero back-fill path -- PASS
   (`tests/test_extract_form_backfill.py`, 13 cases incl. the all-zero W-7 case).

## Lessons

- **A truthy-but-empty placeholder defeats a `if x: skip` guard.** The LLM emits a
  structurally-present-but-useless value (an all-zero rect), and "present" was
  conflated with "valid." Guards over LLM output should validate the value is
  USABLE, not merely present -- here, positive width AND height, not just a non-empty
  dict. Generalizes to any deterministic back-fill layered over flaky model output.
