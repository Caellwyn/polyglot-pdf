## Trigger

The maintainer decided on 2026-11-17 that transcripts from simulated runs may be
committed. Every answer in those runs comes from a scripted or simulated fake
person, and keeping records of the experiments matters more than the privacy of
people who do not exist. The decision is recorded as bd memory
`synthetic-sim-run-artifacts-may-be-committed`. This bead commits the
transcripts from the gemini-3.8-live smoke test (bd r3ham.2), which had been
kept local only.

## What shipped

- Five `--debug` transcripts from the smoke test are now in
  `scripts/spikes/data/r3ham/smoke/<base>.synthetic-transcript.json`, next to
  their cost data. The runs are four W-7 runs (3.8 spelled, 3.8 unbounded, 3.8
  short run, and the 2.5 comparison) and one I-90 v2 run. The 3-question pilots'
  transcripts are not included.
- Each file's `note` field was rewritten. It now says the run is synthetic,
  names the scripted question tables the answers come from, and cites the
  decision. The original note called the file LOCAL-ONLY user data, which would
  contradict the committed copy.
- **The default stays closed.** The harness still writes `*.debug.json`, and the
  repo-wide ignore for that pattern is unchanged. A run gets committed only when
  someone deliberately copies it under the synthetic name. The `.gitignore`
  comment now names that exception. Real speech captured with `--debug` is still
  never committed (`docs/standards/hipaa-pii-policy.md`).
- **One finding is now verified.** The smoke findings doc had left the q16
  empty-visa write "unverified" because its evidence was in the uncommitted
  transcript. The transcript shows 3.8 called
  `update_form_fields(us_visa_type_number_expiration, value="")` and then
  confirmed the empty field. That was an explicit empty write, not a dropped
  call. Noted on bd r3ham.12.

## Lessons

- Opening up a privacy guard for a narrow class of data works best as an
  explicit, named opt-in (a distinct filename). Widening the ignore pattern
  would also open it to real-user runs.
