# Guidance content contract + containment lint + eval metrics (bd wsao.3)

## What shipped

Step 3 of the sprint-16 instructions-enrichment epic:

- **`backend/services/guidance_contract.py`** -- ONE module owning the
  guidance rules for both channels (render-once pattern): the pinned
  containment normalization (unicode punctuation folding, dehyphenation,
  whitespace collapse, casefold; exact substring match -- no similarity
  scores, they would readmit paraphrase), `check_containment` with a recorded
  matched span, `details_paragraphs` (heading scaffolding excluded),
  `is_label_restatement`, the size bounds, and CONTRACT_TEXT for the
  enrichment + judge prompts (wsao.4/.5).
- **8 lint rules in `schema_lint.py`** (all WARNING -- inform, never block):
  instructions missing / too-long / label-restatement / screen-ref; details
  not-contained / no-reference-floor / oversize / headings-missing.
  **Coverage is ONE AGGREGATED finding per schema** ("N of M askable fields
  have no help.instructions"), not per-field -- a fresh pre-enrichment draft
  would otherwise flood the ValidationPanel (and it broke 31 zero-findings
  tests before aggregation; decide-and-note: read_only + signature fields
  are excluded from "askable").
- **eval_extraction guidance columns** (guid% / gLen / cont%): baseline now
  shows i-90 100%/72-char-median, w7 + f1040 0% -- the epic's before/after
  will be visible on every eval run, zero model calls.
- ValidationPanel RULE_LABELS for all 8 rules; the aggregate coverage finding
  anchors at `$.fields` (no field focus BY DESIGN -- the one documented
  exception to the every-finding-focusable contract, noted in the P4.3 test).
- 12-test suite (`test_guidance_contract.py`) incl. the exit-criterion check
  that the coverage rule fires on the REAL w7 kit.

## Table-region eyeball (exit criterion 3; recorded on the bead)

The w7 booklet's prose pages extract cleanly; the Exceptions Tables grid
pages are structurally garbled in BOTH PyMuPDF modes (plain text interleaves
columns at row level; blocks mode merges the two column headers into one
block). Consequence for wsao.4: the engine must reconstruct table rows from
blocks/dict mode or prefer the official IRS HTML for table regions -- and the
baked booklet FLOOR for table regions must be the structured extraction,
because containment verifies faithfully against whatever floor is baked.

## Scar / notes

- The coverage rule's first per-field draft broke 31 tests across 2 files --
  the aggregate-per-schema shape is load-bearing, not cosmetic. Structural
  lint tests now filter `help-*` via `_rules`/`_lint_structural` helpers
  (guidance rules have their own suite).
- Two editor-route fixtures (`VALID_SCHEMA`, the clean-extract draft) now
  carry authored help.instructions so "clean schema reports zero findings"
  keeps meaning CLEAN under the new standard.
