## Trigger

Sprint 20 stage 5 (epic `polyglot-pdf-s1iex`, plan
`docs/sprint_20_sol-intro-tts_plan.md`). With Sol's clip playing from a
static file (bd `s1iex.5`), the Live session is no longer needed before
Agree -- which is what lets the epic delete its second-biggest prize: the
teardown-and-re-handshake seam that produced beads `zq9l` and `ppf1`.

## What shipped

- **Neither overlay connects before Agree on the intro path.** Both the mount
  effect and the language-select handler now show the modal WITHOUT
  connecting; Agree makes the first and only handshake. The interrupt
  sequence (`sendActivityStart` -> `flushAudioQueue` -> `resumePlayback` ->
  `sendActivityEnd`) and `switchToFirstSection`'s
  disconnect/100ms-sleep/re-handshake are unreachable there -- they existed
  only to cut off a model mid-disclaimer, and there is no model to cut off.
- **The already-accepted (reload) branch STILL connects at mount**, guarded
  conjunctively (`introEnabled && !alreadyAccepted`). A reload user never
  sees Agree; removing the mount connect wholesale would leave them with no
  session at all. The plan called this out and the test pins it.
- **The acceptance POST was extracted to one helper per overlay**, so the
  intro and legacy paths log identically. On the intro path it runs
  ALONGSIDE the connect rather than gating it -- a slow logging call must not
  delay the session the user is now waiting on.
- **`INITIATING_MESSAGE` no longer greets.** Sol introduces himself by name
  in the clip, so the model's "Greet user warmly" landed seconds later as a
  second hello. Unconditional, not flag-gated, with the dark-period cost
  recorded (returning users who skip both modals lose the Live greeting until
  the flag flips).
- **A SET-pinned single-handshake test** (`introSingleHandshake.test.ts`, 12
  tests over both overlays): the complete list of connect sites, each
  pre-Agree one flag-guarded, the restart and interrupt unreachable, the
  reload branch preserved, and the legacy path still present for flag-off.

## Lessons

- **Deleting a step deletes its SIDE EFFECTS, and those can be invisible.**
  Fresh-eyes graded criterion 1 a FAIL for a reason I had not considered:
  `switchToFirstSection` was not just the second handshake, it was the ONLY
  production caller that moved the connection manager's `fillLanguage` off
  `createConnectionManager`'s hardcoded `'English'`. Deleting the restart
  therefore shipped `fill_language="English"` in the handshake, so a Spanish
  user would HEAR Spanish (the spoken-language path is separate and correct)
  while every field's guidance told the model to WRITE the values in
  English -- silent data corruption with no audible tell. Fixed by calling
  `changeFillLanguage` BEFORE the connect (it stores the value when not yet
  connected, so it rides the handshake instead of correcting afterwards), and
  pinned positionally: set-before-connect, inside the intro branch. When
  removing a call, enumerate what it did BESIDES the thing you are removing.
- **The SAME lesson, twice, from two different reviewers.** After the
  fill-language miss, the Opus cross-surface pass found a SECOND side effect
  of the deleted restart: `kit_id` rides only the JIT handshake builder, and
  that builder is selected by a flag set from the backend's `session_ready`.
  So a session's FIRST handshake always used the legacy builder, which
  omitted it -- harmless while the form-filling handshake was the SECOND one,
  and silent audit-trail loss once Agree's single connect was the only one.
  `kit_id` is deliberately not derivable from form_metadata, so the backend
  has no fallback: every confirmation record for that session would carry a
  null kit, losing the only discriminator between two kits sharing a
  form_number. Fixed at the SOURCE (the legacy payload now carries it, which
  closes the gap for every first handshake, not just the intro path) and
  pinned on BOTH builders.
- **A mutation test that did not mutate reported success.** The first attempt
  to verify the kit_id pin printed "RED as expected" while the edit had
  silently failed to apply (CRLF marker mismatch); the `||` chain ran the
  failure branch and the error scrolled past. Re-done with an explicit
  applied-check (occurrence count 2 -> 1 asserted BEFORE running the suite).
  Always prove the mutation landed; a no-op mutation looks exactly like a
  passing guard.
- **The bead named ONE test file; the set was THREE.** `test_resume_reconnect`
  was the file the plan predicted, but `test_dti` carried two live "greet"
  assertions and `test_restart_gemini_session` had a test whose NAME asserted
  the old behavior (`..._still_greets`). Found by grepping the whole suite for
  the word rather than trusting the bead's list. All three now identify the
  base template by its section-name directive -- "greet" can no longer
  discriminate, since neither template contains it.
- **Writing the set-pin test found a call site I had missed.** My first draft
  asserted three `handleConnect()` sites; it failed against four. The fourth
  is the stale-connection reconnect inside the legacy Agree sequence --
  genuinely unreachable on the intro path, but only because it sits BELOW the
  early return. So the test asserts that POSITIONALLY rather than by keyword
  proximity: a proximity check still passes if someone moves the return below
  it, which is exactly the edit that would resurrect the second handshake.
  The test earned its keep before it ever ran green.
- **CRLF defeats exact-match string edits.** Two scripted edits silently
  no-opped against a CRLF file (the replace found nothing and reported
  success). The tell was the tests failing IDENTICALLY after an "applied"
  fix. Use the Edit tool, which normalizes, or verify the edit landed before
  re-running.

## Related

A pre-existing instance of the SAME defect class this bead fixed lives on the
soft-refresh reconnect path: a returning non-English user's handshake still
carries `createConnectionManager`'s hardcoded `'English'` fill language,
because that path never calls `changeFillLanguage` either. Verified unchanged
on `origin/dev` and filed by the round-2 reviewer as `polyglot-pdf-oovy1`
rather than folded in here -- it is a different trigger (page reload, not
first connect) and out of this bead's scope.
