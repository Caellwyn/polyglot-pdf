## Trigger

bead polyglot-pdf-wpw.5, picked up after the secretary tail-latency guard (jnjj.43)
shipped. There was no visual signal for "you spoke, the agent is working, but hasn't
started replying" -- so during a slow turn (especially a secretary lookup) the app
looked frozen and users would interrupt with "are you there?". wpw.5 adds a calm
indicator for that processing gap. (It is also the UX half of the jnjj.43 tail-latency
mitigation -- the backend guard bounds the wait, this shows the user it's happening.)

## What shipped

A calm, language-neutral thinking indicator (three pulsing slate dots) in the status
row of both overlays, shown from the user's turn-end until the agent's first response
audio.

**Architecture (changed from the original spec mid-flight).** wpw.5's spec assumed a
pure-frontend gap signal (client activity_end -> first response audio). Investigation
showed the client has NO turn-end signal in native VAD (the overlay's local VAD is
deliberately off in native mode, and the backend sent no turn-boundary message). So
the signal is BACKEND-driven: a new `agent_processing` WS message.
- START: `callback_handler` emits `agent_processing:true` on a user turn. TWO
  triggers -- `service.send_activity_end -> signal_processing_start` (manual/PTT VAD)
  and `on_user_activity` (native VAD, rides input_transcription).
- CLEAR: first response audio (`on_audio`, first chunk of the turn) and turn_complete
  (`on_transcript`). Works in BOTH modes.
- Forwarded via `connection.ts` (`onThinkingChange` + `getThinking`) to both overlays,
  which render the dots and clear defensively on any move off "connected"
  (disconnect / error / section-switch) plus a frontend max-duration safety timer, so
  the indicator can never stick on.

**Decisions (maintainer, this session):**
1. **Cheap visual indicator over a spoken live-model filler** -- a live turn is
   expensive; the indicator is the right layer for "I'm working." (This also reshaped
   jnjj.43, which now spends no spoken filler.)
2. **Language-neutral animated dots over a localized "Thinking..." word** -- there is
   no general UI-string i18n infra (only the disclaimer is translated) and 18 spoken
   languages; dots need zero translation and stay calm.
3. **Ship manual/PTT now; file the native-VAD START as a scoped follow-up** (see
   below) -- after live testing proved the native gap is real.

**SCOPE / live-verification finding (the important part).** Two live real-mic tests
showed the indicator does NOT fire in NATIVE VAD -- the deployed default. Root cause,
confirmed from the backend log (0 `agent_processing` sends in native mode): the
`gemini-live-2.5-flash-native-audio` model on Vertex emits **no `input_transcription`
and no `turn_complete`**, and inbound user audio is continuous (silence streams too),
so there is no clean "user turn ended -> agent thinking" edge for the backend to
detect. `on_user_activity` (the native START trigger) therefore never fires. The CLEAR
path works in both modes; only the native START is missing. Manual/PTT mode works
(driven by `send_activity_end`). The native-VAD START signal is filed as
**bd polyglot-pdf-fa4x** (under the wpw epic) with the investigation options
(get input_transcription to actually fire / output-cadence heuristic / client
approximation). This is honest partial delivery: the feature is correct and tested in
manual/PTT, and the default-mode gap is clearly scoped, not silently shipped broken.

**Also observed (NOT this bead):** in the live test the session disconnected
(client-initiated) right after the first field's confirm, before a second turn -- a
separate, likely pre-existing client section-completion/teardown edge, unrelated to
the thinking signal. Not filed yet (needs its own repro); noted here.

## Lessons

- **Verify the turn-boundary signals a feature depends on against the ACTUAL model,
  not the spec.** wpw.5's whole design hinged on a client- or model-emitted turn-end
  edge; the native-audio model provides neither. Two live tests caught what unit tests
  (which stub `on_user_activity`) never could. For any future "react to the
  conversation turn" feature, confirm the boundary event actually fires in native VAD
  first.
- **A signal that silently never fires in the default mode is worse than none** -- it
  reads as "done" while doing nothing. Better to ship the mode that works, scope the
  gap explicitly (fa4x), and say so, than to land dead code.
- **"thinking" is orthogonal to ConnectionStatus.** It is a separate boolean
  (`onThinkingChange`), not a status value -- folding it into status would collide
  with the many `status === "connected"` gates.

## Doc freshness

- No tier-1/2 doc documents the per-turn indicator or the `agent_processing` wire
  message specifically. `ws-protocol.md` is the wire registry, but `agent_processing`
  is a backend->frontend signal that is still scope-incomplete (native START pending
  fa4x); deferring its protocol-doc entry to fa4x (when the signal is whole) avoids
  documenting a half-wired message as frozen contract. Noted as a fa4x doc task.
- STALE docs tracking the touched files (voice-ai, tool-call-flow, config-deployment,
  etc.) were already stale before this branch and none documents the indicator
  behavior -- reviewed and left.
