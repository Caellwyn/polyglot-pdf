# Verify loop + provenance write: w7 is the first born-verified kit (bd wsao.5)

## What shipped

The wsao.5 machinery in `enrich_instructions.py` + `guidance_contract` +
`schema_lint`:

- **Judge** (`JUDGE_TEXT` rubric; chunked; mid-tier `gemini-2.5-flash` with
  the thinking budget pinned to 0 in `run_json_gemini` -- the Vertex
  flash-thinking cost scar): grounded / unsupported_claims /
  useful_beyond_label / omission_concerns / advice.
- **Bounded rectify** (max 2, full re-entry through the contiguity repairer).
- **KEEP rule, safety-scoped**: drops happen ONLY on safety failures
  (grounding / advice / omissions); a usefulness-only miss FLAGS for the
  human worklist and keeps the text. Judge-unavailable empties every
  proposal (fail SAFE) + one flag.
- **Provenance-guarded write** (`write_kit`): sha1 per key
  (instructions/details/format_hint) + `booklet_sha1`; blank or
  hash-matching machine text updates; anything else is human-protected.
  Legacy bootstrap marks /TU-identical fields machine-owned (leaf-name
  matching -- schemas store widget leaves).
- **Flags re-emitted by lint** (`_emit_guidance_flags`, the
  instructions_enrich analog of the translation flags) + ValidationPanel
  labels: rectified / ungrounded-dropped / enrich-unavailable.

## Measured: the judge tier matters, and usefulness must not gate

- flash-lite judge (first run): 22 FALSE-NEGATIVE drops on
  "not useful beyond the label" -- destroying genuine guidance like
  treaty_country's residence-country interlock. Coverage 87.7% -> 47.4%.
- Fix: mid-tier judge + the safety/quality split above. Result: 44 fields
  written, 6 conservative safety drops (each flagged; the human can restore
  from the worklist), the written kit lints with exactly the 6 persisted
  flags + the coverage aggregate. `scripts/spikes/data/wsao5_w7_verified_write.json`.

## The i-90 bootstrap finding (recorded on the bead)

The bootstrap mechanism works (leaf matching + exact /TU equality,
unit-pinned) -- and honestly marks **0 of 132** i-90 fields machine-owned:
the shipped i-90 corpus is AUTHORED prose, not /TU copies (the sprint-16
recon premise was wrong). All 132 are human-protected, so the wsao.7 refresh
needs a maintainer-authorized `--force` or a widened ownership rule; the
height/weight canary stays reachable that way.

## Scar / notes

- Appending functions AFTER a file's `__main__` guard leaves them undefined
  when the CLI runs (imports were fine, so tests passed) -- the guard now
  lives at the file end with a comment saying why.
- A judge tier that authors filler also judges poorly: floor-tier verdicts
  on abstractive quality are not trustworthy. Safety axes (grounding /
  advice / omission) are the only drop-worthy verdicts at any tier.

## Re-bake evidence (outer review round 2, 2026-07-27)

The committed kit was baked before the fail-open fixes landed, so the outer
review asked whether "born-verified" still holds. A full re-bake through the
FIXED pipeline (`scripts/spikes/data/wsao5_w7_rebake_fixed_pipeline.json`)
produced **byte-identical help content, form_details, and booklet floor** --
the born-verified claim is evidence-backed, and the committed kit (which
carries the 6 worklist flags) stays canonical.

The re-bake also EXPOSED one more silent path: the same 6 fields entered
verify with content and came out empty with ZERO flags. Of the four paths
that empty a field, three flag (disposition drop, judge-unavailable,
completeness sweep) -- the only unflagged one was the rectify writeback
accepting all-blank revisions, so that is the deduced mechanism. Same
content outcome as a drop, invisible to the worklist. Fixed:
rectify-to-empty now emits the same instructions-ungrounded-dropped flag
(pinned by test; the mechanism is proven by the unit test, not the
artifact, which records no verdicts).

The i-90 bootstrap result (0/132) is deliberately NOT committed as a kit
change -- an empty provenance block plus a whole-file reserialization adds
review noise and zero function. The finding lives on the bead and here.
