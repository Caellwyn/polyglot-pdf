## Trigger

`bd polyglot-pdf-7a9.14`. Surfaced during 7a9.9 (Q5): the bake-off scorer matches
on pdf_field_name -- a PROXY for fill-ability that is sound for text but NOT for
checkbox/radio, where the filler selects the widget by matching the app-sent value
against option.value. A schema can score green on names yet fail a real choice
fill. The bead asked for a true round-trip harness, the I-90 choice convention
preserved + enforced, and an extractor that reproduces it -- explicitly preserving
the hard-won I-90 checkbox/radio shape.

## What shipped

Throwaway research (scripts/bakeoff/), no app import; per-arm draft JSON gitignored.

- **roundtrip_fill.py (NEW)** -- feeds a schema through the EXACT production fill
  semantics (backend/routes/pdf_fill_routes.py: field_value+xref_set_key(AS) for
  buttons, field_value+update() for text, exact-then-endswith find_widget,
  read-only bit-flip unlock), saves, re-opens, asserts each widget got its value.
  Reports choice_fill_success (checkbox+radio) separate from text, PLUS a
  value_convention score (option.value == widget leaf). Checkbox/radio verified
  via the /AS xref key (probed: a checkbox's field_value reads back EMPTY after
  save+reopen; state lives in /AS).
- **schema_contract.py** -- added CHOICE-FIELD RULES + a canonical leaf-convention
  example: radio pdf_field_name=null, option.value==widget leaf (== the same
  string controls_fields[].value uses), multi-widget radio grouping by meaning,
  read-only dual-key unlock, on-state derived live.
- **arm_llm_native.py** -- hardened _extract_json: the Claude CLI narrates before
  the JSON ("Let me build the schema...\n{...}") and/or trails a remark; the old
  code grabbed a bracket from the prose and returned a 1-field fragment. Now scans
  every {/[ start, raw_decodes each, keeps the dict carrying "fields" (else
  longest parse). Also tightened the CLI wrapper instruction.

Results (I-90, claude-opus-4-8):
- Harness self-test: I-90 gold scores 23/23 choice + 108/108 text = 100%
  EXCLUDING one defective field; the 5 misses are a REAL production bug (p3_race --
  option pdf_field_names drop the [0] index so the filler never finds them, AND
  semantic values off-convention). Race silently does not fill in the live app.
  Filed bd polyglot-pdf-7a9.15 (P1).
- Gap measured: before encoding, both LLM arms scored 0% value-convention (emit
  "Yes"/"No") despite 100% mechanical fill -- the closed-loop trap the proxy
  misses. After encoding: Opus 100% value-convention (78/78), 100% choice fill,
  and reproduced the exact hand-built I-90 shape incl. the Male/Female two-widget
  radio and the controls_fields leaf reference.

## Lessons

- **Mechanical fill success is necessary but not sufficient for choice fields.**
  A harness that synthesizes its value set from the schema's own option.value
  tests a closed loop -- it proves "this schema fills its own widgets," not "these
  values match what the app sends." The separate value_convention metric
  (option.value == widget leaf == controls_fields value) is what actually catches
  the failure. Generalizes: when a round-trip test sources its inputs from the
  artifact under test, add an independent conformance check or it self-confirms.
- **A round-trip harness finds bugs a name-match proxy structurally cannot.** On
  its first run it caught a live production fill bug (p3_race) the merged scorer
  had passed.
- **CLI-backed LLM output needs prose-tolerant JSON extraction.** Headless
  `claude -p` reasons before/after the JSON; parse by scanning for the JSON value
  that carries the expected key, not the first bracket.
