## Trigger

Gate 1 (bd polyglot-pdf-jnjj.26) is the keystone feasibility question for the
principal/secretary architecture (epic jnjj, SI reduction via task delegation): can
a cheap model (`gemini-2.5-flash-lite`), given the form's per-field context + the
client's current values, answer the principal's PROSE questions reliably enough to
serve as the "secretary"? If retrieval is unreliable, the downstream latency (G2)
and cost (G3) gates are moot.

## Design (settled with the maintainer, 2026-06-18)

The secretary is a PURE retrieval+reasoning specialist, not a navigator:
- It receives the whole form state + relevant per-field context (rendered
  algorithmically from the client's filled state, not the full schema) and returns
  a PROSE answer (the product the principal voices to the user).
- It also emits a structured `sourced_from` field-id trace -- LOGGED ONLY (debug /
  audit / measurement), never returned to the principal (the principal has no form
  structure, so ids are meaningless to it).
- The principal navigates by acting on the prose (its own `switch_section` today; a
  field-level nav tool is the separate, non-blocking prerequisite bd jnjj.36).

Two stance decisions shaped this bead:
1. **Characterize, do NOT auto GO/KILL.** The real safety mechanism is the existing
   human-in-the-loop (principal voices every answer back as a verifiable statement;
   user confirms through the principal; UI focus indicator shows the referenced
   field). "Good enough + CYA" is judged by a human reading the numbers, not a
   threshold the script fails on. The bead's exit criterion #2 was edited from
   "Clear GO/KILL recorded" to the characterization framing so the bead, PR, and
   closeout assessor agree.
2. **Single context format (grouped-by-section) for feasibility;** format
   comparison (flat vs grouped vs prose) is the deferred follow-up bd jnjj.37.

## What was built

Mirrors the G1 contradiction-probe template (bd jnjj.5):
- `backend/scripts/secretary_context.py` -- renders the secretary's grouped-by-
  section context from `(schema, field_values, shown_map)`. `shown_map` is a
  SEPARATE applicability input (not derived from value) so the value-vs-
  applicability query class is measurable; PDF mechanics / validation regex / raw
  conditional logic excluded per the validation-delegation contract.
- `backend/scripts/secretary_recall_corpus.py` -- 49 labeled prose queries across
  six difficulty tiers (easy/aliasing/ambiguous/synthesis/distant/applicability)
  over one shared synthetic fixture; real field ids, fabricated values.
- `backend/scripts/probe_secretary_recall.py` -- asks flash-lite each query,
  scores grounding deterministically (`sourced_from` vs expected ids), counts a
  coarse confident-wrong precondition, and runs a Sonnet CLI judge
  (`claude-sonnet-4-6`, subprocess like `order_probe.py` -- reproducible from the
  script) for synthesis/disambiguation/hallucination.
- Findings: `scripts/spikes/secretary_recall_findings.md`; artifacts
  `scripts/spikes/data/secretary_recall_20260618T170938.{csv,meta.json}`.

## Result (characterization, n=49)

Flash-lite RELIABLY FINDS the right fields and almost never fabricates; its weakness
is OVER-RETRIEVAL (low precision), not invention -- the SAFE failure direction here,
since over-inclusion is caught by the principal's verify-back.

- hit rate (>=1 correct field cited): 47/49 (0.96); mean recall 0.92.
- mean precision 0.81 (the weak spot: it volunteers related-but-unrequested fields,
  e.g. "last name?" -> current AND previous family name, both correct).
- Sonnet-judged hallucination: 1/49. Truly-wrong answers: 2/49.
- The two real errors are field-DISAMBIGUATION, not invention: (1) confused US
  `zipcode` with the foreign `postalcode` sibling and said "not entered"; (2) the
  one hallucination -- invented a non-existent checkbox id and asserted "no
  interpreter" when interpreter fields were filled. Both point at near-duplicate
  sibling fields + a "cite only ids present in context" guard as the prompt/context
  work to harden.
- Rendered context ~9,461 tokens (chars/4 estimate) -- ~2x the research-plan
  estimate (2.7-5.9k); a sizing input for Gate 2 (jnjj.27) caching.

## Caveats

Every number is an UPPER BOUND -- two stacking inflation sources: clean synthetic
values (vs messy real state) AND hand-authored on-distribution queries (vs
spontaneous speech). Single context format. No `spoken_aliases`/`section_label` in
the I-90 JSON (aliasing recall rests on `help.instructions`, 132/132). `shown_map`
is a synthetic fixture, not computed from real conditional logic. Small per-tier N
(5-10) -- the verbatim CSV rows are the primary evidence; the `confident_wrong`
counter over-counts harm (use judge `hallucinated` + the findings triage: 1
hallucination, 2 truly-wrong).
