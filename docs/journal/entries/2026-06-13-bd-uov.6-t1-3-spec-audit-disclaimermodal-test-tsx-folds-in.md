## What shipped

Extended the test from 7 to 67 tests (the 3 existing substring tests left
untouched, per the bead's explicit "do NOT re-do the 3 substrings"). The new
spec audit:

- **Coverage parity across all 18 languages.** The component ships
  `DISCLAIMER_TRANSLATIONS` + `BUTTON_TRANSLATIONS` for 18 languages; only 3 were
  asserted. Added `it.each` loops driven off the EXPORTED `DISCLAIMER_TRANSLATIONS`
  map (not a hardcoded list, so a new language auto-extends the audit) asserting
  every non-English language renders ITS OWN title -- not the English fallback --
  and its own first paragraph. This catches a dropped or silently
  English-fallen-back entry in any of the ~15 previously-unasserted languages.
  **ASCII-only (scar #6):** the expected strings are READ from the source map
  rather than re-typed, so no non-Latin glyph appears in the test source.

- **The p1/p2/p3-vs-fullText distinction (the bead's named gap) -- BY DESIGN, not
  a bug.** The modal renders `p1`/`p2`/`p3` as three `<p>` nodes; `fullText` is
  the longer audio/TTS script, consumed by `VoiceOverlay.tsx` /
  `VoiceOverlayMobile.tsx` (read aloud), and is NEVER painted in the modal. Spec'd
  both sides: the three visual paragraphs ARE rendered; the contiguous `fullText`
  string is NOT.

- **Data-integrity invariants** on the public `DISCLAIMER_TRANSLATIONS` contract:
  all 5 fields non-empty per language, and `fullText` is the audio superset
  (contains p1, p2, and p3) -- which would catch a translation whose spoken and
  visual copy drifted apart.

- **Behavior beyond the 4 existing tests:** the aria dialog contract
  (`role="dialog"`, `aria-modal="true"`, `aria-labelledby` pointing at the title),
  body-scroll lock while open + restore on close, and Escape-key suppression (the
  modal is deliberately not ESC-dismissable).

67 tests, all green; the full frontend suite stays green (362 passed across 21
files). **No bug bead filed:** deriving the spec surfaced no defect -- the modal
behaves to spec across all 18 languages.

A round of pre-PR fresh-eyes caught two test-quality gaps, both fixed before the
PR: (1) the per-language check originally anchored on the title, but Spanish and
Portuguese share the title 'Aviso Importante', so a Portuguese->Spanish misroute
would have passed -- re-anchored on p1 (unique per language) with an up-front
uniqueness invariant; (2) the Escape-suppression test passed even with the
handler removed (the modal has no native ESC dismissal) -- it now dispatches a
real cancelable KeyboardEvent and asserts defaultPrevented, mutation-verified to
fail when the component's preventDefault is neutered.

The bead's "remove the it.skip" sub-task was already satisfied before this work:
PR #122 (T0.0) restored the 3 substrings and removed the skips, so the file had
no disabled assertions to remove (verified by grep). The bead had no

Pre-PR assess: rubric scored PASS; fresh-eyes adversarial loop run to NO-GAPS

## Lessons

When a spec-test bead names a "distinction" that looks like it could be a bug
(here: "p1-vs-fullText rendering"), trace the supposedly-unused field to its real
consumer before assuming a defect. `fullText` is dead in the modal but live in
the voice overlay (TTS) -- so the right spec asserts the SEPARATION (visual shows
paragraphs, audio reads fullText), not "fullText is unused." This is the
spec-driven epic's core discipline applied to a UI surface: spec the intended
behavior, and a divergence becomes a finding rather than a test you weaken.

A reusable pattern for multilingual UI coverage: loop `it.each` over the exported
translation map and assert each entry renders its OWN distinctive text. It scales
coverage to every language for free and stays ASCII-clean because the expected
strings come from the source, never re-typed.
