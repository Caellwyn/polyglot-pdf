## Trigger

`bd polyglot-pdf-7a9.4`, the head-to-head extractor comparison in the PDF->JSON
authoring epic `7a9`. Run a PDF through each extractor, emit a draft FormSchema,
score it with the `7a9.3` harness, and report a per-tool x per-half (a/b) x
per-form table plus failure modes -- so the recommendation bead (`7a9.5`) knows
where the human-labor hours actually go.

## What shipped

`scripts/bakeoff/` -- a throwaway research harness (reuses the backend venv; no app
imports; all `.py` ASCII/cp1252-safe):

- `acroform_dump.py` -- deterministic PyMuPDF AcroForm layer (exact widget names,
  flags, /TU tooltips, rects, choices). The machine-readable field structure OCR
  tools cannot see.
- `schema_contract.py` -- the compact FormSchema output contract handed to each LLM
  arm (names exactly the keys the scorer grades; no ground-truth leakage).
- `arm_gemini.py` -- Gemini multimodal + hybrid arms (native PDF input; structured
  JSON; configurable HTTP timeout).
- `arm_documentai.py` -- Document AI Form Parser hybrid arm (written + validated
  against the SDK; NOT scored -- see decision below).
- `prior_extractor/` -- the recovered + revived prior `pdf_schema_extractor`.
- `run_bakeoff.py` + `manifest.json` -- scores every arm via `schema_score.py` and
  prints the table; `FINDINGS.md` is the human-readable writeup; `_scores.json` the
  machine-readable summary. Bulky per-arm drafts are gitignored.

The Claude arms (multimodal + hybrid, both forms) were produced by subagents
reading the PDF + AcroForm dump against the contract.

## Results (see scripts/bakeoff/FINDINGS.md for the full table)

- **The AcroForm layer is decisive for (a).** Hybrid arms (PyMuPDF widget names fed
  to the LLM) score field-detection F1 96-98% on I-90; pixels-only multimodal arms
  collapse to 2-17% because invented `pdf_field_name`s never join -- and that widget
  name is the round-trip-fill key. Confirms the hypothesis: OCR/multimodal alone is
  not enough; the deterministic AcroForm dump is required input.
- **A strong LLM wins (b).** `claude-hybrid` led conditional-relationship recall on
  both forms (I-90 40.0%, I-589 41.5%), far ahead of every other arm.
- **The old extractor uniquely owns schema-conformant `section_id`** (I-589 88.3%
  vs LLM 0%) via its deterministic /TU tooltip-hierarchy parse -- the strongest
  argument for a FUSED pipeline, not a single winner.
- **Recommended pipeline (-> 7a9.5):** PyMuPDF deterministic skeleton (exact widget
  names, positions, section_ids, validation) fed to a top-tier LLM for the (b)
  reasoning (consolidation, show_if/controls/copy_to/overflow synthesis, tables).

## Decisions (defended)

- **Reuse + revive the prior `pdf_schema_extractor` as an arm + reference.** The
  bead said "clean-slate / do not reuse"; the maintainer overrode (reuse it, build
  on it). Recovered from git `a0bf111` (removed at `5ea05d4`) into
  `prior_extractor/`; revived with: PyMuPDF 1.24 `PDF_WIDGET_TYPE_RADIO` ->
  `RADIOBUTTON` and `choice_values` now `(value,display)` tuples; pydantic-v2
  `model_dump(mode="json")`; `FormMetadata.version` now required;
  `SupplementType.SUPPLEMENT_A` -> `TYPE`; and the dead v1beta REST Files API (404s
  with the current GCP-bound key) swapped for the google-genai SDK (inline bytes +
  Pydantic `response_schema`). Modernized the enhancer model off the retired
  `gemini-2.0-flash-exp`.
- **Drop Document AI (maintainer decision, after cost research):** too expensive for
  negligible benefit over a raw strong-LLM pass. Matches the bake-off structure --
  DocAI only supplies the (a) OCR label/box layer the AcroForm dump already gives
  more precisely, and nothing for (b). API/ADC/SDK were set up and `arm_documentai.py`
  validated, but no billable Form Parser processor was created. Kept for reference,
  excluded from scoring.
- **Skip `gemini-hybrid` on I-589:** Gemini 3.1 Pro `ReadTimeout` on the heavy
  460-widget fusion call at both 8-min and 20-min deadlines -- a reproducible
  operational finding (the single-shot heavy fusion is fragile; a batched/chunked
  approach would be needed). The I-90 gemini-hybrid result (best (a) in the table)
  establishes the pattern; claude-hybrid carries the I-589 conclusion.
- **Commit code + FINDINGS + `_scores.json`; gitignore the bulky per-arm drafts**
  (~4M of regenerable JSON) to keep the PR reviewable.
