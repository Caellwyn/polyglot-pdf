## Trigger

G2 (bd polyglot-pdf-jnjj.6) is the **cost arm** of the GO/NO-GO on A's manifest
swap in the SI-reduction epic (polyglot-pdf-jnjj). The epic shrinks the realtime
Live model's system instruction (SI) by sending a lightweight per-section
manifest (`field_id|spoken_name` pairs + one field's full schema) instead of the
full per-section field dump. A5 (jnjj.12) would default-flip `USE_JIT_SCHEMA`;
this bead had to measure -- not model -- whether the manifest SI actually buys a
real-dollar win on the REAL LARGEST I-90 section before that flip ships. Picked
up mid-stream from a handoff: the harness arm was built and offline-validated in
a prior session (commit f4e16f4b on `claude/competent-diffie-05dc08`); the live
4-cell matrix had not run.

## What shipped

**A measurement + a NO-GO, plus a real production defect the measurement
surfaced.**

- **Brought the handoff's instrumentation into this branch** (cherry-picked the
  `section-reset-jit` arm of `measure_form_session_costs.py`).
- **Ran the live 4-cell matrix on 2.5** (section-reset full-SI baseline vs
  section-reset-jit manifest SI, happy/unhappy):

  | arm | path | run $ | confirmed |
  |---|---|---:|---:|
  | section-reset (baseline) | happy | $0.156 | 17/20 |
  | section-reset (baseline) | unhappy | $0.363 | 20/20 |
  | section-reset-jit | happy | $0.192 | 2/20 |
  | section-reset-jit | unhappy | $0.448 | 1/20 |

- **VERDICT: NO-GO** on the manifest swap as implemented, for two independent
  reasons: (a) JIT cost MORE in real dollars on both paths despite a smaller SI;
  (b) JIT confirmed almost no fields (2/20, 1/20).
- **Rendered per-turn SI floor (exit criterion 1)** measured by rendering the
  real SI per section (each in an ISOLATED process -- see Lessons). The JIT SI is
  NOT constant: post-A2 the manifest lists every section field, so the JIT SI
  grows with field count too (just slower than the full dump). On the largest
  section (section-medical, 54 fields) the SI drops 9503 -> 5382 chars = **43.4%**
  -- a real reduction on big sections, but NEGATIVE on small ones (JIT's manifest
  overhead exceeds a small full-dump; break-even ~9-12 fields). It does not
  convert to a real-dollar win today regardless.
- **Root cause of the cost inversion is a real production defect** (filed as bug
  **polyglot-pdf-jnjj.22**, gap **P** in `docs/components/jit-schema.md`): A2
  (jnjj.9) repaired the JIT SI-BUILD path but NOT the separate RUNTIME next-field
  drip. `get_next_field_schema_for_jit` indexes `self._schema["fields"]` (which
  holds only the first field in JIT mode) instead of the manifest, so it returns
  `None` for every field past the first -- the model never receives schemas for
  fields 2..N and flies blind, looping without advancing and bloating the
  transcript past any SI savings. Verified empirically (drip returned `None`
  after firstName/middleName/lastName/preferredName) and by code path. **A5
  (jnjj.12) is now BLOCKED BY jnjj.22.**
- **Fresh baseline re-measure held** ($0.156/$0.363 vs prior wyhh $0.188/$0.323
  -- within noise; baseline stable post-A2/d24n).

Findings doc: `scripts/spikes/jnjj_g2_jit_cost_findings.md`.

## Lessons

- **A smaller system instruction is necessary but not sufficient for a cost win.**
  The manifest SI is genuinely ~43% smaller on the largest section, yet the run
  cost went UP -- because the runtime mechanism that depends on the manifest (the
  next-field drip) was broken, so the model couldn't advance and the growing
  transcript dwarfed the SI savings. Measure the END-TO-END run cost on the live
  stack, not just the rendered SI size; the SI floor and the real-dollar cost can
  point in opposite directions.
- **A measurement spike is a correctness probe.** The cost matrix's "confirmed
  fields" column (2/20 vs 17/20) was the tell that surfaced a blocking
  production defect A2's repair missed -- the SI-build path and the runtime drip
  are separate code paths sharing one root cause (`fields` has length 1 in JIT
  mode). Watch the secondary columns, not just the headline number.
- **`get_settings` is `@lru_cache`d and imported by reference -- monkeypatching
  `_config.get_settings` does NOT affect already-imported consumers.**
  `ai_context.py` does `from backend.config import get_settings`, capturing the
  lru-cached function object at import. Reassigning `_config.get_settings = lambda`
  in a measurement loop leaves `ai_context`'s reference pointing at the original,
  so a loop measuring full-SI then JIT-SI in one process leaked the mode between
  sections and produced WRONG (mode-swapped) numbers -- the source of a retracted
  ~66.9% SI-reduction figure. Correct approach: one process per cell, set the env
  flag + `get_settings.cache_clear()` at start. Fresh-eyes caught the bad figure.
- **A stale branch base masquerades as a giant diff.** This branch was cut from
  a dev that had since advanced (PRs #212/#213 merged); the pre-rebase diff
  showed other people's merged work as "deletions." Rebase onto current
  `origin/dev` before trusting a diff or a doc-freshness audit
  (worktree-branch-off-dev scar, file-write variant).
