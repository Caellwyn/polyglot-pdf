## Trigger

The 2026-07-01 goal's tier-(a) contractor permission: collect (upload a blank
AcroForm PDF), extract (run the PDF->schema authoring pass), and review forms
end to end -- WITHOUT the maintainer's machine. The approved 92qe plan had kept
extraction maintainer-local (the Vite dev server's /api/extract endpoint spawns
the local pipeline); the goal supersedes that for the author tier, so the
pipeline needed a server-side home. Two hard constraints shaped the design:
the Cloud Run image was built from a backend/-only context (scripts/ never
shipped), and the container has no `claude` CLI (the local extraction default),
so hosted extraction must run a gemini-* model.

## What shipped

**Store**: `put_pdf_bytes` (Local atomic-write with the per-write nonce; GCS
`application/pdf` + no-cache upload).

**Routes** (both AUTHOR-only -- `require_author_role`, 403 for the editor
tier; extraction spends paid model tokens and onboarding creates kits):

- `POST /api/editor/kits` -- multipart PDF upload -> new draft kit. Derives a
  URL-safe kit id from the filename (mirroring the local editor's
  `deriveFormId`), uniquifies with -2/-3... when taken, re-checks the derived
  id against the shared `_safe_kit_id` guard, size-caps the upload
  (`EXTRACTOR_MAX_PDF_MB`, default 25 MB -> 413) and magic-byte-checks
  `%PDF-` (422 for a renamed HTML page). Writes form.pdf + metadata.json
  (label, status draft).
- `POST /api/editor/kits/{id}/extract` -- streams the kit's PDF from the store
  to a temp dir, runs `scripts/authoring/extract_form.py` as a SUBPROCESS
  (the same pattern as the Vite dev endpoint) with `--model EXTRACTOR_MODEL`,
  and on a zero exit + readable output stores the draft via `put_schema`.
  Synchronous by design: Cloud Run runs `--timeout=3600` for the voice
  WebSockets, which covers a minutes-long run, and the editor shows elapsed
  progress. Guardrails: 409 when a schema already exists unless `force=true`
  (the dev endpoint's no-clobber contract); 409 with no PDF; 503 fail-fast
  when EXTRACTOR_MODEL is not gemini-* or no GEMINI_API_KEY is available
  (clear config errors instead of a doomed spawn); 504 on timeout
  (`EXTRACTOR_TIMEOUT_SEC`, default 1500s); 502 with the pipeline's last
  output line on failure -- and the temp --out path is scrubbed from the
  user-facing detail. An `asyncio.Semaphore(1)` serializes extractions per
  instance (bounded memory; the HTTP request queues). Optional multipart
  `instructions_pdf` gives parity with the local flow's help-text enrichment.

**Deploy**: the image now builds from the REPO ROOT -- `Dockerfile` moved from
backend/ to the root and copies `backend/` + `scripts/authoring/` +
`scripts/bakeoff/` (extract_form.py's import chain); a root `.gcloudignore`
keeps the Cloud Build upload to a few MB (no PDFs/node_modules/docs/.git).
`deploy-all.sh` and `backend/deploy-new.sh` submit the root context;
`backend/Dockerfile` is deleted (one image definition). `EXTRACTOR_MODEL`
defaults to `gemini-2.5-pro`: authoring is one-off per form, so quality beats
per-call cost (the runtime token economy does not apply -- the 7a9 doctrine),
and it is env-swappable without a code change.

**Frontend** (hosted mode, author role only -- the role comes from the session
probe; editor-tier users see neither control and the server refuses them
anyway): an "Add a form (PDF)" upload button in the catalogue header
(client-side PDF check, refresh + notice on success), and a per-card "Run
extraction" button on schemaless kits with an elapsed-seconds ticker (a
minutes-long dead button reads as a hang), an optional instructions-PDF picker
per kit, and the server's failure detail surfaced. One extraction at a time
client-side too.

**Tests**: +9 backend (onboard create/uniquify/label, 403 editor, 422 non-PDF,
413 oversize, extract run+store with the subprocess mocked, temp-path never in
the detail, role + no-PDF gates, no-force 409 then force replaces, failure 502
stores nothing, unconfigured 503 x2) and +5 frontend (role-gated controls,
upload flow + client-side refusal, extraction success notice + failure
detail). Full backend suite green; editor suite 356 passed / 30 files.

## Lessons

The dev-server extraction endpoint (bd 7a9.17) turned out to be the design
spec for the hosted one: the same no-clobber 409/force contract, the same
subprocess isolation, the same temp-file-then-promote discipline, the same
temp-path scrubbing in the user-facing detail. When a local capability moves
to a server, port the CONTRACT, not just the behavior -- every guard that
existed locally had a reason that still holds remotely.

A build-context change is the cheapest way to ship sibling directories into an
image when the code layering (research scripts importing each other via
sys.path) makes a package move invasive: moving the Dockerfile to the root +
explicit COPYs + .gcloudignore beat refactoring 6 modules with 7 importers.
