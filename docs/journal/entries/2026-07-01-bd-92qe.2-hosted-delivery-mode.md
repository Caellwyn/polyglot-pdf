## Trigger

Third slice of the hosted-schema-editor epic (`polyglot-pdf-92qe`, plan Bead 3).
The backend write path (bd 92qe.1, PR #279) gives contractors a token-gated
`/api/editor/*` surface over the shared form-kits store -- but the editor SPA
itself still only spoke File System Access (a local folder). This bead teaches
the editor a second delivery mode: one hosted URL a contractor opens, an access
code entered once, and the same catalogue -> open -> edit -> save ->
mark-complete loop running against the shared store instead of local disk.

## What shipped

**remoteKitStore.ts** -- the fetch-backed mirror of `formKitDirectory.ts` over
the editor routes: `listRemoteKits`, `loadRemoteSchema` (404 -> null),
`loadRemotePdfBlobUrl` (object URL for the PDF viewer), `saveRemoteSchema`
(applies the SAME `stripEditorState` the File System Access save applies, so
editor scratch state never reaches the store), `setRemoteStatus`,
`probeSession` (role), plus the access-code plumbing (`localStorage` wins over
a build-baked `VITE_EDITOR_TOKEN`; `AuthError` on any 401). `isHostedMode()`
reads `VITE_DELIVERY_MODE` at call time so tests can stub per case.

**AccessCodeGate** -- the hosted front gate: prompts once, validates via
`GET /api/editor/session` (which reports the tier -- editor vs author),
remembers the code per browser, silently re-probes for returning users, and on
a 401 clears the dead code and re-prompts. Sharing model: URL + access code;
two codes = two permission tiers; no accounts.

**RemoteCatalogue** -- the same card UI as the local catalogue (status badge,
review-% bar, version line, mark-complete / revert-to-draft) listing kits from
the API, DRAFTS INCLUDED (the contractor work list). Review % is computed
client-side per kit by fetching each schema and reusing `getCompletionStats` --
the same single definition the editor and local catalogue use, chosen over a
server-side re-implementation precisely to avoid drift; noted as a scale
caveat (N schema fetches per catalogue load, fine at current kit counts). The
server's promote-gate refusal (422 with the validation detail) is surfaced on
the card, and a 401 routes to the app's auth handler instead of a dead error
banner. Deliberately a SIBLING component of FormCatalogue: the local one is
tightly bound to the directory API (folder picker, drag-drop, host extraction),
none of which exist hosted in this bead (author-tier onboarding/extraction is
bd 92qe.3).

**App.tsx hosted branches** -- gate -> remote catalogue -> open kit (schema +
PDF blob via the routes) -> edit -> Cmd+S PUTs back with a visible `Saving...`
state (a GCS write has real latency); FS-only affordances (Save As, Reload
from file, the legacy FormSelector fallback) hidden in hosted mode; a
mid-session 401 (rotated code) drops back to the gate. Local behavior is
unchanged when the flag is unset.

**Build config** -- `.env.hosted` (committed via a gitignore negation, same
class as `.env.production`/`.env.demo`: public VITE_* values only; the file
itself warns that a real access code must never be baked into it) +
`npm run build:hosted` (`vite build --mode hosted`) + `src/vite-env.d.ts`
(Vite client types so `import.meta.env` typechecks -- the editor never used
env vars before).

**Tests** (+32: `remoteKitStore.test.ts`, `RemoteCatalogue.test.tsx`,
`App.hosted.test.tsx`): request shape (token header, base URL), AuthError on
401 from every call, endpoint contracts (404 -> null, stripEditorState on
save, promote-gate detail surfaced), gate flow (prompt, silent re-probe,
401 re-prompt with storage cleared, 503 keeps the code), open/save round trip
through App, the FS-pickers-never-called guarantee, hidden FS affordances,
progress-scan auth routing, the edits-survive-re-auth behavior lock, and the
non-hosted default rendering the local path untouched. Full editor suite
green: 344 passed / 30 files (312 baseline + 32).

Pre-PR assess: exit-criteria rubric all PASS; fresh-eyes round 1 returned
GAPS-FOUND (4), all four resolved before the PR: (1) an AuthError raised during
the catalogue's per-kit progress scan was swallowed as a "schema unreadable"
card error -- now flagged-and-routed to onAuthError (flag-and-resolve rather
than rethrow, so sibling rejections in the Promise.all are never left
unhandled); (2) the access gate cleared the STORED code on ANY probe failure --
now only a refused code (401/AuthError) is wiped, and a non-auth failure (503
surface-unconfigured, network) keeps the code and shows the real cause even on
the silent probe; (3) the baked VITE_EDITOR_TOKEN path now warns, in
.env.hosted AND the EDITOR_GUIDE maintainer note, that any baked value is
compiled in plaintext into the served bundle -- prefer the prompt; (4) the
'dirty edits survive a 401 gate round trip' asymmetry was resolved as
DELIBERATE (a code rotation must not destroy a contractor's unsaved work;
every request re-authenticates server-side), documented at handleAuthExpired
and locked by a test.

## Lessons

A delivery-mode flag is the right seam for local-vs-hosted: the schema-editing
core (viewer, field list, editor, validation, undo) is mode-agnostic, and only
the EDGES differ (where kits come from, where saves go, what the front door
looks like). Branching at those edges -- a sibling catalogue component + a save
short-circuit -- kept the diff additive; the alternative (threading a storage
abstraction through every component) would have churned the whole tree for the
same behavior.

jsdom reality check: the "non-hosted default unchanged" assertion can't look
for the local catalogue's happy-path UI, because jsdom has no File System
Access API -- the local path legitimately renders its unsupported-browser
message there. Assert the actual invariant (the hosted gate is OFF and no
session probe fired), not a UI detail the environment can't produce.
