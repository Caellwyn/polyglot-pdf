## Trigger

The `derive_sections` prototype (bd polyglot-pdf-6cfu.1) flagged a shipped
field-to-widget mapping bug in the w7 / w7-2 kits: `pdf_field_name` assignments
were shifted one widget through the treaty / name / address / birth /
id-document run. `/api/fill-pdf` therefore wrote every W-7 value one printed box
off through that region -- a user-visible mis-fill on the printed form. P1.

## What was actually wrong

The AcroForm dump + a render of page 1 pinned the true meaning of each widget.
The kit had every field in the run pointing one widget too LOW:

| field (meaning) | was | correct |
|---|---|---|
| treaty_country | f1_04 | f1_05 |
| treaty_article | f1_05 | f1_06 |
| name 1a first/mid/last | f1_06/07/08 | f1_07/08/09 |
| name 1b first/mid/last | f1_09/10/11 | f1_10/11/12 |
| mailing street / city | f1_12/13 | f1_13/14 |
| foreign street / city | f1_14/15 | f1_15/16 |
| dob / country / city of birth | f1_16/17/18 | f1_17/18/19 |
| 6a citizenship / 6b tax id / 6c visa | f1_19/20/21 | f1_20/21/22 |
| 6d issued-by / number | f1_22/23 | f1_24/25 |

The shift ORIGINATED at two real fillable widgets that no field models: **f1_04**
(the box-h "Other (see instructions)" reason free-text line) and **f1_23** (the
6d "Other" identification-document description line). The extractor mis-parked
`treaty_country` on f1_04 and `id_doc_number` on f1_23, which pushed everything
between them down by one. `date_of_entry` (f1_27) was already correct -- the run
"self-healed" there because the kit over-modeled the single exp-date box as
multiple fields, absorbing the surplus.

## Fix

Data-only change to `form-kits/w7/schema.json` and `form-kits/w7-2/schema.json`
(the single tracked source of truth; `frontend/public/form-kits/` is a gitignored
artifact regenerated by `scripts/generate-form-manifest.ts`, the
`form-kits:prepare` pre-hook on dev/build/test):

1. **Remapped `pdf_field_name` AND `pdf_position`** for every field in the run to
   its correct widget. `pdf_position` matters too -- `FieldOverlay.tsx` /
   `valuePainting.ts` paint the on-screen value overlay at those coordinates, so a
   name-only fix would have left the preview pane painting at the old (wrong)
   cell. Both were sourced from the AcroForm widget rects.
2. **Consolidated the mis-modeled id-document date fields.** The form has ONE
   free-text "Exp. date" box (f1_26), but w7 modeled it as three fields
   (`id_doc_exp_month/day/year`) and w7-2 as two (`id_exp_date` +
   `id_exp_date_yyyy`, plus a stray `date_of_entry_yyyy`). A correct mapping needs
   one field per widget, so the splits collapsed to a single `date` field each
   (w7: `id_doc_exp_date` -> f1_26; w7-2: dropped the two `_yyyy` splits). Those
   split field-ids were referenced ONLY in the kit JSON -- zero code / SI /
   frontend ripple.

## The lint-invariant collision (why this was more than a permutation)

The kits lint clean today only because the scrambled mapping is a *bijection*
(every fillable widget claimed exactly once). A semantically-correct mapping is
NOT a pure permutation: it leaves f1_04 and f1_23 (the two "Other" lines)
genuinely unclaimed. So `test_kit_unfillable_field_inventory`'s
`dump-widget-unclaimed` baseline for w7 / w7-2 moved 0 -> 2 -- updated honestly
(the two widgets ARE unmodeled now), not silenced. Modeling those two "Other"
free-text lines is filed as follow-up bead **polyglot-pdf-edzu** (which will
lower the baseline back to 0).

## Verification

- Filled each remapped field of both kits with a distinct test value and rendered
  page 1: every value now lands in its printed cell (exit criterion 1).
- New `backend/tests/test_w7_field_widget_mapping.py` pins the corrected
  field_id -> widget table, that f1_04 / f1_23 stay unmodeled, and that the
  mapping stays a bijection.
- Full backend suite green: 1015 passed, 2 skipped (exit criterion 2).

## Decisions (defended)

- **Remapped `pdf_position` alongside `pdf_field_name`** even though only the
  latter drives the PDF fill -- because the frontend overlay paints at
  `pdf_position`; leaving it stale would keep the same visual bug on the preview.
- **Consolidated the split date fields** rather than inventing widgets for them:
  the PDF has one box, the splits had no widget, and they were kit-JSON-only
  (no ripple). Mirrors the existing single `date_of_entry` field precedent.
- **Raised the unfillable baseline to 2 and filed edzu** rather than modeling the
  two "Other" lines inline: the bead's exit criterion is about *existing* fields'
  correctness, not adding new user-facing voice fields (that is scope creep --
  file, don't fold).
