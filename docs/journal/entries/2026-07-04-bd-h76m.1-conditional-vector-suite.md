## Trigger

First bead (P0.1) of the schema-v2 epic `polyglot-pdf-h76m` (plan:
`~/.claude/plans/rustling-discovering-hearth.md`, maintainer-machine-local).
The epic rewrites the
conditional-logic model (composite ConditionGroup, membership operators) and
its top-listed risk is two-evaluator drift: the voice runtime
(`frontend/src/schema-forms/utils/validation.ts shouldShowField`) and the
editor preview (`schema-editor/src/utils/conditionalVisibility.ts`) implement
the same show_if semantics twice, by hand. P0.1 pins TODAY'S behavior in a
shared vector file BEFORE any semantics change, so every later bead (P3.0
normalizeToComposite, P3.1 composite evaluators, P6.2 hack retirement) changes
semantics against a red/green contract instead of by eyeball.

## What shipped

- `shared/conditional-vectors.json` -- 65 vectors, first tenant of the root
  `shared/` dir. Covers every operator branch of both evaluators: the vq4m
  equals-as-membership hack on checkbox-group triggers, comma-string gating
  (voice path), rigd is_empty-on-array, strict-equality/type-coercion warts
  (`WART-` prefixed), and unknown-operator fallback to `!hidden`.
- Three vectors (prefix `DIVERGENT-`) pin field shapes where the two
  evaluators GENUINELY disagree today, via a per-evaluator
  `expect: {frontend, editor}` object instead of a shared boolean: the
  comma-split gate keys on `group_kind === "checkbox"` in the runtime but on
  `type === 'checkbox' && options[]` in the editor (whose FormField type has
  no group_kind), and FieldValue-wrapper unwrapping is runtime-only. Pinning
  the divergence honestly beats excluding those shapes -- they are the
  measured starting line for the P3.1 convergence work.
- Two thin vitest runners over the SAME file (direct JSON import -- vite
  resolves it natively; `fs.readFileSync(import.meta.url)` broke under jsdom,

  `frontend/src/schema-forms/utils/validation.vectors.test.ts` and
  `schema-editor/src/utils/conditionalVisibility.vectors.test.ts`. Both match
  the default vitest include glob, so both existing CI jobs pick them up with
  zero config.
- Mutation proof (exit criterion 2): a one-line `is_empty` flip in the
  frontend evaluator -> 2 vector tests red; a one-line equals-membership flip
  in the editor evaluator -> 8 red. Both reverted; outputs in the PR body.

## Lessons

- Under vitest+jsdom, `new URL(..., import.meta.url)` is NOT a file URL, so
  `fileURLToPath` throws; a plain JSON import is the robust way for a test to
  read a repo-root fixture (both tsconfigs already had `resolveJsonModule`).
- The two evaluators agree on every operator branch but disagree on GROUP
  DETECTION -- the comma-split gate is keyed on different field properties.
  That means the same stored schema + same values can render a field visible
  in the editor preview and hidden in the voice app (and vice versa) for
  checkbox groups that set only one of group_kind/options. Known, now pinned;
  P3.1 must converge the gates.
