## Trigger

P3.1 of the schema-v2 epic `polyglot-pdf-h76m` (plan:
`~/.claude/plans/rustling-discovering-hearth.md`, maintainer-machine-local) --

rides the P0.1 vector contract and the P3.0 normalizeToComposite helper.

## What shipped

- Frontend `validation.ts`: shouldShowField = normalizeToComposite ->
  unknown-operator fallback (!hidden) -> composite evaluation
  (all_of every / any_of some / none_of none) over an extracted atomic leaf
  evaluator whose v0 semantics are byte-identical (vector-pinned); the vq4m
  equals-membership hack stays quarantined in the leaf until P6.2. New
  operators includes/not_includes (selected-set membership with comma-string
  and bare-scalar tolerance). New `isFieldRequired` (static
  validation.required OR satisfied require_if; fail-open = NOT required).
- Editor `conditionalVisibility.ts`: mirrored composite layer + membership
  operators + isFieldRequired (keyed on the editor's plain `required` bool).
- Voice locked-field path (`conditionalFieldCheck.ts`): checkFieldAccess and
  evaluateFieldAvailability explain composite gates -- required_fields lists
  EVERY atom's trigger, the message keeps the legacy one-atom wording and
  counts the extra conditions; getDependencyChain walks all atoms and gained
  a visited-set cycle guard (the old recursion never terminated on A<->B).
- `fieldGrouping.ts` merge/un-merge: conditions rewritten atom-wise for both
  dialects (shape-preserving -- legacy stays legacy, composite stays
  composite); require_if rewritten + restored symmetrically; fixed a latent
  un-merge clobber where restoring a record that only rewrote controls would
  overwrite an untouched show_if with undefined.
- Editor `validation.ts` reference checks walk all atoms of show_if AND
  require_if. `FieldEditor` renders a composite show_if as a read-only
  summary (the legacy single-condition editor cannot corrupt it) until the
  P4.1 builder ships.
- Types in both islands: CompositeConditionalDisplay / FieldCondition,
  require_if on FormField, includes/not_includes in ConditionalOperator.
- Vector suite v2: 23-case `vectorsV2` (composite structure, the W-7
  any_of-includes pattern, unknown-op-in-composite fallback,
  show_if-overrides-hidden) + 9-case `require` section, run by BOTH runners
  (frontend 191, editor 192 incl. byte-identity); v0 vectors untouched and
  green (exit criterion 2).
- Exit criterion 3 (voice locked-field path): 5 new conditionalFieldCheck
  tests -- composite blocks/opens access, none_of trip, locked reason
  wording, dependency walk + cycle survival.
- Fresh-eyes triage: (recorded at closeout -- see PR.)

## Lessons

- Widening a shared wire type (`show_if`) and letting tsc enumerate the
  breakage sites is a reliable consumer-inventory cross-check: it caught the
  editor FieldEditor UI and test-local evaluators the grep-based inventory
  had already flagged, and nothing more -- the two lists agreeing is the
  signal the inventory was complete.
- vitest's default fork pool flakes under parallel load on this Windows
  environment (one unrelated App.hosted test failed in a full run, passed in
  isolation and on a clean tree, passed full-suite on rerun);
  `--pool=threads` is the stable local invocation. CI (Linux) is unaffected.
