## Trigger

Sprint-6 editor-authoring epic (s4dp), bead B4. Forms must be VISIBLY VERSIONED --
an outdated revision is rejected at submission -- but `extract_form.py` hardcoded
`form_metadata.version = "draft"` and never read the real version, even though the
backend `FormMetadata` model already had version/edition/OMB/expiration fields.
Build B4 first so B3 (help text) layers on the same metadata-extraction pattern.
The maintainer added two constraints: handle forms that DO and DON'T carry version
info, and attach a confidence heuristic.

## What shipped

A deterministic (no-LLM) version-metadata extractor + editor display/edit.

**Empirical grounding:** probed all four repo PDFs first. Version info comes in
three distinct shapes -- USCIS `Edition MM/DD/YY` (I-90, I-589), IRS
`(Rev. Month Year)` (W-7), IRS year-only `2025` (1040) -- with per-field absence
(W-7/1040 have no expiration; 1040 no edition date). The old prior_extractor regex
was I-form-only and would have missed W-7 and 1040.

- **`scripts/authoring/extract_form.py`**: new pure `extract_version_metadata(
  page1_text, title)` (+ a `_extract_version_metadata_from_doc` PyMuPDF wrapper).
  Matches in descending specificity -- generalized `Form <id>` (any USCIS/IRS
  number), `Edition MM/DD/YY`, `Rev. Month Year`, bare-year fallback; OMB
  (specific then loose); expiration (no fallback -- a wrong expiry is worse than
  none); agency. Emits a single `version_confidence`: HIGH (0.9) for a specific
  Edition/Rev match, LOW (0.4) for a generic year/loose-OMB fallback, 0.0 when
  nothing is recoverable. A version-less form degrades to the sentinel "unknown"
  (never "draft"/blank/crash). Wired into `extract()` BEFORE `_normalize_for_schema`
  so real values win; the normalize default changed "draft" -> "unknown".
- **`backend/models/form_models.py`**: `FormMetadata.version_confidence:
  Optional[float]` (0-1), mirroring `ExtractionInfo.extraction_confidence`.
- **`schema-editor/src/types/schema.ts`**: `FormMetadata` gained omb_number /
  expiration_date / agency / version_confidence (the editor type was missing
  them; keeps a load -> edit -> save round-trip from stripping them).
- **`formKitDirectory.ts`**: `versionInfoFromSchema` + a per-kit `version` summary
  on `KitProgress` (label + lowConfidence).
- **`FormCatalogue.tsx`**: each kit card shows "Version: <edition|version>";
  "unknown" is explicit, low-confidence appends "(verify)".
- **`FieldEditor.tsx` + `App.tsx`**: an editable Form-metadata panel (shown when
  no field is selected) for version/edition/OMB/expiration, committing single-key
  patches via a new `handleUpdateMetadata`. Satisfies "make the metadata editable"
  and the version-less "still editable" path.

**Exit-criteria scorecard:** crit 1 (extraction populates real version metadata;
W-7 -> version "December 2024" + omb 1545-0074; I-90 -> edition 01/20/25 +
expiration 02/28/2027 + omb 1615-0082; shown on the form card) -- PASS, via the
real-PDF tests + the FormCatalogue/FieldEditor display. Implicit crit (version-less
-> "unknown", still editable) -- PASS, via the synthetic version-less test + the
metadata-edit test.

**Fresh-eyes assess (Sonnet, pre-PR):** NO-GAPS (one docstring nit fixed inline).

**Codex review (PR #263) found 4 real P1s -- all fixed:**
1. Clearing the Version input sent `{version: undefined}`; `JSON.stringify` drops
   undefined keys, so a save would strip the REQUIRED `form_metadata.version` and
   fail backend validation. Fixed: the metadata setter degrades `version` to the
   "unknown" sentinel on clear (optional fields still clear to undefined).
2. The bare-year version fallback was UNSCOPED -- `Expires 02/28/2027` on a
   version-less form became version "2027", making it look versioned and
   misleading the outdated-revision check (the fresh-eyes pass flagged this risk;
   Codex correctly escalated it to a blocker). Fixed: a year is only a version
   when in the TITLE or adjacent to "Form <id>" on page 1, never an arbitrary
   page date.
3. The catalogue card's version came only from the disk scan, so an in-session
   metadata edit+save left a stale version on the card. Fixed: threaded a live
   version summary through liveProgress -> editedProgress -> the card (prefers the
   live value over the scan).
4. The metadata editor showed only when no field was selected, but nothing could
   clear the selection back to null -- so after clicking any field it was
   unreachable. Fixed: a "Form metadata" button in the Field-Properties header
   clears the selection back to the metadata panel.

Tests added for each: version-clear -> "unknown"; expiration-year-not-version +
year-needs-form-context; the metadata-reachability flow (select field -> "Form
metadata" -> panel). Editor 264 green; Python 25 green.

**Codex round 2 found 3 follow-on P1s (consequences of the r1 fixes) -- all fixed:**
1. A manual version edit left the stale auto `version_confidence` (0/0.4), so the
   "(verify)" hint stuck with no way to clear it. Fixed: a non-empty manual
   version edit clears version_confidence (the human value is authoritative); a
   cleared version stays low via the "unknown" branch.
2. The r1 year-scoping fixed the page-text path but the TITLE search was still an
   unscoped `\b20\d{2}\b` -- a non-version year in the title (e.g. an expiration)
   could still be promoted. Fixed: the title year must be adjacent to "Form <id>"
   too ("2025 Form 1040" / "Form 1040 2025").
3. The unconditional `form_metadata.update(version_meta)` let the "unknown"
   no-match sentinel OVERWRITE a real version the LLM pass had already placed for
   an unsupported format. Fixed: the "unknown" sentinel no longer overwrites an
   existing non-unknown version (deterministic recovery wins, absence does not).

Tests for each. Editor 265 green; Python 25 green. Reached the 2-round Codex
ceiling here (both rounds found real, distinct, converging bugs) -- escalated to
the maintainer for the merge call rather than auto-looping a 3rd round.

**Decisions (mine):**
- **One version-scoped confidence float**, not per-field -- per the plan; per-field
  is overkill and the editor surfaces a single "is this version trustworthy" hint.
- **No fuzzy fallback for expiration** -- a wrong expiry date is worse than a blank
  one; OMB and version get fallbacks, expiration does not.
- **Kept the lossy whitelist nowhere here** -- N/A; this is metadata, not the
  grouping reversal.

**Live verification (Chrome, FS-Access-stub approach from s4dp.1):** loaded the
i-90 gold schema -> the Form-metadata panel rendered with version "v9_conformant" +
edition "01/20/25"; edited OMB -> Save -> the saved JSON carried
`omb_number: "1615-0082"` with edition/version preserved. The catalogue-CARD
version line is covered by component/unit tests (the card path needs the native
directory picker, which the headless stub can't drive).

## Lessons

When porting a "proven" extractor, re-probe the actual target set: the
prior_extractor metadata regex was validated only on I-forms and silently missed
the IRS `(Rev. Month Year)` and year-only formats. A 10-minute page-1-text probe
across all available PDFs mapped the real format variety before any code, and
turned "port the regex" into "generalize the regex + add a confidence tier."
