## Trigger

The jnjj epic's B-pillar contradiction validator (and later A-pillar secretary)
both need a cheap text-generation path separate from the expensive Live model.
This bead (B2) lays the shared port + adapter foundation: `ITextAI` (abstract port)
and `TextAIGemini` (Gemini implementation), wired into `backend/dependencies.py`
via `get_text_ai()`. The sibling beads build the validator service (B3) and the
secretary prompt + catalog logic on top.

## What shipped

**New files:**
- `backend/ports/text_ai_port.py` -- `ITextAI` ABC with two abstract methods:
  `validate(payload)` (the B-pillar contradiction checker) and `ask(query, context)`
  (stub for the A-pillar secretary, raises `NotImplementedError` until that bead
  lands). Port is frozen now so downstream beads can build against it without a
  port-change PR.
- `backend/adapters/text_ai_gemini.py` -- `TextAIGemini` implements `ITextAI`.
  Three-way client construction mirrors `LiveAIGemini` (Vertex ADC / AI Studio
  api_key / bare test fallback). Calls `client.aio.models.generate_content` (NOT
  the bidi Live path). `validate()` uses `response_mime_type="application/json"`,
  parses the verdict, and is fully fail-open (timeout / parse error / network error
  all return `{"conflicts": []}`). `_generate()` internal helper accepts
  `stable_prefix + fresh_tail` as separate parameters -- the structural split that
  makes the implicit->explicit caching upgrade a contained change inside `_generate`
  with no port or caller changes.
- `backend/tests/unit/test_text_ai_gemini.py` -- 8 unit tests with a stubbed
  `genai.Client`: happy path (no conflicts + with conflicts), cache-hit logging,
  fail-open on exception, fail-open on bad JSON, fail-open when no client,
  `ask()` raises `NotImplementedError`, and `get_text_ai()` wiring.

**Modified files:**
- `backend/dependencies.py` -- added `get_text_ai()` alongside `get_live_ai()`.
  Feeds `settings.MODEL_LABELING` (existing knob, default `gemini-2.5-flash`;
  pin to `gemini-2.5-flash-lite` in deploy env) into `TextAIGemini`. Reuse of
  `MODEL_LABELING` was the F3 contract decision in `validation-delegation.md`.
- `docs/standards/ai-models.md` -- `MODEL_LABELING` is now live, not orphaned;

- `docs/standards/validation-delegation.md` -- rewrote "Current state" from

**Caching strategy (implicit, MVP):**
The `stable_prefix` (secretary SI + field catalog, estimated 2.7-5.9k tokens)
is passed as a separate parameter from `fresh_tail` (current values + query).
Gemini's implicit cache fires when the same leading token sequence recurs across
requests. `_log_usage` logs `cached_content_token_count` as `cache_hit=(cached_tokens > 0)`
on every call -- this is the "confirm it fires" observability requirement. Explicit
per-form caching (`client.caches.create()`) is the scale-production upgrade path
deferred to after Gate 2 (jnjj.27) establishes the flash-lite token minimum.

## Lessons

**`structlog.testing.capture_logs()` beats `capfd` for structured-log assertions in
a shared test suite.** When another fixture reconfigures `structlog`'s global
processors, the `ConsoleRenderer` that normally writes to stdout may not be active,
so `capfd.readouterr().out` returns empty even though the log was emitted. The
`capture_logs()` context manager intercepts at the processor level regardless of
the renderer -- use it for any test that asserts on a specific log event or key.
(Applied here in `test_validate_cache_hit_logged`.)
