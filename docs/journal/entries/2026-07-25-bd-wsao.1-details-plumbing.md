# help.details plumbing: verbatim booklet guidance reaches the AI (bd wsao.1)

## What shipped

Step 1 of the sprint-16 instructions-enrichment epic
(`docs/sprint_16_instructions-enrichment_plan.md`): the schema + runtime
plumbing for the second guidance channel, ahead of any enrichment engine.

- **Schema:** `FieldHelp.details` (verbatim per-field booklet excerpts) and
  `FormMetadata.details` / `FormMetadata.booklet_text` (form-level guidance +
  the whole-booklet secretary floor) -- Pydantic + all three TS mirrors
  (frontend `schema.ts`, schema-editor `types/schema.ts`,
  `backend/schemas/form_schema_types.ts`).
- **Guidance path (inline v1 delivery):** `get_field_guidance` carries
  `details`; `render_field_guidance` appends an `Official reference text:`
  segment for the CURRENT field. No-details renders are byte-identical.
- **Spoken ask-hint:** unchanged by construction -- `formatNextFieldHint`
  reads only `help.instructions`; a test now PINS that details never leak
  into the spoken channel.
- **Secretary catalog:** field entries render an indented `details: |` block;
  the static catalog ends with `=== FORM-LEVEL GUIDANCE ===` and
  `=== OFFICIAL FORM INSTRUCTIONS (verbatim reference) ===` sections (the
  floor). Appended at the END so the cacheable prefix of a no-reference
  schema is byte-identical (implicit-cache stability preserved).
- **Static SI:** one `DEEP QUESTIONS:` line -- ground requirement answers in
  the reference text; never invent legal/document requirements; ask the
  secretary when no reference text covers the question. SI stays fully
  static.
- **Editor:** a Details textarea in FieldEditor's Help & Guidance section.
- **Guard:** `instructions-not-rendered.test.tsx` extended -- details must
  never render on-screen, same contract as instructions (bd 0x10.2).

## Transport decision (exit criterion 3)

Details ride the CLIENT path (schema.json -> `full_schema` handshake ->
backend), not a server-side kit join. Measured: i-90 compact schema 657 KB
already ships via `full_schema` today (bd p68s); w7 is 124 KB; the w7 booklet
text is 83 KB (~20.5k tokens) -- worst-case w7 payload ~250 KB, well under the
incumbent i-90 payload. Server-side join was rejected: it forks source of
truth with the editor, breaks editor-draft sessions the backend kit store
never sees, and adds a kit dependency to `/ws/fill`. Full numbers on the bead
comment (polyglot-pdf-wsao.1).
