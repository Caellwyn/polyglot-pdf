## Trigger

Bead polyglot-pdf-uov.7 (T1.4, under the spec-driven test epic uov). Two test
files -- `backend/tests/unit/test_form_state.py` and
`backend/tests/contract/test_tool_contracts.py` -- were flagged at epic-scoping
time as 0-line stubs that "read as coverage but assert nothing." The bead's
charge: implement real spec-tests (likely folded into T2.1 / T3.3) or delete.

## What shipped

On inspection only ONE of the two named files was still a stub:

- `test_tool_contracts.py` is **no longer empty** -- epic wpw (WS-A, bd
  polyglot-pdf-8k8; PRs #126/#133) filled it with a real 280-line tool-call
  SEQUENCE contract (update_form_fields -> confirm_field ordering, gated as
  `@pytest.mark.external`). Nothing to do there.
- `test_form_state.py` remained 0 lines.

Resolved `test_form_state.py` by **implementing, not deleting**. The choice of
WHAT to spec was the real decision: the obvious "form state" angles were already
covered elsewhere, so a naive fill would have duplicated existing tests. Mapping
the existing coverage:

- persistence-ABSENCE (no field value survives a reconnect) -> already owned by
  `test_stateless_reconnect_isolation.py` (T2.1 / uov.8).
- the async request/response plumbing (`request_form_state` /
  `handle_form_state_response`) -> already owned by `test_request_coordinator.py`.

The genuine gap was `FormFillingService.update_form_state()` -- the inbound
web-session acknowledgment boundary -- which had **zero** coverage despite real
branching logic. The new file specs its documented contract: validate each
field_id against the loaded schema, silently drop unknown / non-dict / id-less
entries, accept the id under either the `field_id` or `id` key, return
`{"applied_fields": [...]}` in input order, and -- the load-bearing invariant --
never cache the PII-shaped values (CLAUDE.md scar #4: stateless backend, client
owns all state). 8 tests, all green; the full backend unit suite stays green
(207 passed locally; closeout prep saw 311 passed across the whole suite).

**No bug bead filed:** `update_form_state` behaves exactly as its docstring
documents -- deriving the spec surfaced no defect (the spec-driven-test epic
files a bug bead only when the code diverges from reasonable/documented
behavior).

The bead had no `## Exit criteria` section (a creation-time-norm slip), so a
retrospective rubric was written at claim time and scored at closeout (both PASS;
see the PR body scorecard).

**Pre-PR assess:** rubric scored 2/2 PASS; fresh-eyes adversarial loop run to

## Lessons

When a "fill the empty stub" bead names a concept that is already partly tested,
the duplication check comes first: enumerate which sibling test files already own
each facet of the concept, then aim the new file at the one untested method with
real branching. Here that turned "test form state" (vague, would have duplicated
two files) into "spec `update_form_state`'s acknowledgment contract" (a real
gap). This is a specific instance of the existing "verify claims against code"
scar -- the stub's filename ("form_state") did not by itself say what was
uncovered.
