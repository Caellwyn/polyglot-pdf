# Secretary build: ask_secretary tool + agent (backend half)

## Trigger

Epic `polyglot-pdf-jnjj` (SI reduction via task delegation) needs the secretary
to exist as a running feature, not just offline research probes. The feasibility
gates had passed -- Gate 1 RECALL (jnjj.26: flash-lite reliably maps prose->field
on the real I-90) and Gate 2 LATENCY (jnjj.27: ~1s blocking lookup) -- and
`TextAIGemini.ask()` was a `NotImplementedError` stub. This PR is the bridge from
"proven in probes" to "runs in a live session," for the BACKEND half of jnjj.45.

It was planned first: a short /plan-epic (sprint 7,
`docs/sprint_7_secretary-build_plan.md`) scoped the feature, surfaced the one
genuine wire-contract decision to the maintainer (full schema at handshake, vs.
client renders the catalog per ask), and MECE-decomposed it into four children.
This PR closes the three backend children; the fourth (jnjj.45d, the frontend /
wire half) is a separate PR.

## What shipped

Three backend beads, bundled into one PR (each too small for its own full cycle):

- **jnjj.45a (polyglot-pdf-69mv)** -- promoted the validated context renderers from
  `backend/scripts/secretary_context.py` (research) to a production module
  `backend/services/secretary_context.py`. The scripts file became a thin
  re-export shim that keeps the Gate-1/2 probes working with byte-identical
  output (proven: the shim re-exports the SAME function objects; rendered catalog
  + tail bytes are identical to the pre-move version).
- **jnjj.45b (polyglot-pdf-1fhr)** -- implemented `TextAIGemini.ask()` on the
  existing `_generate(stable_prefix, fresh_tail)`. The request is built so
  Gemini's implicit cache (~1/10 rate) fires: a BYTE-STABLE
  `[SECRETARY_SI + render_static_catalog(schema)]` prefix (never mutated within a
  session) + an APPEND-ONLY `[render_values_tail(...) + the prose query]` tail.
  Returns the model's `answer` prose; fail-open `""` on any error so the principal
  asks the user directly. PII-safe logging (ids/counts/lengths only).
- **jnjj.45c (polyglot-pdf-ugrf)** -- wired the `ask_secretary` tool end to end:
  declaration in `config.py` TOOL_DECLARATIONS (single prose `query` param),
  dispatch in `callback_handler.on_tool_call` -> `_handle_ask_secretary_tool`,
  `FormFillingService.handle_ask_secretary` (assembles the context from the cached
  schema + a fresh client form-state round-trip, runs the BLOCKING `ask()` under
  `asyncio.wait_for(SECRETARY_TIMEOUT_S)` with fail-open), and `text_ai` injection
  via `dependencies.py`. Added the `SECRETARY_TIMEOUT_S` env knob (default 8s). The
  timeout here is the INTERIM tail-latency stopgap; the graceful "please hold"
  filler is jnjj.43.

**Key design facts (maintainer-decided 2026-06-27):** (1) the catalog handoff is
"full schema at handshake" -- the backend caches the whole-form schema in-session
and renders the cacheable catalog itself; (2) the secretary is the TEXT model
(`generate_content`), so every `ask()` resends the full SI + context (no
server-side memory) and implicit caching requires the byte-stable prefix +
append-only tail; (3) ship the validated renderers AS-IS -- the catalog's detail
(help text, options) is what Gate 1 proved makes recall work, and because the
catalog is cached, trimming it saves the first call only. Trimming is a deferred,
evidence-driven follow-up.

**Tests:** new `ask()` tests (returns prose; byte-identical-prefix across
value-changing calls; no-PII-in-logs; fail-open on error / bad-json / no-schema /
no-client), new `handle_ask_secretary` tests (happy path; timeout fail-open;
error fail-open; shown-map derivation), new `ask_secretary` routing tests in
`test_callback_handler.py`, and the tool-contract set updated for the 6th tool
(a deliberate-review gate that correctly caught the new tool). Full backend suite
green: 455 passed, 2 skipped.

**Pre-PR assess (Step 5.5):** rubric scorecard all 6 criteria PASS (see PR body);
fresh-eyes (Sonnet, 1 round) returned NO-GAPS on the rubric. It raised 2
non-gap robustness findings, both adopted inline: (1) the `SECRETARY_TIMEOUT_S`
comment + handler docstring implied it caps the whole blocking wait, but it caps
only the model call -- corrected to note the +~5s form-state round-trip (worst-case
~timeout+5s); (2) `test_ask_logs_no_pii` could pass vacuously if the logger patch
failed to capture calls -- added an `assert logged` guard (verified non-vacuous).
Finding 3 (a schema-drift note: a field present in sections[] but absent from
fields[] is silently skipped by both renderers) was left as-is: that is correct,
intentional current behavior (the `if field is None: continue` guard), not a gap.
No out-of-scope beads filed.

**Out-of-scope / deferred:** none filed -- the remaining work (jnjj.45d client
catalog + shown; jnjj.43 graceful filler) was already planned as its own bead.
