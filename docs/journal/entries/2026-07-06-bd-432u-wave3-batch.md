## What shipped (per bead)

- **432u** (schema-editor/src/components/FieldEditor.tsx + utils/fieldGrouping.ts
  + App.tsx): renaming a choice-option's LABEL re-mints its slug on every
  keystroke, which previously silently orphaned any dependent field's
  show_if/require_if that referenced the old slug (the inverse of the delete
  guard, which BLOCKS deleting a referenced option). Fix = the REWRITE
  resolution: a new `retargetOptionValueReferences` util rewrites every
  dependent condition (legacy single-atom AND composite all_of/any_of/none_of)
  from (triggerFieldId, oldSlug) to newSlug, and the label onChange commits the
  renamed field + retargeted dependents in ONE atomic `onUpdateFields` call.
  BLOCK-on-reference was rejected because the per-keystroke commit would make a
  referenced option permanently un-renameable. The subagent traced
  `useSchemaHistory.commit` and found two sequential commits in one handler do
  NOT merge (the second's `present` replaces the first), so a naive two-call
  approach would have dropped the rename -- hence the single-commit build.
  New `onUpdateFields` prop mirrors the existing multi-field commit precedent
  (`handleMoveOption`/`handleMergeFields`) and is optional (absent -> old
  single-field path). 7 new tests.
- **bhem** (backend/services/form_filling_service.py): after a Level-3 farewell +
  restart_gemini_session, the initiating message used the NORMAL (greeting)
  template because `_is_resume_session` was False (set at the original fresh
  connect), so Gemini re-greeted instead of resuming silently. Fix = an explicit
  `force_resume` parameter on send_initiating_message (option b), chosen over
  temporarily mutating `_is_resume_session` (option a) because that flag has a
  SECOND consumer (build_form_context_message -> ai_context.build_form_context's
  is_reconnect SI branch) -- a localized parameter is side-effect-free and needs
  no try/finally. restart_gemini_session passes force_resume=True; other call
  sites keep the default (False, still driven by _is_resume_session). Tests:
  restart uses RESUME even after a fresh original connect; fresh non-restart
  still greets.
- **de8b** (deploy-all.sh): corrected the BACKEND_EXTRA_ENV comment that claimed
  "the demo runs on AI Studio: VERTEXAI=false" -- the demo actually sets
  VERTEXAI=true (Vertex ADC). Comment-only. (Filed by fresh-eyes during the 4b30
  wave-1 work.)

## Decisions (defended)

- **432u: rewrite, not block** -- forced by the per-keystroke commit (a block
  would freeze a referenced option's label); documented in code + this entry.
- **432u: new optional `onUpdateFields` prop** -- a small, obvious multi-field
  commit hook mirroring existing App.tsx precedent, in direct service of the
  bead; not a new cross-code contract, so decided (not escalated).
- **bhem: explicit param (b), not flag-mutation (a)** -- because
  `_is_resume_session` has a second consumer; the localized parameter is the
  lower-risk change.
- **Filed fgdo rather than fixing the flaky test here** -- out of this batch's
  scope (a test-infra timing bug in an untouched test), so filed per the
  scope-creep rule.
