## Trigger

T0.0 of the spec-driven test-and-codebase-health epic (`polyglot-pdf-uov`). The
maintainer asked to investigate under-testing and reframed it: the codebase is
unhealthy, so tests should encode reasonable/documented behavior, not current
output, and a failing spec-test is a finding. Every child bead in the epic is
gated on this one because coverage tooling (T0.1), CI (T0.2), and the spec-tests
(T1-T3) are all meaningless on a suite that does not collect. The investigation
had flagged "5 backend collection errors + 1 real failure + frontend not
runnable"; T0.0 turns that into an honest green-or-xfail baseline.

## What shipped

The "collection errors" were a **pytest config-discovery bug**, not broken tests.
The only config lived at `backend/pytest.ini`, which a bare `pytest` from the repo
root never discovers -- so `testpaths`/`pythonpath`/markers were ignored and pytest
scanned the whole tree, choking on dev probe scripts (`scripts/test_*.py`, all
`__main__`/`asyncio.run`) and orphaned `__main__` modules (`backend/test_*.py`,
one of which has a `test_manifest_generation(schema)` fn pytest can't supply an
arg for). `closeout_prep` never hit this because it runs `pytest <abs
backend/tests>` (explicitly scoped).

Changes:
- **Single root `pytest.ini`** (deleted `backend/pytest.ini`): `testpaths =
  [backend/tests, tests]`, `pythonpath = .`, `addopts = --import-mode=importlib`
  (removes the duplicate-basename "import file mismatch" structurally -- e.g.
  `test_section_switching.py` under both `scripts/` and `backend/tests/unit/` --
  without needing `__init__.py`), `norecursedirs` for `scripts`/`node_modules`/etc,
  and the `external` marker. A bare `pytest` now collects 607 deterministically and
  pulls in BOTH real suites: the backend suite AND the top-level `tests/`
  harness-tooling suite (~380 tests for closeout/bd_safe/next_bead/doc-freshness),
  which was previously in no scoped command at all.
- **Native-VAD test corrected (stale test, not a bug).**
  `test_activity_signals_suppressed_in_native_vad` asserted that BOTH
  `activity_start`/`activity_end` are fully suppressed in native VAD mode. But
  `send_activity_end` intentionally sends `audio_stream_end=True` in native mode
  (deliberate fix, bd `polyglot-pdf-6vo` / PR #119: PTT-as-a-gate withholds audio
  after release, so without it Gemini's VAD never closes the turn and the session
  goes silent; `audio_stream_end` is the documented signal compatible with
  automatic VAD, NOT the conflicting `activity_end`). The code is right; the test
  lagged the `6vo` change. Corrected the assertion to the current spec
  (`activity_start` suppressed; exactly one `send_realtime_input` carrying
  `audio_stream_end`).
- **Frontend made runnable for a bare `vitest run`.** `frontend/vite.config.ts`
  had no `test` block, so `vitest run` (CI, no CLI flag) used the default node
  environment and `sessionStorage` was undefined -- 7 `navigation-confirmation`
  failures. The `npm test` script masked it with `--environment jsdom`. Added
  `test.environment = 'jsdom'` to the config. (`schema-editor` already had this;
  113/113 green untouched.)
- **Honest green-with-skips, not silent red.** The 3 pre-existing DisclaimerModal
  body-copy regex failures (= bd `polyglot-pdf-pwt`) are marked `it.skip` linked to
  T1.3 (`uov.6`), which owns deriving the disclaimer spec and deciding whether the
  modal copy or the assertion is wrong (and removing the skip). T1.3 and the epic
  bead were updated to record this.

Triage decisions (red-test loop, per-case): native-VAD failure = quick/obvious
stale-test fix, done inline (code provably correct via the `6vo` comment + a
passing companion test). DisclaimerModal failures = owned by a later bead, skipped
+ linked rather than fixed here (T0.0 is not the spec-audit bead). No bug beads
filed -- nothing in this surface turned out to be a live defect.

Result: backend `pytest -m "not external"` 604 passed / 2 skipped / 0 fail;
frontend `vitest run` 125 passed / 3 skipped; schema-editor 113 passed.
`npm ci` is environment setup, not a committed change.

No Codex/Copilot review this round (both usage-capped) -- substituted a second
fresh-eyes pass per the maintainer's instruction.

## Lessons

- **A pytest config one directory down is invisible to a root `pytest`.** Put the
  canonical config at the repo root (or pass `-c`) or CI/devs running a bare
  `pytest` silently scan probe scripts and error on collection while a scoped
  closeout run stays green. Captured in `docs/standards/testing.md`.
- **A green vitest only proves what the env supports.** No `test` block in the vite
  config means `vitest run` uses node, where `sessionStorage`/DOM are undefined;
  the `--environment jsdom` flag on the npm script hides it from anyone who runs
  the bare binary (CI). Set the environment in config, not on the CLI.
- **"Pre-existing failure" is a real triage category.** The native-VAD red was a
  test that lagged a deliberate code change; the fix is to update the assertion to
  the current spec, never to delete-to-green.
