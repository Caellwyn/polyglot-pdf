## Trigger

Sprint 20 stage 4 (epic `polyglot-pdf-s1iex`, plan
`docs/sprint_20_sol-intro-tts_plan.md`). The backend can synthesize Sol's
intro clip (bd `s1iex.3`) and the avatar animates for clips (bd `s1iex.4`);
this is the client that actually fetches and plays it, and the modal rewiring
that makes the words on screen and the words spoken one source.

## What shipped

- **`introPlayer.ts`** -- fetch `POST /api/tts/intro`, play, cancel. Reuses
  the spell-back player's STRUCTURE (monotonic `generation`, `cancelledUpTo`
  poison marks, injectable seams) but deliberately NOT its timing model: that
  80s budget exists because a Gemini tool round-trip waits on the far side,
  and nothing waits on this clip. Bounds here are a 45s fetch timeout (a cold
  synthesis measured ~20s, bd `s1iex.3`) and a playback watchdog sized past
  the longest measured language (German 120.2s).
- **A per-(language, form) blob cache** so "Listen Again" replays instantly
  with no network round trip -- provably the same audio the user just heard --
  and so the tap-to-play retry after a refused autoplay is instant rather than
  another 20-second wait.
- **`introScript.ts` + a byte-identical mirror of the backend store**, pinned
  by `introScript.mirror.test.ts`. Vite cannot cleanly import out of
  `backend/`, so the plan's fallback (duplicate + byte-equality test) is what
  shipped -- the same mirror idiom as `MAX_SPELLBACK_CHARS` and the agree-label
  table.
- **The modal renders those canonical paragraphs** when passed, with the
  language's own agree label interpolated from the same table the backend
  speaks. Omitting the prop keeps today's `p1/p2/p3` verbatim -- which is what
  the flag being off must look like, and is proven by the 105 pre-existing
  modal tests passing UNCHANGED.
- **Both overlays wired** (hand-duplicated; one-sided edits are the standing
  hazard): one player per mount, ONE effect that starts the clip whenever the
  modal becomes visible -- covering all three sites that open it -- and Agree
  calling `stop()` FIRST, before any await.
- **`isIntroClipEnabled()`**, the frontend half of the two-flag design. It
  cannot be a backend flag delivered in `session_ready`, because it decides
  whether the client connects before Agree at all.
- 24 new tests; seven assertion families mutation-verified. Full frontend suite
  96 files / 1496 tests green; `tsc --noEmit` clean.

## Lessons

- **Check whether the work is already done before doing it.** One of this
  bead's three exit criteria -- "delete the mid-modal language switch" -- was
  already satisfied by bd `87a9`, which had removed `handleLanguageChange`
  from both overlays and left a comment explaining why. Verified rather than
  assumed: the language picker and the disclaimer are gated on SEPARATE state
  flags and the picker only mounts before the disclaimer opens, so no switch
  path is reachable and nothing is left visible-but-inert (the plan's worse
  case). A plan written weeks earlier describes the code as it was THEN.
- **Do not add English state strings to an 18-language modal.** "Loading..."
  and "Tap to play" would have been 18 untranslated phrases in the one surface
  whose entire purpose is speaking the user's language. The states ride on
  `disabled` / `aria-busy` / CSS instead, with a reduced-motion-safe variant.
  Cheaper, accessible, and it does not create a translation debt the next
  language addition inherits.
- **A stray control character can pass every gate and still defeat review.**
  A literal NUL in the cacheKey template rendered as a space, typechecked
  fine, and survived 16 tests plus a five-mutation pass -- because no test
  read the bytes. Its cost was that git classified the whole file as BINARY,
  so `git diff` printed nothing for a 274-line new file, locally and in the
  PR view. Found by fresh-eyes reading the raw bytes. Now pinned by a
  control-character scan (mutation-verified) and recorded in
  `docs/standards/testing.md`.
- **Guard the CHOKE POINT, and pin the whole set.** The cross-surface review
  found the blocking bug in this bead: I guarded ONE of two `readDisclaimer`
  call sites per overlay, so with the flag ON the model still read the legacy
  disclaimer OVER Sol's clip -- two voices, two texts. The fix was not a
  second guard at the second site but a guard at the `pendingDisclaimerRead`
  effect, the one choke point all three `setPendingDisclaimerRead(true)`
  paths flow through, plus a SET test asserting the complete list of call
  sites is guarded so a third caller fails CI. Scar #7 again, in the shape it
  keeps taking: the first fix was correct and simply was not the whole set.
- **A flag that switches behavior needs a test with the flag ON.** No test
  constructed an overlay with `introEnabled` true, which is exactly why the
  above survived 16 tests and a five-mutation pass. The new set-pin closes it
  at the source level; a rendered flag-ON test is filed as
  `polyglot-pdf-jd57a`.
- **A prop the parent must supply is a contract too.** The clip needs an auth
  token BEFORE any WebSocket exists, so it cannot borrow the connection's
  token plumbing. Rather than inventing a second auth path in the overlay, the
  parent passes down the SAME accessor it already builds for the
  ConnectionManager.
