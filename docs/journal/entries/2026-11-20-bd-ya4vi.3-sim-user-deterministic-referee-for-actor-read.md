## Trigger

These pilots were for the 3.8 benchmark redo (bd `polyglot-pdf-15j9v`): one
self-correcting W-7 run and one I-90 v2 run, both on gemini-3.8-live. Both
showed the Haiku actor misjudging Gemini's read-backs, and both errors went
against the model:

- **I-90 v2.** Gemini read the mother's first name back correctly, as "You
  said C, O, R, A, Z, O, N. Is that correct?", more than 20 times. The actor
  rejected it every time. The 34-turn loop used up the 150-turn cap, so the
  run stopped at 54/57 confirmed and reported a model failure that was the
  actor's.
- **Self-correcting W-7.** The actor accepted the slipped middle name
  ("L, U, C, Y"; the true value is Lucia). The run's 21/22 accuracy was
  therefore the actor's error. It also falsely rejected 3 correct ID-number
  read-backs.

Both pilots are discarded from the benchmark. The actor runs with effort
`low` and thinking disabled, and its long history of repeated rejects seems
to feed on itself.

## What shipped

- **`sim_user.actor.referee(decision, text, history, persona, slips_spoken)`**,
  applied by `SimDriver` after every actor decision. It acts only on an
  exact whole-token match, using the same `_tokens` normaliser as the stub.
  That normaliser collapses spelled letters and digit words, so "C, O, R, A,
  Z, O, N" becomes `corazon` and "two four ... six" becomes `249...6`.
  - A reject of a read-back that holds the true value (spoken, value or
    spelling) and not the spoken slip becomes a confirm (`reject_to_confirm`).
  - A confirm of a read-back that holds a spoken slip and not the true value
    becomes a reject on that field (`confirm_to_reject`). The field is the
    last answered one.
  - Everything else is left to the actor: no read-back cue, a paraphrase, a
    date said in words, or both values present.
  - Values too generic to act on are also left alone: yes, no, none, and
    anything under 3 characters.
  - Only the LAST read-back in the heard text is judged (`last_readback`:
    the last question-mark-ended segment holding a read-back cue). A heard
    window can hold two read-backs, and the user answers the last one.
  - The opposing-value guard is deliberately non-strict. A short true value
    such as "Ana" still blocks a slip override when it is present.
- **Ledger.** Each user turn now carries `referee` (the label, or null), and
  `summary.sim_user.referee_overrides` counts both directions. A run's
  overrides show how often the actor alone would have mis-scored the model.
- **Validation.** Replaying both pilot transcripts through the referee
  overrides exactly the 24 misjudged turns (I-90: 20; W-7: 1 + 3) and no
  others.
- **Benchmark audit.** In the 6 benchmark runs on the first referee build, 14
  overrides fired, and 13 were right. The wrong one: Gemini read back the
  right ZIP ("97203. Is that correct?"), re-asked the question, then read
  back 90210. The applicant said no to 90210, and the referee overrode the
  no because 97203 was earlier in the same window. Scoping to the last
  read-back drops exactly that override and keeps the other 13.
- **Also in this PR: bd `polyglot-pdf-ya4vi.5`.** gTTS synthesis now retries
  a failed request with 2/5/15/30 s backoff. Two benchmark runs had died
  mid-session on a transient "Failed to connect", losing their live spend.

## Lessons

- **An LLM judge in a measurement harness needs a deterministic floor.**
  Where the right verdict is mechanically checkable, an exact match against
  the answer key, check it in code and let the model judge only the
  ambiguous rest. Otherwise the judge's errors land in the model's score:
  here, a turn-cap "failure" and a wrong-field "miss" that were both the
  actor's.
- **A minimum-length gate on the ACTING match must not also gate the
  GUARD.** The first draft used one 4-character threshold for both. "Ana"
  then fell under it, so a read-back holding both "Ana" and the slip "Alma"
  looked like a slip-only read-back and was overridden. A parametrized test
  over every slipped fact caught it before merge.
- **Scope the evidence to exactly the claim.** The referee first read the
  whole heard window. That window is bigger than the read-back being
  answered, so an earlier read-back leaked in as evidence. This is the same
  trap as bd memory `a-checker-that-infers-a-claim-from-text`, and only a
  per-turn audit of every override caught it.
- **A pilot is worth its cost when it reads per-turn transcripts, not just the
  headline.** The I-90 headline (89% accuracy, turn cap hit) read as a model
  weakness. The per-turn actor log showed it was the actor's.
