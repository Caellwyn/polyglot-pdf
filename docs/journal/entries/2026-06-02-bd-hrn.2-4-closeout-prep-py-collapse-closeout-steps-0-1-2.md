## Trigger

Sprint-1 harness tuning, supporting Change #4 of
[`docs/sprint_1_harness-tuning_plan.md`](../../sprint_1_harness-tuning_plan.md)
(bead `polyglot-pdf-hrn.2`). The /closeout skill's Steps 0, 1, 2, and 4 are four
separate deterministic checks (preconditions, beads housekeeping, doc-freshness,
tests), each costing a skill-load echo and an orchestrator turn to read. The plan
calls for collapsing them into one script run returning a single structured TODO —
a token-burn reduction in the same family as `closeout_housekeeping.py` (which
already collapsed the two beads audits into one run).

## What shipped

**`scripts/closeout_prep.py`** — a zero-token aggregator that runs all four
checks in sequence and prints ONE structured TODO (or `--json`):
- **Reuses, doesn't reimplement.** It shells out to the existing
  `closeout_housekeeping.py` (Step 1) and `check_doc_freshness.py` (Step 2) as
  subprocesses, and implements the preconditions (Step 0: clean tree + commits
  ahead of the base) and the pytest run (Step 4) inline. No audit logic was
  duplicated.
- **Per-check status → one verdict.** Each check returns `ok` / `attention`
  (orchestrator must triage) / `fail` (the check itself couldn't run). These roll
  up with FAIL outranking ATTENTION outranking OK, mapped to exit codes
  **0 = READY / 3 = ATTENTION / 1 = PREP-ERROR** — mirroring
  `closeout_housekeeping.py`'s advisory `SLIP-FOUND` (3) vs tooling-failure (1)
  contract, so a caller can branch "there's triage to do" vs "the script broke."
- **Reports, never fixes.** A dirty tree, a beads slip, a STALE doc, or a red
  suite is surfaced (with detail inline) but never auto-repaired — every fix
  stays the orchestrator's judgment.
- **Worktree-safe.** `$R` (main repo) supplies only the venv interpreter; `$WT`
  (this worktree) supplies the doc/test targets and the script copies, and the
  check subprocesses run with cwd = `$WT`, so the gate audits THIS branch and not
  the main checkout (the `polyglot-pdf-9pe` lesson, applied to the aggregator).
- The doc check parses the checker's literal `STALE:` marker (verified against
  `check_doc_freshness.py:616`); the test check excludes the flaky `external`
  live-Gemini test (`-m "not external"`).

**`.claude/skills/closeout/SKILL.md`** — rewired:
- New **Step 0 — Prep** runs `closeout_prep.py` once and reads the `RESULT:`
  line; **READY skips straight to Step 3**, ATTENTION points into the per-check
  triage references, PREP-ERROR falls back to the hand-run commands.
- The old Steps 0/1/2/4 became **"detail" triage references** under Step 0 (their

  `$WT`-not-`$R` doc-freshness rationale), no longer separate auto-run echoes.
- Step 4 now notes prep already ran the suite and a re-run is only needed if code

the tests pass/fail mapping + summary-line extraction, the rendered TODO's

## Lessons

- **Collapse deterministic skill steps by COMPOSING the existing scripts, not
  reimplementing them.** `closeout_prep.py` is mostly subprocess orchestration +
  status roll-up; the actual audit logic still lives once, in
  `closeout_housekeeping.py` / `check_doc_freshness.py`. This keeps the token
  win without forking the behavior (and without a second place to fix a bug).
- **A three-valued check status (ok/attention/fail) beats a boolean.** Separating
  "ran, found work to triage" from "couldn't run" lets the aggregator give the
  orchestrator a `READY` fast-path AND distinguish a real closeout blocker from a
  tooling hiccup — the same distinction `closeout_housekeeping.py` already drew
  between exit 3 and exit 1, now applied at the aggregate level.
