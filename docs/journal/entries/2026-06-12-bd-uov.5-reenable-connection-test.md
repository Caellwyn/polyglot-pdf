## Trigger

Bead polyglot-pdf-uov.5 (T1.2 of the spec-driven test & codebase-health epic,
polyglot-pdf-uov). The frontend connection/reconnect/audio suite was parked as
`connection.test.ts.NEEDS_SECTION_REFACTOR` -- disabled because it asserted
names the section-rename (gfb.4) deleted. Phase 0 of the epic (green baseline +
coverage tooling + CI) was already closed; this is the first Phase-1 "un-rot a
disabled suite" slice. The epic's doctrine: tests encode the SPEC (documented,
reasonable behavior), not whatever the current code happens to emit, and a
failing spec-test is a FINDING (bug bead + xfail), not something to suppress.

## What shipped

Re-enabled `frontend/src/shared/connection.test.ts` (off the
`.NEEDS_SECTION_REFACTOR` suffix, via `git mv`) and rewrote it from shape-only
`toBeDefined()` theater into a real spec suite for `createConnectionManager`.
The old suite asserted removed names -- `currentPartId`,
`startSection`/`switchSection`/`completeSection`/`getCurrentSection`/
`getCompletedSections`; the rewrite targets the current section-based API and
encodes the three behaviors the bead named:

- **(a) Section-based state contract.** Initial state persists under
  `schema_form_state` anchored to the first SECTION (`currentSectionId`, NOT the
  removed `currentPartId`); a legacy `currentPartId` payload migrates forward on
  `load()`; state survives manager recreation (the stateless-reconnect
  contract -- `formSessionId` is stable across two `createConnectionManager`
  calls).
- **(b) Native-VAD activity-signal suppression (bd 333/6vo).** After the backend
  `onNativeVadMode(true)` handshake: `sendActivityStart` and the Silero barge-in
  callbacks are suppressed, but `sendActivityEnd` is STILL forwarded (the backend
  converts it to `audio_stream_end` so a PTT-release turn can close);
  `setNativeVad` reconfigures the audio layer.
- **(c) Audio-queue barge-in.** With PTT off, a VAD speech-start while Gemini
  speaks flushes the playback queue; a speech-end while Gemini is silent resumes
  playback + audio context; with PTT ON (the default) the whole barge-in path is
  gated off.

Design note: `WebFormConnection` is mocked, and `nativeVad` is a private closure
flag set only by the backend-driven `onNativeVadMode` callback -- so the test
captures the `callbacks` object the factory passes into the mocked
`WebFormConnection` constructor and fires `onNativeVadMode` by hand to exercise
the suppression spec.

One self-inflicted red during authoring (not a code finding): an initial
assertion checked `currentSectionId` in sessionStorage after construction and
got `undefined`. Root cause: the `currentPartId -> currentSectionId` migration
in `SchemaFormStateManager.load()` is **lazy** -- it rewrites the field in the
returned in-memory object but does NOT re-persist, so sessionStorage keeps the
legacy bytes until the next `save()`. Corrected the test to assert the real
contract (`SchemaFormStateManager.load()` returns the migrated field), which is
exactly what the factory consumes. No bug: the migration is correct, just
write-on-next-save.

Full FE suite **273 -> 289**, all green (12 tests in connection.test.ts + 4 in
the new webFormConnection.reconnect.test.ts). No genuine spec-red surfaced, so no
xfail/bug-bead under the epic's findings doctrine.

**Adversarial fresh-eyes assess: 2 rounds (Sonnet, arm B).** Round 1 returned

## Lessons

`SchemaFormStateManager.load()` migrates the legacy `currentPartId` /
`completedParts` keys forward IN MEMORY but does not re-persist -- a spec-test
for the migration must assert on the loader's return value, not on the
post-construction sessionStorage bytes (those stay legacy until the next save).
General enough to note where the part/section terminology canon lives; see
[terminology.md](../../standards/terminology.md) if a future test trips on the
same lazy-migration shape.
