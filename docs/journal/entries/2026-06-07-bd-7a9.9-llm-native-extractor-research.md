## Trigger

`bd polyglot-pdf-7a9.9`, the parallel research branch of the PDF->JSON authoring
epic `7a9`. The maintainer asked to (1) read the bead + its plan, (2) conduct the
suggested research and a prototype on I-90 comparing against ground truth and the
other bake-off arms, and (3) report findings with metrics comparable to the
bake-off. The cited proposal doc
(`docs/research/2026-06-07-llm-native-extractor-architecture.md`) was never
committed, so the question was reconstructed from the bead text + the committed
bake-off (`scripts/bakeoff/FINDINGS.md`).

THESIS under test: the deterministic extractor's "intelligence" layer
(`heuristic_hierarchy_parser.py` + `extractor.py` section-id/field-semantics) is
reverse-engineered from USCIS conventions and is a heuristic treadmill. KEEP
`acroform_dump.py` as a generic exact-token oracle, RETIRE the USCIS heuristics,
and move structural reasoning onto a strong LLM fed a generic bundle of every
structural signal the PDF exposes.

## What shipped

A runnable prototype + a full findings report, scored on I-90 against the committed
gold and the committed bake-off numbers. **Throwaway research output** (same

New tools under `scripts/bakeoff/`:
- `structural_enrich.py` -- a GENERIC (zero-USCIS) enrichment pass over
  `acroform_dump.py`: name-token decomposition (author's own delimiters, no
  P1->Part-1 mapping), tab order (reading-order rank), visual-row clusters.
- `arm_llm_native.py` -- pluggable-model arm. Backend auto-dispatched by `--model`

Findings (full report:
`docs/research/2026-06-07-7a9.9-llm-native-extractor-prototype-findings.md`):
- **Architecture validated on (a).** Generic enrichment matches/beats the current
  `gemini35flash-hybrid` arm on field detection + typing with ZERO form-specific
  code -- a.F1 97.0 -> 98.5, type 85.5% -> 96.9%, on BOTH gemini-3.5-flash and
  claude-opus-4-8. Opus additionally recovered `pdf_position` 99.2% (no prior arm
  did). Bundle-only (no PDF) already scores a.F1 98.5 / copy_to 100% on Opus.
- **Q1 correction (the headline finding).** The bake-off claim "the deterministic
  extractor owns schema-conformant section_id" does NOT generalize: on I-90 EVERY
  arm including the heuristic scores section_id 0.0%; the 88.3% it posts is
  I-589-ONLY, an artifact of the I-589 gold having been authored by editing that
  extractor's output. section_id exact-match is a ground-truth SEEDING artifact,
  not a capability -- filed as a DECISION bead (7a9.13).
- **Q2 W-7 probe.** W-7 (the in-repo non-USCIS form) has 0% tooltips +
  positional-only leaf names (`f1_23`, `c1_11`): the heuristic would produce
  nothing; only "read the page" works. Strongest single argument for retiring the
  heuristics. (Also corrected the bead's "I-589 has 0 dotted paths" -- all three
  forms are 100% dotted XFA; the real variance is tooltip presence + leaf
  semantics.) W-7 has no gold schema, so it stays qualitative.
- **Q4 anti-hallucination.** pdf_field_name fidelity 100% with one "copy verbatim"
  rule; no name-reference+rehydrate needed at I-90 scale.

## Lessons

- **A "convention" the deterministic layer appears to win can be a ground-truth
  SEEDING artifact.** When a gold schema was authored by editing tool X's output,
  exact-string metrics will always favor tool X on that form and mislead about
  generalization. Score grouping/structure, not authored id strings, when the id
  is idiosyncratic. (Generalizes the scorer caveat already in
  `scripts/schema_score.py`; the decision is bead 7a9.13.)
- **Probe the cheapest disqualifying case first.** The 10-minute W-7 acroform dump
  (0 tooltips, positional names) settled the retire-the-heuristics question more
  decisively than any I-90 score, because it is the case the heuristic cannot
  handle at all. Do the disconfirming probe before the elaborate benchmark.
- **The local `claude` CLI (`-p --output-format json`) is a free-in-env LLM
  backend** for research harnesses on this machine (subscription auth; `--bare`
  DISABLES that auth and forces ANTHROPIC_API_KEY, so do not use `--bare` for the
  free path). Its `cost_usd_equiv`/`input_tokens` fields are accounting artifacts,
  not real in-env cost. Dispatch by model-name prefix keeps one `--model` knob.
