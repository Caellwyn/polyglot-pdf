## What shipped

- `backend/services/schema_lint.py`: structured findings (`LintFinding`:
  severity/rule/path/message) over a RAW schema dict -- deliberately not the
  Pydantic classes, so it lints exactly the drafts `model_validate` rejects
  (the archived W-7 draft is the canonical input). Rules: unknown-operator,
  value-arity, option-value-missing/duplicate/comma (+ slug format on
  v2-stamped schemas), ref-unresolved-field, ref-option-value,
  condition-malformed, composite-depth (<= 1), show-if-cycle (WARNING), and
  dump-widget-multiclaim (with an optional acroform dump; exact-or-dot-suffix
  widget matching, same convention as the filler's find_widget). Operator
  facts come from the P1.1 vocabulary registry
  (`backend/models/conditional_vocabulary.py`) -- no hand-copied lists.
- Lint core lives in `backend/` (not `scripts/authoring/` as the registry
  docstring originally sketched) so the promotion gate imports it in-process;
  the registry docstring pointer was updated. `extract_form.py` imports it
  via its existing repo-root sys.path pattern, degrading gracefully when the
  backend is unimportable (same contract as its `_validate_schema`).
- Promotion gate (`editor_kit_routes.py` Mark-complete): zero lint ERRORs to
  promote; violations 409 with rule+path+message (capped at 8 findings +
  count). WARNINGs never block. This is one half of the P5.3 two-gate seam:
  a stored-with-issues draft stays un-promotable until repaired.
- `extract_form.py`: lint findings recorded in `_bakeoff.authoring.lint`
  ({errors, warnings, findings[]}) and printed after extraction; the acroform
  dump is read into memory before its temp file is removed so the
  widget-claim rule sees it. Exit codes unchanged (P5.3 owns tri-state exit).
- Archived the broken W-7 draft (the planning session's `w7_local.json`) as
  `backend/tests/fixtures/w7_broken_draft.json`; pinned RED (9
  unknown-operator findings naming is_selected/contains_any + the
  all-values-"1" duplicate).
- i-90 gold data fix: removed the dead `controls_fields` unlock target
  `p7_checkbox7extend[1]` (the real field is `p7_checkbox7extend`; lint
  found genuine reference drift). Behavior-neutral: controls_fields is dead
  at runtime (verified in the epic plan).
- Known, deliberate limitation (fresh-eyes round 1): the promotion gate lints
  WITHOUT a dump (no acroform dump is stored per-kit yet), so the
  dump-only widget-claim rule fires at extraction time only until P5.3
  (bd h76m.14) persists the dump as a kit artifact -- the gate call site
  carries a comment to pass it then. Documented rather than built now: the
  plan explicitly sequences dump-as-kit-artifact to P5.3.
- Two principled lint tolerances keep shipped v1 kits clean: empty-string
  condition values are the v1 emptiness idiom (`not_equals ""` = "when not
  empty"; the i-90 unit-type radios use it; P6.1 migrates it to
  is_not_empty), and a field-level + same-field-option claim on one widget is
  the benign groups-of-one convention.

## Lessons

- Lint and validate are different tools: Pydantic answers "does this parse
  into the contract?" while lint answers "what exactly is wrong, where?" --
  and must run on inputs Pydantic rejects. Building lint over the raw dict
  (never model classes) is what makes the broken-draft fixture testable at
  all.
- Shipped "gold" data can fail a new gate honestly: running the new linter
  over i-90 surfaced one genuine reference-drift bug (fixed) and one
  legitimate v1 idiom the rule had to learn (empty-string emptiness
  comparison). Budget for a tolerance-vs-fix triage whenever a new gate
  meets old data.
