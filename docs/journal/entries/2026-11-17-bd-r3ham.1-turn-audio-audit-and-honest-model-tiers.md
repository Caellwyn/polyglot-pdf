## Trigger

Epic polyglot-pdf-r3ham covers post-migration validation and a benchmark of `gemini-3.8-live` and `gemini-3.1-flash-lite`, following bd1zs (2026-10-21). The maintainer asked for three things:
- a single-run check for obvious deficiencies;
- a re-test of the 2.5-era quirks (above all spelling aloud, to see whether the Cloud TTS spell-back can retire);
- fresh cost and latency figures for the investor materials.

Every one of those runs goes through `scripts/spikes/measure_form_session_costs.py`. That instrument had three defects which would have quietly corrupted the numbers:
1. A run labelled `--model 2.5` actually drove 3.8 (bd uzecd).
2. The secretary and validator pricing table had no row for `gemini-3.1-flash-lite`. Every lite call was therefore billed at the 2.5-pro fallback rate.
3. Nothing detected the defect developers most often report on 3.8, the "silent audio turn": the output transcript is present but the audio is empty, often right after a tool response.

## What shipped

- **Model tiers that match their labels.**
  - Both `measure_form_session_costs.py` and `diag_compression_matrix_sdk28.py` now have an explicit `3.8` tier (production constants, and now the default).
  - The `2.5` tier is pinned to the real 2.5 native-audio ids, through `resolve_model_id` in the harness and `VERTEX_IDS` in the diagnostic.
  - The set was enumerated by grep before fixing. The six other probes that import `MODEL_NATIVE_STANDARD` follow the current tier and print the real id, so none of them mislabels a run.
- **Turn-audio audit**, in the new stdlib-only module `scripts/spikes/turn_audio_audit.py`. Every run reports four counts:
  - `silent_turn`: a transcript with less than 300 ms of audio.
  - `silent_after_tool`: within one user exchange, less than 300 ms of audio after the last tool call. `name_spellback` is exempt because its contract is silence.
  - `missing_completion`.
  - `runaway_audio`: more than 20 s in one turn.

  It also writes per-turn rows to `.meta.json` (character counts only, never transcript text). The harness feeds it from four places:
  - the fake client's audio and transcript surfaces;
  - the tool tap;
  - `speak()`'s activity_end;
  - the adapter's per-generation boundary edge, `_dev_flush_audio_dump`, wrapped only when present.

  A new `--audit-transcripts` flag requests output transcription for the silent-turn check. It is off by default, because production does not request output transcription.
- **Canonical text pricing.** The harness's rate rows now derive from `backend/config.py` `TEXT_GENERATION_PRICING`, and the no-model default is the production lite model.
- **Live pilot** (3-question W-7, Vertex `gemini-3.8-live`, deploy config, under `scripts/spikes/data/r3ham/pilot/`).
  - The model id was recorded correctly.
  - The audit saw 8 turns and 8 exchanges.
  - It flagged one **39 s runaway-audio turn** after `confirm_field`, which ran until the next scripted answer barged in. On the next question the model made no tool call, and that field never filled.
  - Zero transcript characters arrived. This was traced to an adapter bug, filed as **polyglot-pdf-r3ham.6**: 3.8 bundles `output_transcription` into the same server message as an audio chunk, and the receive loop's post-audio `continue` drops it. A bare genai probe found 3/3 bundled on 3.8 versus 0/10 on 2.5.
- **Assess record.**
  - Exit-criteria scorecard: all PASS.
  - Fresh-eyes ran 2 rounds:
    - Round 1 found one gap: the per-turn `turn_complete` field named in the criteria was missing. It was adopted and fixed.
    - Round 2 returned NO-GAPS.
  - The Opus outer cross-surface review, round 1, found 2 blockers in untouched consumers, both adopted:
    - pricing tests in `tests/test_stress_harness_units.py` were still pinned to the 2.5-flash-lite default, which would have turned CI red;
    - the boundary-hook wrap crashed the harness's offline dry-run fakes. After the fix, `test_dry_run_i90_v2_continuous_dti_drip_advances_past_section_boundary` passes with an i-90_v2 kit present.
  - Opus round 2 returned NO-GAPS.
  - The Opus reviewers filed two pre-existing or non-blocking docstring nits: polyglot-pdf-fre9j and polyglot-pdf-p8z7c.
  - 14 mutations, plus one for the new `turn_complete` field and one for the pricing source, each turned the suite red.
- **Filed alongside:** polyglot-pdf-r3ham.7. The official Vertex model-versions page lists `gemini-2.5-pro`, `gemini-2.5-flash` and `gemini-2.5-flash-lite` as retiring on 2026-10-20, yet all three still answered a live call on 2026-11-17, and the app still uses 2.5-pro and 2.5-flash. ## Lessons

- **A run artifact that records the model id is the only defence against a mislabelled instrument.** The uzecd defect was invisible from the CLI and from the filenames. Check the resolved id in the raw `.meta.json` before trusting any number.
- **A harness-local copy of a canonical table goes stale at the next migration.** The July rate table predated bd1zs, so lite calls fell through to the "unknown model, price at the highest row" guard. That guard did what it was built to do (overestimate rather than underestimate), which is exactly why nobody noticed. Derive from the canonical source.
- **A migration can change the shape of server messages, not just the model's behaviour.** 2.5 sent transcripts in their own messages; 3.8 bundles them with audio. Receive-loop code that `continue`s after one field of a message is fragile to that.
- **Downloaded scratch kits activate kit-coupled tests locally.** With `form-kits/w7` and `form-kits/i-90_v2` present, six tests in `test_pdf_fill_dropdown_export_codes.py` and `test_eval_extraction.py` failed. With the kits removed, all of them pass. Run the closeout suite with scratch kits parked outside the tree, which matches CI.
