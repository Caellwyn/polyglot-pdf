## Trigger

Bead polyglot-pdf-uov.15 (T3.4, under the spec-driven test epic uov, Phase 3).
The static PII never-logged guard (`backend/tests/test_no_pii_logging.py`,
bd hjo/oeq/t1c) only scanned three hand-listed `GUARDED_FILES`, so any newer
backend logging site was unguarded -- a leak in a file nobody added to the list
ships silently to Cloud Logging. The bead: widen the guard to newer sites and add
a check that flags log calls in non-guarded backend files.

## What shipped

Extending the guard immediately paid for itself: a sweep of ALL backend files
with the existing leak detectors surfaced **two live PII leaks** in files the
hand-maintained list never covered (the exact failure mode the bead names).

**Findings (fixed here as obvious in-service redactions):**

- `request_coordinator.py` (x3): `_log.error(..., spoken_name=spoken_name)` on
  the `get_field_value` send / timeout / error paths logged the raw
  user-speech-derived field label. The guard's OWN policy comment (bd t1c)
  already mandates the `spoken_name_length=len(...)` form -- the file just was
  never scanned. Fixed to the redacted length form.
- `form_filling_service.py`: `_log.info("send_initiating_message", ...,
  message=message)` logged the rendered initiating text, which embeds
  `next_field_hint` (derived from form field data). Fixed to
  `message_length=len(message)`.

Both are observability-only redactions (log a length instead of the value); no
control flow changed, and both call sites stay covered by the existing suite
(`test_resume_reconnect.py`, `test_request_coordinator.py`). The full backend
suite is green (326 passed) after the fixes.

**Guard extension (the deliverable):**

1. `test_no_pii_logging_anywhere_in_backend` -- a completeness sweep over every
   non-test / non-probe / non-script backend `.py`, running the same
   `_scan_leaks` + `_scan_print_leaks` detectors. A new logging site is now
   covered the moment it lands, with NO list edit. It has a `>5 files` vacuity
   guard so a broken path glob fails loudly instead of passing on zero files.
2. `GUARDED_FILES` widened (`+request_coordinator.py`, `+form_filling_service.py`,
   `+websocket_routes.py`) so the highest-value sites keep labelled, per-file
   regression coverage UNDER the broad sweep.

**Mutation-verified:** injecting `_log.info("x", value=value)` into an UNGUARDED
file (`validation_handler.py`) fails the new sweep -- proving it genuinely covers
files outside the explicit list, not just the ones already named.

The bead had no `## Exit criteria` (creation-time-norm slip); a retrospective
3-criterion rubric was written at claim time and scored at closeout.

## Lessons

An allow-list-style guard (scan THESE files) silently narrows to whatever was
known when it was written; its blind spot grows with every new file. The robust
shape for a security invariant that must hold *everywhere* is a deny-by-default
SWEEP (scan ALL files, fail on any violation) with a small, explicit skip-list
for the deliberate exceptions (tests assert on PII on purpose; probes/dev scripts
never hit the request path). Keep the labelled per-file tests for clear failure
messages on the high-value sites, but put the sweep underneath as the net. The
tell that an allow-list has rotted: widen it once and see whether the newly-
covered files were already clean -- here two of them were not. Added to
docs/standards/hipaa-pii-policy.md.
