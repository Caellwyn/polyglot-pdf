## Trigger

Sprint 20 stage 3 (epic `polyglot-pdf-s1iex`, plan
`docs/sprint_20_sol-intro-tts_plan.md`). Deliberately UNFLAGGED and
independent of the rest of the epic: it fixes **shipped** behavior. Today a
spell-back clip plays and Sol sits frozen, because a clip on a bare
`HTMLAudioElement` bypasses every signal the avatar depends on. The intro
clip (beads `.5`/`.6`) would have inherited the same deadness, so this lands
first.

## What shipped

The three gates that kept Sol idle, each closed at its own layer:

- **`audioManager.attachClipElement(el)`** splices a clip element into the
  SAME playback graph the model's PCM already uses (`createMediaElementSource`
  -> the existing `getOutputAnalyser` node -> destination), and fires the
  `vffOnAudioPlaybackStart/End` globals. One energy source, so
  `deriveSolState` learns nothing new. Returns an idempotent release; clips
  are ref-counted so the spell-back clip and the intro clip cannot clear each
  other's state, and a clip ending mid-model-turn does not silence Sol.
  Creates the AudioContext if absent (Sol's intro runs with NO session), and
  degrades to element-only playback rather than throwing when Web Audio is
  unavailable.
- **`spellbackPlayer`** attaches after the blob URL is set and releases on
  EVERY settle path (ended, error, watchdog, PTT interrupt, cancel) -- a leaked
  attachment would strand Sol in `speaking` forever.
- **`deriveSolState`** gained `clipPlaying`, checked BEFORE the live-session
  gate but AFTER `paused`/`offline`. This was the non-obvious find: fixing the
  audio signal alone would still have left Sol idle, because `speaking` is
  gated on `isLiveSession(status)` and the intro clip plays with no session at
  all. Both overlays pass it (hand-duplicated, so both were edited).
- **The shared-flag invariant across ALL FOUR writers.** `geminiIsSpeaking`
  gates `getOutputEnergy`, and three model-audio paths (`playAudio`'s
  `onended`, its catch, and `resetPlaybackClock`) cleared it unconditionally.
  Since the clip's drain-wait is BOUNDED (8s, then it plays anyway) a clip
  legitimately overlaps a model turn's tail, and in client-VAD mode a
  barge-in flush lands mid-clip -- either would zero the flag and flatline
  Sol's amplitude for the rest of the clip while the STATE still read
  `speaking`. All four sites now check `activeClipCount`, and a test pins the
  complete SET (count + a guard within each site's window) so a new clear-site
  fails CI. Found by fresh-eyes, not by me.
- **`isSpeaking()` stays MODEL-ONLY; the avatar gets a separate union.** The
  Opus cross-surface pass found the real consequence of widening the shared
  flag: `isSpeaking()` has EIGHT turn-taking callers in untouched files, and
  two form a DEADLOCK pair -- `onVADSpeechStart` suspends the playback
  context when it is true, `onVADSpeechEnd` only resumes when it is false.
  Since the clip now lives INSIDE that context (on `dev` it was a bare
  element, immune), a clip would have been suspended mid-word and never
  resumed, killing the clip and the model's next audio. Also, the post-resume
  re-prompt (`connection.ts:842`) would have been suppressed by a clip,
  reintroducing the bd `yo5t` silence. Fix: `isSpeaking()` now excludes
  clips (its callers' original meaning), and `isAnyAudioPlaying()` is the new
  union the avatar's energy gate and the playback watchdog read.
  `cleanup()` also resets the clip count, so a teardown mid-clip cannot
  strand the guards permanently.
- **A CLIP-ONLY signal to feed it**: `audioManager.isClipPlaying()`
  (ref-counted) plus a `vffOnClipStateChange` notification, consumed by a new
  `useClipPlaying` hook (chained subscription + the same polled safety net as
  its sibling). The first revision of this bead passed `useGeminiSpeaking`
  into `clipPlaying` -- see Lessons.
- **9 tests** across the three layers, all four assertion families
  mutation-verified red-then-green.
- **`frontend/src/dev/clipAnimationCheck.html`** -- a dev-only browser harness,
  because jsdom has no Web Audio and cannot prove the graph carries the clip.

## Lessons

- **The manual check earned its place.** The unit tests were green and the
  browser harness still said FAIL -- peak energy 0.00. The implementation was
  fine; the HARNESS was wrong (it sampled inside `requestAnimationFrame`,
  which Chrome throttles to **zero in a background tab**). Re-measured on a
  timer: peak 26.64, globals start/end each once. Two lessons: a verification
  harness must not depend on tab focus, and a FAIL from a new harness deserves
  the same suspicion as a surprising model result -- check the harness before
  the code (the repo's own "be as suspicious of your own harness code" rule,
  here proven on the frontend).
- **A frozen test clock can WEDGE vitest rather than fail it.** The player's
  pre-clip drain-wait loops until `now()` shows a sustained quiet window, so a
  harness pinning `now: () => 0` spins forever: the worker never exits, no
  results print, and it looks like an environment/junction problem. The
  bisect that found it (run the pure-function describe alone -> rc=0) is the
  cheap move; an existing passing test in the same directory is the control
  that proves the environment is fine.
- **Fixing an energy source is not enough when a state machine gates on
  session liveness.** Worth checking the consumer's preconditions before
  assuming a signal fix is sufficient.
- **Widening a shared PREDICATE is a contract change for every reader, not
  just a value change.** Making `geminiIsSpeaking` mean "model OR clip" was
  the root of BOTH review rounds' findings: first the four writers, then the
  eight readers. The durable answer was not a cleverer flag but two honestly
  named predicates -- `isSpeaking()` (what turn-taking always meant) and
  `isAnyAudioPlaying()` (what the avatar actually wants). When a new case
  makes an existing boolean ambiguous, SPLIT it rather than widen it; the
  compiler and the reviewers then work for you instead of against you.
- **Adding a condition to a SHARED mutable flag means auditing every writer,
  not just the one you added** (scar #7 in a new guise). This bead introduced
  the rule "only clear `geminiIsSpeaking` when no clip is playing" and
  implemented it in exactly one of four clear-sites. The other three were
  reachable in production (a bounded drain-wait; a client-VAD barge-in), and
  no test covered them because the new suite only exercised the writer I had
  touched. The durable fix is the SET pin: assert the complete list of
  clear-sites and that each carries the guard, so the next writer must
  justify itself.
- **A source-reading test must resolve paths from the TEST FILE, never
  `process.cwd()`.** This repo runs worktree vitest from the MAIN checkout (a
  node_modules junction workaround), so a cwd-relative read audited main's
  copy: it counted 3 clear-sites while the branch had 4, and would have
  passed against an unfixed branch. `expect.getState().testPath` is the
  reliable anchor.
- **A NEW state input must be exactly as narrow as its justification.** The
  first revision wired `clipPlaying: solSpeaking` in both overlays -- and
  `useGeminiSpeaking` is true for the model's OWN audio too. The justification
  ("audible with no session") holds only for clips, so the broad signal
  silently regressed bd `polyglot-pdf-bxng`: every transient state
  (`reconnecting`, `switching_section`, `connecting`) rendered `speaking`
  instead of `connecting`. It was found by PRINTING a before/after state
  matrix rather than reasoning about it -- nine lines of throwaway test code,
  and the existing 49-test `solState` suite plus my own 9 new tests were all
  green through the regression, because none of them combined the new input
  with a reconnect status. **When adding an input to a precedence-ordered
  state machine, enumerate the existing states against it** rather than
  spot-checking the one path you had in mind; the guard now loops over the
  whole `isConnecting` set.
