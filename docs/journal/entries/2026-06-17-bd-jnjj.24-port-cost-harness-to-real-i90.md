## Trigger

`scripts/spikes/measure_form_session_costs.py` was hardcoded to the DEMO schema
(`adult_intake_demo_schema.json`), which is non-representative -- flat `description`
on 2/174 fields, no nested `help` block, no parts/sections arrays. That demo
substrate is what invalidated the original G2 measurement (bd jnjj.6) and hid the
help.instructions bug (jnjj.23). All forward cost/JIT/DTI/secretary measurement
must run on the REAL I-90 (`form-kits/i-90/schema.json`: 8 parts / 16 sections /
132 fields, `help.instructions` on 132/132). This bead is the shared-infra
prerequisite: it makes the harness able to load the I-90. It unblocks jnjj.25 (the
live DTI-vs-baseline measurement) and the secretary recall/latency research.

## What shipped

A `--schema {demo,i90}` flag on the cost harness (default `demo`, back-compat):

- A `SCHEMAS` registry maps each key to its source path + matching question plan.
  `load_schema(key)` and the `run()` driver select from it; the output filename +
  `meta` now carry the schema key so demo/i90 runs never collide.
- `I90_QUESTIONS`: a 20-question plan over the first 3 real I-90 sections (Part 1
  "Information About You", mailing address, physical address), with FICTIONAL
  answers. **Only unconditionally-visible fields are scripted** -- the name-change
  radio (`p1_checkbox4`) is answered "no" so the `show_if` previous-name fields stay
  hidden, and the conditional apt/suite fields are skipped; otherwise the plan would
  stall asking for a field the client never shows.
- Full I-90 audio cache (38 utterances: 20 say + 16 wrong + confirm/reject)
  synthesized and committed, matching the harness's "committed; reruns are
  network-free" convention.

**Exit-criteria scorecard:**
1. Harness loads `form-kits/i-90/schema.json` and runs a >=20-question plan over the
   first ~3 sections with full per-field context reaching the SI -- **PASS** (20
   questions, all field_ids valid, 3 sections; verified offline).
2. section-reset (full-SI) AND JIT arms render production-faithful I-90 SIs (spot
   check contains real help.instructions) -- **PASS** (full-SI: A-Number "7-9 digit"
   present, 9 `Note:` lines section 1; JIT: manifest lists the section's fields).

## Lessons

- **Measurement fidelity is a schema problem first.** Every cost/correctness verdict
  this epic produced on the demo schema was suspect because the demo lacks the
  structure (nested help, conditionals, real section sizes) that drives the
  behavior being measured. Porting the harness to the real form is the precondition
  for trusting any downstream number -- it should have been the FIRST measurement
  bead, not a late one.
- **A question plan must respect the form's own visibility logic.** Scripting a
  hidden (`show_if`) field would make the live driver wait forever for a field the
  client never renders. The plan answers the controlling radio to keep the
  conditional fields hidden and scripts only visible fields -- the plan is part of
  the form's navigation contract, not just a field list.
